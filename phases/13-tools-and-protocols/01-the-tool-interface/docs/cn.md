# 工具接口——为什么智能体需要结构化输入输出（The Tool Interface — Why Agents Need Structured I/O）

> 语言模型产生 token。程序执行行动。这两者之间的差距就是工具接口：让模型请求行动、让宿主执行行动的契约。2026 年所有主流栈——OpenAI、Anthropic 和 Gemini 的函数调用；MCP 的 `tools/call`；A2A 的任务片段——都是同一个四步循环的不同编码。本章为这个循环命名，并展示运行它所需的最小机制。

**类型：** 学习  
**语言：** Python（标准库，无 LLM）  
**前置知识：** Phase 11（LLM 补全 API）  
**预计时间：** 约 45 分钟

## 学习目标

- 解释为什么只能生成文本的 LLM 自身无法对真实世界采取行动。
- 画出四步工具调用循环（描述 → 决策 → 执行 → 观察），并说明每一步的负责方。
- 将工具描述编写为三个部分：名称、JSON Schema 输入和确定性执行函数。
- 区分纯工具和有副作用的工具，说明这种区分对安全性的重要性。

## 问题所在

LLM 输出的是下一个 token 的概率分布。这就是全部输出面。如果你问聊天模型"班加罗尔现在的天气如何"，它能写出一个合理的句子，但它无法拨打天气 API。这个句子可能碰巧正确，也可能是三天前的数据。

弥合这个差距就是工具接口的目的。宿主程序——你的智能体运行时、Claude Desktop、ChatGPT、Cursor 或自定义脚本——向模型宣告一个可调用工具列表。当模型决定需要采取某个行动时，它输出一个结构化的有效载荷，指定工具名称和参数。宿主解析该有效载荷，真正运行工具，并将结果反馈回来。循环继续，直到模型决定不需要更多调用。

这个契约的第一个版本于 2023 年 6 月以 OpenAI 的"functions"参数的形式发布。Anthropic 在 Claude 2.1 中以 `tool_use` 块跟进。Gemini 几个月后添加了 `functionDeclarations`。现在每个提供商都暴露相同的形状：输入带 JSON Schema 类型的工具列表，输出 JSON 有效载荷的工具调用。模型上下文协议（2024 年 11 月）将这个契约通用化，使一个工具注册中心能服务于每个模型。A2A（2026 年 4 月，v1.0）在智能体之间的委托场景中叠加了同一原语。

四步循环是所有这些底层的不变量。Phase 13 中的其他一切都是对它的细化。

## 核心概念

### 第一步：描述

宿主用三个字段声明每个工具。

- **名称。** 一个稳定的、机器可读的标识符。`get_weather`，而不是"天气工具"。
- **描述。** 一段自然语言简介。"当用户询问特定城市当前情况时使用。不要用于历史数据。"
- **输入模式。** 描述工具参数的 JSON Schema 对象（draft 2020-12）。

模型接收到列表。现代提供商使用提供商特定的模板将这些声明序列化到系统提示中，因此作为调用者你只需处理结构化形式。

### 第二步：决策

给定用户消息和可用工具，模型选择三种行为之一：

1. **直接回答文本。** 不调用工具。
2. **调用一个或多个工具。** 输出结构化调用对象。在 `parallel_tool_calls: true` 下（OpenAI 和 Gemini 默认开启，Anthropic 需选择开启），模型可以在一次轮次中输出多个调用。
3. **拒绝。** 严格模式结构化输出可以产生类型化的 `refusal` 块而非调用。

工具调用有效载荷有三个稳定字段：调用 `id`、工具 `name` 和 JSON `arguments` 对象。id 存在是为了让宿主能将后续结果与特定调用关联，这在并行调用以乱序返回时很重要。

### 第三步：执行

宿主接收调用，根据声明的模式验证参数，并运行执行器。无效参数意味着模型幻觉了一个字段或使用了错误类型——这是弱模型上非常常见的失效模式。生产宿主对无效参数做三件事之一：快速失败并将错误暴露给模型、用约束解析器修复 JSON，或在提示中包含验证错误后重试模型。

执行器本身是普通代码。Python、TypeScript、shell 命令、数据库查询。它产生一个结果，通常是字符串，但也可以是任何 JSON 值或结构化内容块（MCP 中的文本、图像或资源引用）。结果必须可序列化。

### 第四步：观察

宿主将工具结果附加到对话中（作为带匹配 `id` 的 `tool` 角色消息），并重新调用模型。模型现在在上下文中有了工具输出，可以产生最终答案或请求更多调用。这持续到模型停止发出调用或宿主达到迭代次数安全限制为止。

### 信任分割

工具有两种对安全性重要的类型：

- **纯工具。** 只读、确定性、无副作用。`get_weather`、`search_docs`、`get_current_time`。推测性调用是安全的。
- **后果性工具。** 改变状态、花费金钱、接触用户数据。`send_email`、`delete_file`、`execute_trade`。必须有门控机制。

Meta 2026 年的智能体安全"二规则"说，单次轮次最多可以组合以下两种：不受信任的输入、敏感数据、后果性行动。工具接口是你执行该规则的地方——通过拒绝调用、要求用户确认或升级权限范围。完整的安全章节见 Phase 13 · 15，智能体级权限策略见 Phase 14 · 09。

### 循环所在的位置

| 上下文 | 谁描述 | 谁决策 | 谁执行 |
|--------|--------|--------|--------|
| 单轮函数调用（OpenAI/Anthropic/Gemini） | 应用开发者 | LLM | 应用开发者 |
| MCP | MCP 服务器 | LLM 通过 MCP 客户端 | MCP 服务器 |
| A2A | 智能体卡发布者 | 调用智能体 | 被调用智能体 |
| Web 浏览器（函数调用智能体） | 浏览器扩展/WebMCP | LLM | 浏览器运行时 |

到处都是同样的四步。列名在变，结构不变。

### 为什么不直接提示模型输出 JSON？

"让模型以 JSON 格式回复"是函数调用之前的模式。在前沿模型上约有 5-15% 的失败率，在较小的模型上失败率更高。失败模式包括缺少括号、尾随逗号、幻觉字段和类型错误。然后你需要一个 JSON 修复步骤、重试，或约束解码器。

原生函数调用有三个优点。第一，提供商对精确的调用形状进行端到端训练，使严格模式下有效 JSON 率升至 98-99%。第二，调用有效载荷位于其自身的协议插槽中，而非自由文本内部——因此工具调用永远不会泄漏到用户可见的回复中。第三，提供商用约束解码强制执行模式合规性（OpenAI 的严格模式、Anthropic 的 `tool_use`、Gemini 的 `responseSchema`）。输出保证能通过验证。

### 断路器

当模型停止发出调用或宿主达到最大轮次数时，循环终止。生产宿主将此设置为 5 到 20 轮之间。超过这个数，几乎可以肯定是在一个模型无法退出的循环中。Claude Code 默认 20；OpenAI Assistants 默认 10；Cursor 的智能体模式默认 25。

另一种选择——无界循环——每隔六个月就会出现"智能体一夜间花了 400 美元 API 调用"的事故报告。不要在没有界限的情况下发布。

Phase 14 · 12 深入讲解错误恢复和自我修复；Phase 17 讲解生产速率限制。

## 动手使用

`code/main.py` 不使用 LLM 运行四步循环。一个虚拟的"决策器"函数通过对用户消息进行模式匹配来模拟模型；执行器、模式验证器和观察步骤工具是真实的。运行它以查看带可打印中间状态的完整请求/响应编排，然后在后续课程中用任何真实提供商替换虚拟决策器。

要关注的内容：

- 工具注册表每个工具持有三个字段：名称、描述、模式和执行器引用。
- 验证器是仅用标准库编写的最小 JSON Schema 子集（类型、必填、枚举、最小/最大）。Phase 13 · 04 提供了更完整的版本。
- 循环将迭代次数限制为五次。生产智能体需要这种断路器。

本章生成 `outputs/skill-tool-interface-reviewer.md`。给定草稿工具定义（名称 + 描述 + 模式 + 执行器概述），该技能审核其循环适用性：名称是否机器稳定，描述是否是完整的使用简介，模式是否正确使用了 JSON Schema 2020-12，以及纯工具与后果性工具的分类是否明确。

## 练习

1. 在 `code/main.py` 中添加第四个工具 `get_stock_price(ticker)`。将其描述写为"当用户按股票代码询问当前股价时使用。不要用于历史价格或市场摘要。"运行工具库并确认虚拟决策器将提到股票代码的查询路由到新工具。

2. 破坏模式验证器。传入一个 `arguments` 对象缺少必填字段的调用，并确认宿主在执行前拒绝它。然后传入一个带有额外未知字段的调用。决定：宿主应该拒绝还是忽略？用安全论据为你的选择辩护。

3. 将工具库中的每个工具分类为纯工具或后果性工具。向需要的注册表条目添加 `consequential: true` 标志，并将循环改为每当选择后果性工具时打印"将向用户确认"行。这就是每个生产宿主需要的确认门的形状。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 工具（Tool） | "模型可以调用的东西" | 名称 + JSON Schema 类型输入 + 执行器函数的三元组。 |
| 函数调用（Function calling） | "原生工具调用" | 提供商级 API 支持，用于输出结构化工具调用而非散文。 |
| 工具调用（Tool call） | "模型的行动请求" | 模型输出的带 `id`、`name`、`arguments` 的 JSON 有效载荷。 |
| 工具结果（Tool result） | "工具返回的内容" | 执行器的输出，包装在带匹配 id 的 `tool` 角色消息中。 |
| 并行工具调用（Parallel tool calls） | "同时多次调用" | 一次模型轮次中的多个调用对象，独立且可按 id 排序。 |
| 严格模式（Strict mode） | "保证 JSON" | 强制模型输出根据声明的模式验证的约束解码。 |
| 纯工具（Pure tool） | "只读工具" | 无副作用；可安全重新运行。 |
| 后果性工具（Consequential tool） | "行动工具" | 改变外部状态；需要门控、审计或用户确认。 |
| 四步循环（Four-step loop） | "工具调用周期" | 描述 → 决策 → 执行 → 观察。 |
| 宿主（Host） | "智能体运行时" | 持有工具注册表、调用模型并运行执行器的程序。 |
