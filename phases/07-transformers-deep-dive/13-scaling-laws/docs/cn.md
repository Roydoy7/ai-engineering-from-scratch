# 缩放定律

> 2020 年 Kaplan 的论文说：模型更大，损失更低。2022 年 Hoffmann 的论文说：你训练得不够。计算量进入两个桶——参数和 token——而分配比例并不显而易见。

**类型：** 学习
**语言：** Python
**前置知识：** 第7阶段第05课（完整 Transformer）、第7阶段第07课（GPT）
**预计时间：** 约45分钟

## 问题背景

当你有 C FLOPs 的训练计算量，想要得到最好的模型时，你面临两个旋钮：

1. **多少参数（N）？** 模型越大，容量越高。
2. **多少训练 token（D）？** 数据越多，容量利用越好。

FLOPs 大约等于 `6 × N × D`。你可以推高 N 压低 D，或者推高 D 压低 N。哪个更好？

2022 年之前，答案是"使劲推 N"。GPT-3（2020 年）是在约 3000 亿 token 上训练的 1750 亿参数模型。每个参数约 1.7 个 token。Kaplan 缩放定律支持这一做法。

Hoffmann et al.（2022 年），通过训练一个称为 Chinchilla 的小型模型家族，发现了不同的事实：最优比例更接近**每个参数 20 个 token**。GPT-3 训练量不足了 10 倍。Chinchilla（700 亿参数，1.4 万亿 token）在每个基准上都击败了 GPT-3（1750 亿，3000 亿 token），推理成本仅为其 2.5 分之一。

2026 年是 Chinchilla 的世界——但有一个重要转折。Llama 3 8B 在 15 万亿 token 上训练，每个参数对应 1875 个 token。超过 Chinchilla 最优的九十四倍。对于大规模使用的模型，推理成本比训练成本更重要，所以过度训练（超过 Chinchilla）以缩小可部署体积是 2026 年的默认做法。

## 核心概念

### Hoffmann 定律

来自 Chinchilla 论文，损失遵循：

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 参数量（不含嵌入层）
- `D` = 训练 token 数
- `α ≈ 0.34`，`β ≈ 0.28`（大致对称）
- `E ≈ 1.69`，不可降低的损失下限
- `A ≈ 406`，`B ≈ 411`

随着规模扩大，两个项相互权衡。在固定计算量（C = 6ND）下对 `N` 求导并求解：

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

计算量最优：每个参数 20 个 token。

### 为什么还要过度训练

Chinchilla 最优使每个训练 FLOP 的训练损失最小。但训练成本只支付一次；推理成本是永远持续的。

对于每月服务 1 万亿 token 的聊天机器人，推理主导总成本。Llama 的方式：训练更小的模型，训练更长时间。在 15 万亿 token 上训练的 80 亿参数模型是推理深度优化的：

- 适合消费级 GPU
- 延迟是 Chinchilla 最优 700 亿参数模型的几分之一
- 质量对大多数任务来说足够接近

DeepMind 2024 年的论文（"过度训练是新的最优"）将此形式化。对于推理主导的工作负载，根据服务量，正确比例更接近每个参数 100–500 个 token。

### 涌现 vs 平滑性

声称：某些能力（算术、多步推理、思维链跟随）在某个规模突然"涌现"。

Schaeffer et al.（2023 年）认为这是测量伪象：涌现指标使用不连续评分（精确匹配、阈值处准确率），这隐藏了底层 logit 的平滑改进。连续指标（交叉熵）显示的是平滑曲线。

2026 年的共识是：通过连续损失的预测是可靠的。基准跳跃通常是评分器伪象。根据连续指标规划预算。

### 2026 年的图景

缩放定律仍然有效，但：

| 因素 | 变化方式 |
|------|---------|
| 数据质量 | 策划"好"token（Phi 风格）使曲线移动超过 2 倍有效计算量 |
| MoE | 总参数与活跃 FLOP 解耦；缩放定律按每活跃 FLOP 计算 |
| 后训练 | 某些能力（指令跟随、代码）随 SFT+RLHF 的提升多于预训练 |
| 多模态 | 图像 + 文字 token 共同扩展；每种模态有单独的曲线 |
| 合成数据 | 模型生成训练数据；有效计算量可以复利增长 |

Muon 优化器（Kimi Moonlight，2024 年）展示了在相同数据下比 AdamW 约 2 倍的有效计算量增益。一些 2026 年的训练运行默认使用 Muon。改变缩放定律中的绝对常数，而不改变其形状。

## 动手实现

见 `code/main.py`。我们实现 Chinchilla 损失方程，并在几个计算预算下求解计算量最优的 `(N, D)`。

### 第一步：Chinchilla 损失

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

在固定 `C = 6ND` 下绘制 `L` 关于 `(N, D)` 的等值线图。找到最小值。

### 第二步：计算量最优前沿

对于从 `1e17` 到 `1e25` FLOPs 的计算预算，在 `6ND = C` 约束下找到最小化损失的 `(N, D)`。验证比例 `D/N ≈ 20`。

### 第三步：过度训练代价

计算训练 10 倍更小的模型（最优 N 的 1/10，10 倍的最优 D）所付出的额外损失。报告换来的推理 FLOP 节省（与 N 成比例）。

### 第四步：与真实模型对比

输入已知的 `(N, D)` 对——GPT-3、Chinchilla、Llama 3 8B、DeepSeek-V3（活跃参数），比较预测损失与报告损失。

## 工程应用

你不太可能自己训练前沿模型。但缩放定律会告诉你：

1. **你的微调是否有足够的数据。** 如果你的任务特定数据低于基础模型每参数 20 个 token，预期会在某个损失下限饱和。
2. **是否应该选择更大的基础模型。** 如果你把所有预算都花在推理上，倾向于选择更小、训练更长的模型。
3. **收益递减的位置。** 超过 1000 倍 Chinchilla 最优后，对数损失的变化变成噪声。

**2026 年的研究走向：**

- **数据受限制度。** 网络上高质量 token 的数量是有限的（过滤后约 5–10 万亿英语 token）。前沿预训练正在接近这一上限。合成数据、多语言、多模态和 RLHF 扩展微调是下一个杠杆。
- **计算乘数技巧。** Muon 优化器、MoE、更好的数据策划——每项都改变绝对常数，而不改变渐近线。
- **强化学习的缩放定律。** 开放性问题。早期证据表明 RL 样本中存在幂律，但指数与预训练非常不同。

## 关键术语

| 术语 | 常见说法 | 真正含义 |
|------|---------|---------|
| 参数 (N) | "模型大小" | 不含嵌入的权重数量；决定容量 |
| Token 数 (D) | "训练数据" | 见过的训练 token 数；决定参数被利用的程度 |
| 计算量 (C) | "花费的 FLOP" | 标准 Transformer 约等于 `6 × N × D` |
| Chinchilla 最优 | "D/N ≈ 20" | 使每个预训练 FLOP 损失最小化的比例 |
| 过度训练 (Over-training) | "超过 Chinchilla" | 花费额外训练 FLOP 以节省推理 FLOP；D/N >> 20 |
| 不可降低的损失 (Irreducible loss) | "下限" | 缩放定律中的 `E` 项；数据本身的熵 |
| 涌现能力 (Emergent capability) | "规模带来的突然跳跃" | 通常是评分器伪象；连续损失是平滑的 |
| 有效计算量 (Effective compute) | "训练效率乘数" | 更好的数据/优化器/架构使每个 FLOP 走得更远 |
