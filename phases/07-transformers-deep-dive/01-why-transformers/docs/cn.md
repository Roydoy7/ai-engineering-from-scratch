# 为什么是 Transformer——RNN 的问题

> RNN 逐个处理 token，Transformer 同时处理所有 token。这一单一架构选择改变了 2017 年之后深度学习的每一条规模化曲线。

**类型：** 学习
**语言：** Python
**前置知识：** 第3阶段（深度学习核心）、第5阶段第9课（序列到序列）、第5阶段第10课（注意力机制）
**预计时间：** 约45分钟

## 问题背景

2017 年之前，地球上每一个最先进的序列模型——语言、翻译、语音——都是循环神经网络。LSTM 和 GRU 在翻译基准上统治了半个十年，是所有人手中唯一的工具。

它们有三个致命弱点。**顺序计算**意味着你无法在时间轴上并行化：token `t+1` 需要来自 token `t` 的隐状态。1024 个 token 的序列意味着要在每个周期可以执行 100 万次浮点运算的 GPU 上串行执行 1024 步。训练时间在专为并行设计的硬件上随序列长度线性增长。

**梯度消失**意味着 50 个 token 之前的信息已经被压缩过了 50 次非线性变换。门控循环单元（LSTM、GRU）缓解了这个问题但从未消除。长距离依赖——"我去年夏天在飞往京都的飞机上读的那本书……"——频繁失败。

**固定宽度隐状态**意味着编码器在解码器看到任何东西之前，必须将整个源序列压缩进一个向量。不管源序列是 5 个 token 还是 500 个，瓶颈的形状是一样的。

2017 年的论文《Attention Is All You Need》提出了一个激进的方案：完全去掉递归。让每个位置并行地关注其他所有位置。用一次大型矩阵乘法代替 1024 次串行矩阵乘法进行训练。

结果到 2026 年主导了每种模态：语言（GPT-5、Claude 4、Llama 4）、视觉（ViT、DINOv2、SAM 3）、音频（Whisper）、生物学（AlphaFold 3）、机器人（RT-2）。同一个模块，不同的输入。

## 核心概念

**递归作为瓶颈**。RNN 计算 `h_t = f(h_{t-1}, x_t)`。每一步都依赖前一步，在计算 `h_4` 之前无法计算 `h_5`。在拥有 10000+ 并行核心的现代 GPU 上，长序列会浪费 99% 的硅片。

**注意力作为广播**。自注意力同时为每个位置对 `(i, j)` 计算 `output_i = sum_j(a_ij * v_j)`。整个 N×N 注意力矩阵在一次批量矩阵乘法中填满，没有任何一步依赖另一步。GPU 非常喜欢这个。

**加速不是常数**。它是 `O(N)` 串行深度和 `O(1)` 串行深度之间的差异。实践中，在 N=512 的匹配硬件上，Transformer 每轮训练快 5–10 倍，随着序列长度增加差距扩大，直到遇到注意力的 `O(N²)` 内存壁（后来 Flash Attention 解决了这个问题——见第12课）。

**Transformer 的代价**。注意力内存随 `O(N²)` 增长。2K 上下文还好，128K 上下文则需要滑动窗口、RoPE 外推、Flash Attention 分块或线性注意力变体。递归在时间和内存上都是 `O(N)`，Transformer 用内存换时间，然后通过并行性赢回时间。

**归纳偏置的转变**。RNN 假设局部性和近期性。Transformer 不做任何假设——每个位置对都是注意力的候选。这就是为什么 Transformer 需要更多数据才能训练好，但一旦有了足够数据就能扩展更远。Chinchilla（2022）将其形式化：给定足够的 token，Transformer 总是击败参数量相同的 RNN。

## 动手实现

这里没有神经网络——我们用数值方式模拟核心瓶颈，让你在笔记本上感受差距。

### 第一步：测量串行深度

见 `code/main.py`。我们构建两个函数：一个像 RNN 一样将序列编码为加法链（串行），一个像注意力一样并行归约（广播）。数学相同，依赖图不同。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # can't parallelize: h depends on previous h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # every x is independent
```

我们对长度达 100000 的序列分别计时。RNN 版本是 O(N) 且在单 CPU 流水线上运行。即使在纯 Python 中，注意力风格的归约在长度 ≥ 1000 时也胜出，因为 Python 的 `sum()` 用 C 实现，每步没有解释器开销。

### 第二步：统计理论操作数

两种算法都做 N 次加法。差异在于*依赖深度*：在下一步可以开始之前必须按顺序发生多少次操作。RNN 深度 = N。注意力深度 = 树归约时 log(N)，并行扫描时为 1。是深度而非操作数决定 GPU 时间。

### 第三步：在长序列上的实证规模化

我们打印一个计时表格，让 O(N) 差距清晰可见。在 2026 年 Mac 笔记本上，1000 个元素以下的序列太快无法测量。10 万个元素显示出清晰的线性扫描。将其推广到 16384 个 token 的 Transformer 和等效的 12 层 LSTM，你就能明白为什么训练时钟时间在 2016 年是个障碍。

## 工程应用

2026 年何时还选 RNN：

| 场景 | 选型 |
|------|------|
| 流式推理，每次一个 token，内存恒定 | RNN 或状态空间模型（Mamba、RWKV） |
| 超长序列（>1M token）注意力内存爆炸 | 线性注意力、Mamba 2、Hyena |
| 无矩阵乘法加速器的边缘设备 | 深度可分离 RNN 在 FLOP/瓦特上仍胜出 |
| 其他所有情况（训练、批量推理、最多 128K 上下文） | Transformer |

状态空间模型（SSM）如 Mamba 本质上是具有结构化参数化的 RNN，兼具两者之长：训练时 `O(N)` 扫描内存，通过选择性扫描实现并行训练。它们以更好的长上下文扩展性恢复了 90% 的 Transformer 质量。2026 年大多数前沿实验室训练混合 SSM+Transformer 模型（如 Jamba、Samba）——递归没有消亡，它是一个组件。

## 关键术语

| 术语 | 常见说法 | 真正含义 |
|------|---------|---------|
| 递归 (Recurrence) | "RNN 是串行的" | 第 `t` 步依赖第 `t-1` 步的计算，强制沿时间轴串行执行 |
| 串行深度 | "图有多深" | 依赖操作的最长链；即使硬件无限也限制时钟时间 |
| 注意力 (Attention) | "让 token 互相看" | 加权和 `sum_j a_ij v_j`，其中 `a_ij` 来自位置 i 和 j 之间的相似度 |
| 上下文窗口 | "模型能看多少" | 注意力层可以接收的位置数，二次内存代价在这里体现 |
| 归纳偏置 | "架构中的假设" | 关于数据形态的先验；CNN 假设平移不变性，RNN 假设近期性 |
| 状态空间模型 | "有代数支撑的 RNN" | 通过结构化状态空间矩阵参数化以支持并行训练的递归 |
| 二次瓶颈 | "为什么上下文这么贵" | 注意力内存 = 序列长度的 `O(N²)`；Flash Attention 隐藏常数，但不改变增长率 |
