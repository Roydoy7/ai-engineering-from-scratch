# 混合记忆：向量 + 图 + KV（Mem0）（Hybrid Memory: Vector + Graph + KV — Mem0）

> Mem0（Chhikara 等人，2025）将记忆视为并行运行的三个存储——向量存储用于语义相似性，KV 存储用于快速事实查询，图存储用于实体关系推理。检索时一个评分层对三者进行融合。这是 2026 年外部记忆的生产标准。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 07（MemGPT）、Phase 14 · 08（Letta 块）  
**预计时间：** 约 75 分钟

## 学习目标

- 解释为什么单一存储（仅向量、仅图或仅 KV）不足以支撑智能体记忆。
- 说出 Mem0 的三个并行存储及各自优化的内容。
- 描述 Mem0 的融合评分——相关性、重要性、新近度——以及为什么它是加权和而非层次结构。
- 用标准库实现一个玩具三存储记忆，包含写入所有三个存储的 `add()` 和融合结果的 `search()`。

## 问题所在

单一存储对三类查询中的某一类是错误的：

- **语义相似性** — "我们上周讨论过智能体漂移什么？" 向量胜出；KV 和图存储遗漏。
- **事实查询** — "用户的电话号码是什么？" KV 胜出；向量是浪费，图是杀鸡用牛刀。
- **关系推理** — "哪些客户共享相同的账单实体？" 图胜出；向量和 KV 无法回答。

生产智能体在一个会话中会提出所有三类查询。单一存储的记忆总会对其中两类查询出错。Mem0 的贡献是将三者连接在单一的 `add`/`search` 接口后面，并用评分函数融合它们。

## 核心概念

### 三个并行存储

Mem0（arXiv:2504.19413，2025 年 4 月）在 `add(text, user_id, metadata)` 时：

1. 从文本中提取候选事实（一个 LLM 驱动的步骤）。
2. 将每个事实写入向量存储（嵌入）用于语义搜索。
3. 将每个事实写入以 (user_id, fact_type, entity) 为键的 KV 存储，用于 O(1) 查询。
4. 将每个事实作为类型化边写入图存储（Mem0g），用于关系查询。

在 `search(query, user_id)` 时：

1. 向量存储按嵌入余弦返回 top-k。
2. KV 存储返回以查询派生的 (user_id, type, entity) 为键的直接命中。
3. 图存储返回从查询实体可达的子图。
4. 评分层融合三者。

### 融合评分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性（Relevance）** — 向量余弦、KV 精确匹配、图路径权重。
- **重要性（Importance）** — 写入时标记或习得（某些事实更重要：姓名、ID、策略）。
- **新近度（Recency）** — 自上次写入或读取以来的指数衰减。

权重按产品调整。聊天智能体 `w_recency` 更高；合规智能体 `w_importance` 更高；检索智能体 `w_relevance` 更高。

### Mem0g 与时序推理

Mem0g 添加了冲突检测器。当新事实与现有边矛盾时，现有边被标记为无效但不删除。时序查询（"用户在三月的城市是什么？"）遍历在该时间有效的子图。

这是 Letta 的失效模式所推广的合规级行为。

### 基准数字

Mem0 论文报告（2025）：

- **LoCoMo**（长文本对话记忆）：91.6
- **LongMemEval**（长序列情景记忆）：93.4
- **BEAM 1M**（100 万 token 记忆基准）：64.1

对比基线（全上下文 128k LLM、平铺向量存储、平铺 KV）都落后 10+ 个百分点。单凭基准数字不足以决定选择——操作形态才是决定性因素——但这些数字表明融合设计不是四舍五入的误差。

### 范围分类

Mem0 按范围划分记忆：

- **用户记忆（User memory）** — 跨会话持久，以 `user_id` 为键。
- **会话记忆（Session memory）** — 在单个线程内持久。
- **智能体记忆（Agent memory）** — 每个智能体实例的状态。

每次写入选择一个范围。检索可以跨范围查询，带有每范围权重。不加思考地混合范围是导致"助手把 Bob 的项目告诉了 Alice"事件的原因。

### 这个模式在哪里出错

- **嵌入漂移。** 在前一百次查询中看起来正确的向量结果随着语料库增长而退化。定期对使用最频繁的前 N 条记录重新嵌入。
- **KV 模式蔓延。** `(user_id, type, entity)` 看起来简单，直到每个团队都添加了自己的 `type`。每季度审计类型集合。
- **图爆炸。** 一个嘈杂的提取器每条消息添加 50 条边。限制每次 `add` 调用的图写入量；丢弃低置信度的边。

## 构建它

`code/main.py` 用标准库实现三存储模式：

- `VectorStore` — 以朴素 token 重叠相似度作为嵌入替代。
- `KVStore` — 以 `(user_id, fact_type, entity)` 为键的字典。
- `GraphStore` — 类型化边（主体、关系、客体、有效性）。
- `Mem0` — 带 `add()`、`search()`、融合评分和范围感知检索的顶层门面。
- 在多用户、多会话对话上的完整演示追踪。

运行：

```
python3 code/main.py
```

输出显示三条独立的召回路径加上融合后的 top-k。在 `main()` 顶部翻转评分权重，观察排名变化。

## 使用它

- **Mem0（Apache 2.0）** — 生产就绪。使用 Postgres + Qdrant + Neo4j 自托管，或使用托管云。
- **Letta** — 三层核心/回忆/归档；自带向量和图后端。
- **Zep** — 带时序知识图和事实提取的商业替代方案。
- **自定义构建** — 需要精确控制提取器（合规）或融合权重（新近度主导的语音智能体）时。

## 交付它

`outputs/skill-hybrid-memory.md` 生成一个带融合评分器、范围分类和时序失效连接的三存储记忆脚手架。

## 练习

1. 将玩具向量相似度替换为真实的嵌入模型（sentence-transformers、Ollama、OpenAI 嵌入）。在合成长对话上测量 recall@10。经过 1000 次写入后排名会漂移吗？
2. 添加时序查询：`search(query, as_of=timestamp)`。只返回在该时间点或之前有效的记录。哪个存储需要做最多工作？
3. 实现冲突检测器：如果新事实与图边矛盾，使旧边失效并记录两者。用"用户住在柏林" -> "用户住在里斯本"测试。
4. 将融合评分器扩展到包含 `user_feedback` 维度（对检索到的记录点赞）。如何防止滥用（智能体只返回它已经喜欢的记录）？
5. 阅读 Mem0 文档（`docs.mem0.ai`）。将玩具移植到 `mem0` 客户端调用。在相同的 20 个测试查询上比较检索质量。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 混合记忆（Hybrid memory） | "向量加图加 KV" | 并行写入三个存储，检索时融合。 |
| 事实提取（Fact extraction） | "记忆摄入" | 将文本分解为（实体、关系、事实）元组的 LLM 步骤。 |
| 融合评分（Fusion scoring） | "相关性排名" | 相关性、重要性、新近度的加权和。 |
| 范围（Scope） | "记忆命名空间" | 用户/会话/智能体——决定谁能看到什么。 |
| Mem0g | "记忆图" | 带时序有效性的类型化边，用于关系查询。 |
| 时序失效（Temporal invalidation） | "软删除" | 标记矛盾的边为无效；永不删除。 |
| 嵌入漂移（Embedding drift） | "检索衰退" | 随语料库增长，向量质量退化；定期重新嵌入。 |
