# 记忆块与睡眠时计算（Letta）（Memory Blocks and Sleep-Time Compute — Letta）

> MemGPT 在 2024 年变成了 Letta。2026 年的演进增加了两个理念：模型可以直接编辑的离散功能记忆块，以及在主智能体空闲时异步整合记忆的睡眠时智能体。这就是如何将记忆扩展到单次对话之外的方法。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 07（MemGPT）  
**预计时间：** 约 75 分钟

## 学习目标

- 说出 Letta 使用的三个记忆层（核心、回忆、归档）及各自的作用。
- 解释记忆块模式：Human 块、Persona 块和用户定义块作为一等类型对象。
- 描述睡眠时计算是什么，为什么它位于关键路径之外，以及为什么它可以运行比主智能体更强大的模型。
- 实现一个脚本化的双智能体循环：主智能体服务响应，睡眠时智能体在轮次之间整合块。

## 问题所在

MemGPT（第 07 课）解决了虚拟内存的控制流问题。随后出现了三个生产问题：

1. **延迟。** 每个记忆操作都在关键路径上。如果智能体必须在用户等待时进行剪枝、摘要或调和，尾延迟会爆炸。
2. **记忆腐烂。** 写入不断积累。相互矛盾的事实继续存在。检索在过时内容中溺没。
3. **结构丢失。** 平铺的归档存储无法表达"Human 块始终在提示中；Persona 块始终在提示中；Task 块每会话切换"。

Letta（letta.com）是 2026 年的重写版本。记忆块使结构明确；睡眠时计算将整合移出关键路径。

## 核心概念

### 三个层级

| 层级 | 范围 | 所在位置 | 由谁写入 |
|------|------|----------|----------|
| 核心（Core） | 始终可见 | 主提示内部 | 智能体工具调用 + 睡眠时重写 |
| 回忆（Recall） | 对话历史 | 可检索 | 自动轮次日志 |
| 归档（Archival） | 任意事实 | 向量 + KV + 图 | 智能体工具调用 + 睡眠时摄入 |

核心是 MemGPT 的核心层。回忆是对话缓冲区及其被驱逐的尾部。归档是外部存储。这种分层清理了 MemGPT 双层的过载问题。

### 记忆块

块是核心层的一个类型化、持久化、可编辑的部分。原始 MemGPT 论文定义了两种：

- **Human 块** — 关于用户的事实（姓名、角色、偏好、目标）。
- **Persona 块** — 智能体的自我概念（身份、语气、约束）。

Letta 将其推广到任意用户定义的块：用于当前目标的 `Task` 块、用于代码库事实的 `Project` 块、用于硬约束的 `Safety` 块。每个块都有 `id`、`label`、`value`、`limit`（字符上限）、`description`（让模型知道何时编辑它）。

块可通过工具接口编辑：

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — 压缩接近上限的块。

### 睡眠时计算

2025 年 Letta 的新增功能：在后台、关键路径之外运行第二个智能体。睡眠时智能体处理对话转录和代码库上下文，将 `learned_context` 写入共享块，并整合或使归档记录失效。

由此产生的特性：

- **无延迟成本。** 主响应不需要等待记忆操作。
- **允许使用更强大的模型。** 睡眠时智能体可以使用更昂贵、更慢的模型，因为它不受延迟约束。
- **自然的整合窗口。** 在用户不等待时进行去重、摘要、使矛盾事实失效。

这种形态与人类的工作方式一致：你做任务，睡一觉，长期记忆在夜间沉淀。

### Letta V1 与原生推理

Letta V1（`letta_v1_agent`，2026）废弃了 `send_message`/心跳和内联 `Thought:` token，转而支持原生推理。Responses API（OpenAI）和带扩展思考的 Messages API（Anthropic）在独立通道上输出推理，跨轮次传递（在生产环境中跨提供商加密）。控制循环仍然是 ReAct。思考轨迹是结构化的，而非提示形状。

### 这个模式在哪里出错

- **块膨胀。** 无限 `block_append` 很快达到上限。在写入超出上限之前触发块摘要器。
- **静默漂移。** 睡眠时智能体重写了一个块，主智能体从未注意到。给块添加版本控制，在追踪中呈现差异。
- **投毒的整合。** 睡眠时智能体将攻击者可访问的内容处理到核心层。第 27 课的内容同样适用于睡眠时接口。

## 构建它

`code/main.py` 实现了：

- `Block` — id、label、value、limit、description。
- `BlockStore` — CRUD + `near_limit(label)` 辅助方法。
- 两个脚本化智能体——`PrimaryAgent` 服务一个轮次，`SleepTimeAgent` 在轮次之间整合。
- 一个追踪，显示三轮次对话中的块写入，以及一个摘要块并使过时事实失效的睡眠时过程。

运行：

```
python3 code/main.py
```

转录显示了分离：主轮次快速且产生原始写入；睡眠时过程进行压缩和清理。

## 使用它

- **Letta**（letta.com）提供参考实现，支持自托管或托管云。
- **Claude Agent SDK 技能**作为块形状的知识——技能是智能体按需加载的命名、版本化、可检索的指令块。
- **自定义构建**，适用于希望控制存储后端的团队。使用 Letta API 契约，以便以后可以迁移。

## 交付它

`outputs/skill-memory-blocks.md` 为任何运行时生成一个 Letta 形态的块系统，带有睡眠时钩子，包括安全规则和引用连接。

## 练习

1. 添加一个 `block_summarize` 工具，当 `near_limit` 返回 true 时用模型生成的摘要替换块值。哪个触发阈值能最小化摘要调用次数和块溢出？
2. 在归档上实现睡眠时去重：文本 token 重叠 >90% 的两条记录合并为一条。只在睡眠时过程中执行，永远不在关键路径上。
3. 给块添加版本控制。每次写入时记录旧值和差异。暴露 `block_history(label)` 供操作员调试"为什么智能体忘记了 X"。
4. 将睡眠时智能体视为不受信任的写入者。当它们修改 Persona 或 Safety 块时，要求第二个智能体审查后再提交。
5. 将示例移植到使用 Letta API（`letta_v1_agent`）。块模式有什么变化，原生推理如何改变追踪形态？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 记忆块（Memory block） | "可编辑的提示部分" | 核心记忆的类型化、持久化、LLM 可编辑部分。 |
| Human 块（Human block） | "用户记忆" | 关于用户的事实，固定在核心层。 |
| Persona 块（Persona block） | "智能体身份" | 自我概念、语气、约束，固定在核心层。 |
| 睡眠时计算（Sleep-time compute） | "异步记忆工作" | 第二个智能体在关键路径之外进行整合。 |
| 核心/回忆/归档（Core / Recall / Archival） | "三层" | 三层记忆分割：始终可见 / 对话 / 外部。 |
| 块上限（Block limit） | "字符上限" | 每个块的字符限制；强制进行摘要。 |
| 原生推理（Native reasoning） | "思考通道" | 提供商级别的推理输出，而非提示级别的 `Thought:`。 |
| 习得上下文（Learned context） | "睡眠时输出" | 睡眠时智能体写入共享块的事实。 |
