# Reflexion：语言强化学习（Reflexion: Verbal Reinforcement Learning）

> 基于梯度的强化学习需要数千次试验和 GPU 集群才能修正一个失败模式。Reflexion（Shinn 等人，NeurIPS 2023）用自然语言实现：每次试验失败后，智能体写下一段反思，存入情景记忆，并在下一次试验时以该记忆为条件。这就是 Letta 的睡眠时计算、Claude Code 的 CLAUDE.md 学习机制和 pro-workflow 的 learn-rule 背后的模式。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 01（智能体循环）、Phase 14 · 02（ReWOO）  
**预计时间：** 约 60 分钟

## 学习目标

- 说出 Reflexion 的三个组件（执行者、评估者、自我反思者）以及情景记忆的作用。
- 用标准库实现一个包含二元评估器、反思缓冲区和全新重试的 Reflexion 循环。
- 针对给定任务，在标量反馈、启发式反馈和自我评估反馈之间做出选择。
- 解释语言强化为什么能捕获基于梯度的强化学习需要数千次试验才能修正的错误。

## 问题所在

智能体任务失败了。在标准强化学习中，你需要运行数千次试验、计算梯度、更新权重。代价高、速度慢，而且大多数生产智能体没有针对每次失败的训练预算。

Reflexion（Shinn 等人，arXiv:2303.11366）提出了另一个问题：如果智能体只是思考自己为什么失败，然后带着这个思考在提示中再试一次，会怎样？无需权重更新，无需梯度，只需在试验之间存储的自然语言。

结果：在 ALFWorld 上超过了 ReAct 和其他非微调基线。在 HotpotQA 上优于 ReAct。在代码生成（HumanEval/MBPP）上达到当时的最新水平。这一切都没有进行任何梯度计算。

## 核心概念

### 三个组件

```
执行者（Actor）      ：生成轨迹（ReAct 风格循环）
评估者（Evaluator）  ：评分轨迹——二元、启发式或自我评估
自我反思者（Self-Reflector）：对失败写下自然语言反思
```

加上一个数据结构：

```
情景记忆（Episodic memory）：历史反思列表，在下一次试验的提示中前置
```

一次试验运行执行者。评估者为其评分。如果分数低，自我反思者生成一段反思（"我选错了工具，因为我把问题误读为询问 X，而实际上是询问 Y"）。反思进入情景记忆。下一次试验重新开始，但能看到这段反思。

### 三种评估器类型

1. **标量** — 外部二元信号。ALFWorld 成功或失败，HumanEval 测试通过或失败。最简单，信号最强。
2. **启发式** — 预定义的失败特征。"如果智能体连续两次执行相同动作，标记为卡住。""如果轨迹超过 50 步，标记为低效。"
3. **自我评估** — LLM 对自己的轨迹评分。在没有真实标准时需要。信号较弱；与工具接地验证配合使用效果更好（第 05 课——CRITIC）。

2026 年的默认做法是混合使用：有真实标准时用标量，没有时用自我评估，启发式规则作为安全护栏。

### 为什么这能推广

Reflexion 与其说是一种新算法，不如说是一种有名字的模式。几乎每个生产级"自愈"智能体都运行某种变体：

- Letta 的睡眠时计算（第 08 课）：一个独立的智能体对过去的对话进行反思并写入记忆块。
- Claude Code 的 `CLAUDE.md` / "保存记忆"模式：反思被捕获为学习内容，前置到未来的会话中。
- pro-workflow 的 `/learn-rule` 命令：纠正内容被捕获为明确的规则。
- LangGraph 的反思节点：一个对输出评分并在需要时路由到精炼节点的节点。

所有这些都来自同一洞察：自然语言是一种足够丰富的媒介，可以在运行之间传递"我从失败中学到的东西"。

### 何时有效，何时无效

Reflexion 在以下情况有效：

- 有清晰的失败信号（测试失败、工具错误、错误答案）。
- 任务类型是可复现的（同类问题可以再次提问）。
- 反思有空间在轨迹上改进（足够的动作预算）。

Reflexion 在以下情况无效：

- 智能体第一次就成功了。
- 失败是外部原因（网络中断、工具损坏）——对"网络中断"的反思对未来的运行没有帮助。
- 反思变成迷信——存储关于偶发性错误运行的叙述。

2026 年的陷阱：记忆腐烂。反思积累；有些已经过时或错误；随着情景缓冲区增长，重新运行变慢。缓解措施：定期压缩（第 06 课）、反思的 TTL，或单独的睡眠时清理智能体（Letta）。

## 构建它

`code/main.py` 在一个玩具谜题上实现了 Reflexion：生成一个和为目标值的 3 元素列表。执行者生成候选列表；评估者检查总和；自我反思者写下一行关于出错原因的诊断。反思进入情景记忆用于下一次试验。

组件：

- `Actor` — 一个在看到反思时会改进的脚本化策略。
- `Evaluator.binary()` — 对目标总和的通过/失败判断。
- `SelfReflector` — 生成一行失败诊断。
- `EpisodicMemory` — 具有 TTL 语义的有界列表。

运行：

```
python3 code/main.py
```

追踪显示三次试验。试验 1 失败，存入一段反思；试验 2 看到反思并有所改进但仍然失败；试验 3 成功。与无反思的基线运行相比——基线会一直卡在试验 1 的答案上。

## 使用它

LangGraph 将反思作为节点模式发布。Claude Code 的 `/memory` 命令和 pro-workflow 的 `/learn-rule` 将情景缓冲区外化为 Markdown 文件。Letta 的睡眠时计算在空闲时间运行自我反思者，使主智能体保持低延迟。OpenAI Agents SDK 不直接提供 Reflexion；你可以用自定义 Guardrail（按分数拒绝轨迹）和跨运行保持的记忆 `Session` 来构建它。

## 交付它

`outputs/skill-reflexion-buffer.md` 创建并维护一个带有反思捕获、TTL 和去重功能的情景缓冲区。给定任务类型和失败情况，它生成一段真正对下一次试验有帮助的反思（而不是泛泛的"更加小心"）。

## 练习

1. 从二元评估器切换到返回距离指标（距目标有多远）的标量评估器。它收敛更快吗？
2. 为反思添加 10 次试验的 TTL。超过该点后，旧的反思是有帮助还是有害？
3. 实现启发式评估器：如果同一动作重复则将试验标记为卡住。这与自我反思者如何交互？
4. 用一个忽略反思的对抗性执行者运行 Reflexion。迫使执行者注意到反思所需的最小反思提示工程是什么？
5. 阅读 Reflexion 论文第 4 节关于 AlfWorld 的内容。从概念上重现 130% 成功率提升：与普通 ReAct 相比，关键的差异在哪里？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Reflexion | "自我纠正" | Shinn 等人 2023 年——执行者、评估者、自我反思者加情景记忆。 |
| 语言强化（Verbal reinforcement） | "无梯度学习" | 前置到下一次试验提示的自然语言反思。 |
| 情景记忆（Episodic memory） | "任务级反思" | 某类任务的历史反思有界缓冲区。 |
| 标量评估器（Scalar evaluator） | "二元成功信号" | 来自真实标准的通过/失败或数值评分。 |
| 启发式评估器（Heuristic evaluator） | "基于模式的检测器" | 预定义的失败特征（如卡死循环、步骤过多）。 |
| 自我评估器（Self-evaluator） | "LLM 评估自身轨迹" | 无真实标准时的低信号回退——与工具接地验证配合使用。 |
| 记忆腐烂（Memory rot） | "过时的反思" | 情景缓冲区充满过时条目；通过压缩/TTL解决。 |
| 睡眠时反思（Sleep-time reflection） | "异步自我反思" | 在非关键路径上运行自我反思者，使主智能体保持快速。 |
