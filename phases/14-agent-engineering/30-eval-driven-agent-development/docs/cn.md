# 评估驱动的智能体开发（Eval-Driven Agent Development）

> Anthropic 的指导："从简单的提示词开始，通过全面的评估进行优化，只有在需要时才添加多步骤智能体系统。"评估不是最后一步。它是驱动 Phase 14 每个其他选择的外部循环。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 全部课程  
**预计时间：** 约 60 分钟

## 学习目标

- 说出三个评估层——静态基准测试、自定义离线、在线生产——及各自的用途。
- 解释评估器-优化器紧密循环。
- 描述 2026 年最佳实践：评估与代码并列，在 CI 中运行，为 PR 设门控。
- 将 Phase 14 的每一课与它生成的评估案例关联起来。

## 问题所在

智能体能通过演示。它们以演示无法预测的方式在生产中失败。基准测试回答"这个模型是否具有广泛能力？"而不是"这个智能体是否为我的产品提交了正确的补丁？"答案：三个层次的评估，持续运行，每个护栏和学到的规则都映射到评估案例。

## 核心概念

### 三个评估层

1. **静态基准测试** — 代码用 SWE-bench Verified（第 19 课），浏览/桌面用 WebArena/OSWorld（第 20 课），通用用 GAIA（第 19 课），工具使用用 BFCL V4（第 06 课）。用于跨模型比较和回归门控。污染是真实的：SWE-bench+ 发现 32.67% 的解决方案泄露。始终报告 Verified / 审计过的分数。

2. **自定义离线评估** — 你产品的形态：
   - LLM 作为评判（Langfuse、Phoenix、Opik——第 24 课）。
   - 基于执行（运行补丁，检查测试）。
   - 基于轨迹（将动作序列与黄金对比；OSWorld-Human 显示顶级智能体超出黄金 1.4-2.7 倍）。

3. **在线评估** — 生产：
   - 会话回放（Langfuse）。
   - 护栏触发的警报（第 16、21 课）。
   - 每步成本/延迟追踪（第 23 课 OTel 跨度）。

### 评估器-优化器（Anthropic）

紧密循环：

1. 提议者生成输出。
2. 评估器判断。
3. 精炼直到评估器通过。

这是 Self-Refine（第 05 课）的推广。你关心的任何智能体流程都可以包装在评估器-优化器中以提高可靠性。

### 2026 年最佳实践

- 评估与代码并列。
- 在每次 PR 的 CI 中运行。
- 根据评估分数门控合并（例如"相比 main 无超过 5% 的回归"）。
- 每个护栏映射到一个评估案例。
- 每个学到的规则（Reflexion、pro-workflow 学习规则）映射到一个失败案例。

### 评估驱动开发在哪里失败

- **没有基线。** 没有最后已知良好状态的评估是不可读的。存储基线。
- **没有基础的 LLM 评判。** 评判者也会幻觉。CRITIC 模式（第 05 课）——评判者基于外部工具。
- **对评估过度拟合。** 针对评估优化会偏离生产实用性。轮换案例。
- **不稳定的评估。** 非确定性案例导致误报。固定种子，快照状态。

## 构建它

`code/main.py` 是一个标准库评估框架：

- 带类别（基准测试、自定义、在线）的案例注册表。
- 一个被测试的脚本化智能体。
- 评估器-优化器循环：提议、判断、精炼直到通过或达到最大轮次。
- CI 门控：聚合通过率 + 与基线的回归比较。

运行：

```
python3 code/main.py
```

输出：每个案例的通过/失败、回归标志、CI 门控判决。

## 使用它

- 在与智能体代码相同的仓库中编写评估案例。
- 通过 CI 在每次 PR 上运行它们。
- 回归时使构建失败。
- 随时间追踪通过率。
- 将每次生产失败与一个新案例关联。

## 交付它

`outputs/skill-eval-suite.md` 为智能体产品构建一个带 CI 门控和回归追踪的三层评估套件。

## 练习

1. 拿出你的一次生产失败。编写一个能重现它的评估案例。你的智能体现在能通过它吗？
2. 为你的领域构建一个带三个维度（事实性、语气、范围）的 LLM 评判评分标准。对 50 个会话评分。
3. 将评估套件连接到 CI。在 >= 5% 回归时使构建失败。
4. 添加轨迹效率指标：智能体比黄金轨迹多用了多少步？
5. 将 Phase 14 的每一课映射到你套件中的一个评估案例。有缺失的吗？那就是需要填补的空白。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Static benchmark（静态基准测试） | "现成评估" | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| Custom offline eval（自定义离线评估） | "领域评估" | 在你的产品形态上的 LLM 评判/执行/轨迹 |
| Online eval（在线评估） | "生产评估" | 会话回放、护栏警报、成本/延迟追踪 |
| Evaluator-optimizer（评估器-优化器） | "提议-评判-精炼" | 迭代直到评判者通过 |
| CI gate（CI 门控） | "合并阻断器" | 评估回归时使构建失败 |
| Baseline（基线） | "最后已知良好状态" | 用于检测回归的参考分数 |
| Trajectory efficiency（轨迹效率） | "超过黄金的步骤数" | 智能体步骤数除以人类专家最小步骤数 |
