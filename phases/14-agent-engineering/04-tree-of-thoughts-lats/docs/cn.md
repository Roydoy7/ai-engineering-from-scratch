# 思维树与 LATS：有计划的搜索（Tree of Thoughts and LATS: Deliberate Search）

> 单一的思维链轨迹没有回溯的余地。ToT（Yao 等人，2023）将推理变成一棵树，在每个节点上进行自我评估。LATS（Zhou 等人，2024）在蒙特卡洛树搜索框架下统一了 ToT、ReAct 和 Reflexion。24 点游戏的准确率从 4%（CoT）提升到 74%（ToT）；LATS 在 HumanEval 上达到 92.7% pass@1。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 01（智能体循环）、Phase 14 · 03（Reflexion）  
**预计时间：** 约 75 分钟

## 学习目标

- 将推理框架化为搜索：节点是"思考"，边是"扩展"，值是"有多大前景"。
- 用标准库实现 ToT 风格的 BFS 树搜索，带有自我评估评分。
- 扩展为带有选择/扩展/模拟/反向传播的玩具 LATS MCTS 循环。
- 决定何时搜索值得付出 token 倍增的代价（24 点游戏、代码生成），何时单一轨迹就足够（简单问答）。

## 问题所在

思维链是线性的。如果第一步错了，后续每一步都建立在错误的前提上。在 24 点游戏（用四个数字通过 + − × ÷ 凑出 24）中，GPT-4 CoT 的准确率只有 4%。模型早早选错了子表达式，无法恢复。

推理需要的是提出多个候选方案、评估它们、选择有前景的方案，并在遇到死胡同时回溯的能力。这就是搜索。思维树和 LATS 是两种规范的表述。

## 核心概念

### 思维树（Yao 等人，NeurIPS 2023）

每个节点是一个连贯的中间步骤（"一个思考"）。每个节点可以扩展出 K 个子思考。LLM 用评分提示对每个节点进行自我评估。搜索探索这棵树——BFS、DFS 或束搜索。

```
                     （根节点："用 4 6 4 1 凑 24"）
                    /               |            \
           （"6 - 4 = 2"）    （"4 + 1 = 5"）    （"4 * 6 = 24"）  <- 评分：高
              /   \              |                  |
          ...    ...          ...                完成
```

自我评估是承重的部分。论文展示了三种变体：`sure / likely / impossible` 分类、`1..10` 数值评分和候选人投票。三种方式在 24 点游戏上都显著超过 CoT（GPT-4 从 4% 提升到 74%）。

### LATS（Zhou 等人，ICML 2024）

LATS 在蒙特卡洛树搜索（MCTS）框架下统一了 ToT、ReAct 和 Reflexion。LLM 扮演三个角色：

- **策略（Policy）**：提出候选下一步动作（ReAct 风格）。
- **价值函数（Value function）**：为部分轨迹评分（ToT 风格自我评估）。
- **自我反思者（Self-reflector）**：失败时写下自然语言反思（Reflexion 风格），用于重新播种未来的展开。

环境反馈（观察）融入价值函数，使搜索基于真实工具结果而非仅凭模型意见。论文发表时的结果：GPT-4 在 HumanEval pass@1 达到 92.7%（SOTA），GPT-3.5 在 WebShop 平均达到 75.9（接近基于梯度的微调）。

### 最简化的 MCTS

每次迭代的四个阶段：

1. **选择（Select）** — 使用 UCT（树的上置信界）从根节点走到叶节点。
2. **扩展（Expand）** — 通过策略生成 K 个子节点。
3. **模拟（Simulate）** — 从子节点用策略展开，用价值函数（或环境奖励）为叶节点评分。
4. **反向传播（Backpropagate）** — 沿路径向上更新访问计数和价值估计。

UCT 公式：`Q(s, a) + c * sqrt(ln N(s) / N(s, a))`。第一项是利用；第二项是探索。针对每个任务调整 `c`。

### 成本现实

搜索会使 token 用量爆炸。ToT 在 24 点游戏上使用的 token 是 CoT 的 100-1000 倍。LATS 类似。这不是免费的；搜索应保留用于：

- 单一轨迹明显不足的任务（24 点游戏、复杂代码）。
- 正确性比耗时更重要的任务。
- 有廉价可靠价值函数的任务（代码的单元测试、数学的显式目标）。

如果你的任务有唯一正确答案但评估器噪声大，搜索通常会使情况变差——它会找到一个"高分"的错误答案。

### 2026 年的定位

大多数生产智能体不运行 LATS。它们运行带有工具接地验证的 ReAct（CRITIC，第 05 课）。搜索出现在专业的小众领域：

- 以测试作为价值函数的代码智能体（HumanEval 风格）。
- 探索多条查询路径的深度研究智能体。
- LangGraph 子图中以规划为主的工作流。

AlphaEvolve（第 11 课）是 2025 年的极端案例：对代码进行进化搜索，机器可验证的适应度，前沿成果（56 年来首次改进 4x4 矩阵乘法）。

## 练习

1. 用 UCT c=0.1 vs c=2.0 运行玩具 LATS。追踪有什么变化？
2. 将价值函数替换为噪声更大的评分器（添加随机抖动）。MCTS 还能找到最佳叶节点吗？它能容忍的最小信噪比是多少？
3. 实现束搜索 ToT（每层保留 top-k）并与 BFS 比较。在严格的 token 预算下哪个更好？
4. 阅读 LATS 论文第 5.1 节。重现 HumanEval 轨迹计数：达到报告的 pass@1 需要多少次展开？
5. 阅读 LATS 论文关于"LATS 帮助较少时"的讨论。写一段将任务形态映射到搜索策略的决策规则。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 思维树（Tree of Thoughts） | "分支 CoT" | Yao 等人——带有自我评估的思考节点树。 |
| LATS | "LLM 的 MCTS" | Zhou 等人——在 MCTS 框架下统一 ToT + ReAct + Reflexion。 |
| UCT | "上置信界" | 平衡利用（Q）和探索（ln N / n）的选择公式。 |
| 价值函数（Value function） | "这个状态有多好" | 基于提示的 LLM 评分或环境奖励；用于反向传播。 |
| 策略（Policy） | "动作提议者" | ReAct 风格的生成器；输出候选的下一个思考/动作。 |
| 展开（Rollout） | "模拟轨迹" | 用策略从节点走到叶节点，用价值评分。 |
| 反向传播（Backpropagate） | "更新祖先" | 将叶节点的奖励沿路径向上推，更新访问计数和 Q 值。 |
| 搜索成本（Search cost） | "token 爆炸" | 在 24 点游戏上是 CoT 的 100-1000 倍；采用前先核算预算。 |
