# 失败模式：为什么智能体会出问题（Failure Modes: Why Agents Break）

> MASFT（伯克利，2025）将 14 种多智能体失败模式归类为 3 个类别。微软的分类法记录了现有 AI 失败如何在智能体环境中被放大。行业现场数据收敛于五种反复出现的模式：幻觉动作、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 05（Self-Refine 与 CRITIC）、Phase 14 · 24（可观测性）  
**预计时间：** 约 60 分钟

## 学习目标

- 说出 MASFT 的三个失败类别，以及每个类别中至少四种具体模式。
- 解释为什么智能体失败会放大现有的 AI 失败模式（偏见、幻觉）。
- 描述五种行业反复出现的模式及其缓解措施。
- 实现一个用失败模式标签标记智能体追踪的标准库检测器。

## 问题所在

团队发布的智能体在 90% 的追踪上能正常工作。10% 的失败不是随机噪音——它们落入少数几个反复出现的类别。一旦你能说出它们的名字，你就能监控它们并修复它们。

## 核心概念

### MASFT（伯克利，arXiv:2503.13657）

多智能体系统失败分类法。14 种失败模式聚类为 3 个类别。标注者间 Cohen's Kappa 0.88——这些类别是可靠地可区分的。

核心主张：失败是多智能体系统中的根本设计缺陷，而非可通过更好基础模型修复的 LLM 局限性。

### 微软《智能体 AI 系统失败模式分类法》

- 现有 AI 失败（偏见、幻觉、数据泄露）在智能体环境中被放大。
- 新失败来自自主性：大规模非预期动作、工具误用、使命漂移。
- 该白皮书是智能体产品的风险登记册。

### 《智能体 AI 中的故障表征》（arXiv:2603.06847）

- 失败来源于编排、内部状态演化和环境交互。
- 不仅仅是"坏代码"或"坏模型输出"。

### LLM 智能体幻觉调查（arXiv:2509.18970）

两种主要表现：

1. **遵从指令偏差** — 智能体不遵循系统提示词。
2. **长程上下文误用** — 智能体忘记或错误应用早期轮次的上下文。

子意图错误：遗漏（错过步骤）、冗余（重复步骤）、无序（步骤顺序错误）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026 年现场分析收敛于：

1. **幻觉动作（Hallucinated actions）。** 智能体调用不存在的工具或捏造参数。
2. **范围蔓延（Scope creep）。** 智能体将任务扩展到超出用户要求的范围（创建额外的 PR，发送额外的邮件）。
3. **级联错误（Cascading errors）。** 一次错误调用触发下游效应。幻觉 SKU 触发四次 API 调用——一个多系统事件。
4. **上下文丢失（Context loss）。** 长期任务忘记早期轮次的约束。
5. **工具误用（Tool misuse）。** 用错误参数调用正确工具，或完全调用错误工具。

级联是最致命的。智能体无法区分"我失败了"和"任务不可能完成"，经常在 400 错误上幻觉出成功消息以关闭循环。

### 缓解措施：每步门控

在推理链的每个步骤自动验证门控，对照环境状态检查事实基础。具体来说：

- 每步安全分类器（第 21 课）。
- 工具调用参数验证（第 06 课）。
- 对照已知事实交叉检查检索到的内容（第 05 课，CRITIC）。
- 通过重新探测状态来检测成功幻觉（文件真的被创建了吗？）。

### 失败监控在哪里出错

- **只标记崩溃。** 大多数智能体失败会产生看起来有效的输出。需要内容级检查。
- **没有基线。** 漂移检测需要一个最后已知良好状态；没有它，你无法说"这变得更糟了"。
- **过度警报。** 每次失败都产生一个页面。聚类和速率限制。

## 构建它

`code/main.py` 实现了一个标准库失败模式标记器：

- 覆盖五种模式的合成追踪数据集。
- 每种模式的检测器函数（工具调用、输出、重复动作的签名模式）。
- 标记每条追踪并报告模式分布的标记器。

运行：

```
python3 code/main.py
```

输出：每条追踪的标签 + 聚合分布，是 Phoenix 追踪聚类呈现内容的低成本复现。

- **Phoenix** 用于生产漂移聚类（第 24 课）。
- **Langfuse** 用于会话回放 + 标注。

## 练习

1. 添加"成功幻觉"检测器：智能体返回成功但目标状态未变化。
2. 标记你构建的产品的 100 条真实追踪。哪种模式占主导？修复它的成本是多少？
3. 实现"级联半径"指标：给定步骤 N 的失败，它影响了多少下游步骤？
4. 阅读 MASFT 的 14 种失败模式。选择三种适用于你产品的。编写检测器。
5. 将一个检测器连接到 CI 任务：如果 >= 5% 的追踪标记某种模式，则使构建失败。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| MASFT | "多智能体失败分类法" | 伯克利 14 模式分类 |
| Cascading error（级联错误） | "涟漪失败" | 早期一个错误在 N 步中传播 |
| Context loss（上下文丢失） | "忘记了约束" | 长期轮次丢弃早期轮次的事实 |
| Tool misuse（工具误用） | "错误工具 / 错误参数" | 有效调用，错误调用方式 |
| Success hallucination（成功幻觉） | "伪造完成" | 智能体在 400 错误上声称成功；状态未变化 |
| Scope creep（范围蔓延） | "过度扩展" | 智能体做的比要求的多 |
| Instruction-following deviation（遵从指令偏差） | "不服从" | 忽略系统提示词或用户约束 |
| Sub-intention errors（子意图错误） | "计划缺陷" | 计划执行中的遗漏、冗余、无序 |
