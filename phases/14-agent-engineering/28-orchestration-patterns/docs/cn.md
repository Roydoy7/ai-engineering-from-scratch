# 编排模式：监督者、群体、层次（Orchestration Patterns: Supervisor, Swarm, Hierarchical）

> 四种编排模式在 2026 年的框架中反复出现：监督者-工作者、群体/对等、层次、辩论。Anthropic 的指导："重要的是为你的需求构建正确的系统。"从简单开始；只有在单个智能体加五种工作流模式不足时，才添加拓扑。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 14 · 12（工作流模式）、Phase 14 · 25（多智能体辩论）  
**预计时间：** 约 60 分钟

## 学习目标

- 说出四种反复出现的编排模式及各自的适用场景。
- 描述 2026 年 LangChain 的建议：基于工具调用的监督 vs 监督者库。
- 解释 Anthropic 的"构建正确系统"规则及其如何约束拓扑选择。
- 在标准库中针对共同的脚本化 LLM 实现所有四种模式。

## 问题所在

团队在需要之前就采用"多智能体"。四种模式在框架中反复出现；一旦你能说出它们的名字，你就能选择正确的一种——或者完全跳过拓扑。

## 核心概念

### 监督者-工作者

- 一个中央路由 LLM 分发给专家智能体。
- 决定：回环到自身、交接给专家、终止。
- 专家之间不互相交流；所有路由都通过监督者。

框架：LangGraph `create_supervisor`、Anthropic 编排者-工作者、CrewAI Hierarchical Process。

**2026 年 LangChain 建议：** 通过直接工具调用而非 `create_supervisor` 来实现监督。提供更精细的上下文工程控制——你决定每个专家看到什么。

### 群体/对等

- 智能体通过共享工具接口直接交接。
- 没有中央路由器。
- 比监督者延迟更低（更少跳数）。
- 更难推理（没有单点控制）。

框架：LangGraph 群体拓扑、OpenAI Agents SDK 交接（当所有智能体都可以交接给所有其他智能体时）。

### 层次

- 监督者管理子监督者管理工作者。
- 在 LangGraph 中实现为嵌套子图；在 CrewAI 中实现为嵌套团队。
- 以运营复杂性为代价扩展到大型智能体群体。

何时需要：当单个监督者的上下文预算无法容纳所有专家的描述时。

### 辩论

- 并行提议者 + 迭代交叉批评（第 25 课）。
- 不真正是编排——更像是验证——但在框架中作为拓扑选择出现。

### CrewAI Crew vs Flow

CrewAI 正式化了两种部署模式：

- **Flow** 用于确定性事件驱动的自动化（推荐的生产起点）。
- **Crew** 用于自主的基于角色的协作。

这与上面四种模式正交，但映射到拓扑：Flow 通常是监督者或层次；Crew 通常是带 LLM 路由器的监督者。

### Anthropic 的指导

"LLM 领域的成功不在于构建最复杂的系统。而在于为你的需求构建正确的系统。"

决策顺序：

1. 单个智能体 + 工作流模式（第 12 课）——从这里开始。
2. 监督者-工作者——当你有 2-4 个专家时。
3. 群体——当延迟比推理清晰度更重要时。
4. 层次——只有在监督者上下文预算失败时。
5. 辩论——当准确性比成本更重要时。

### 这个模式在哪里出错

- **拓扑优先思维。** "我们需要多智能体"，而不先识别多智能体解决什么问题。
- **群体中的弹跳交接。** A -> B -> A -> B。使用跳数计数器。
- **虚假层次。** 因为"企业需要"而设置三层；实际只有两个团队。折叠它。

## 构建它

`code/main.py` 在标准库中针对脚本化 LLM 实现了所有四种模式：

- `Supervisor` — 中央路由器。
- `Swarm` — 带直接交接的对等。
- `Hierarchical` — 监督者的监督者。
- `Debate` — 并行提议者 + 批评。

每种模式处理相同的三意图任务（退款 / bug / 销售）。追踪形态各不相同。

运行：

```
python3 code/main.py
```

输出：每种模式的追踪 + 操作次数。监督者最清晰；群体最简短；层次最深；辩论最昂贵。

## 使用它

- **LangGraph** 用于监督者和层次（嵌套子图）。
- **OpenAI Agents SDK** 用于工具形交接（监督者形态）。
- **CrewAI Flow** 用于生产确定性。
- **自定义** 用于辩论或需要精确控制时。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Supervisor-worker（监督者-工作者） | "路由器 + 专家" | 中央 LLM 分发给专家；专家之间不交流 |
| Swarm（群体） | "对等" | 通过共享工具直接交接；没有中央路由器 |
| Hierarchical（层次） | "监督者的监督者" | 用于大型群体的嵌套子图 |
| Debate（辩论） | "提议者 + 批评" | 并行提议者，交叉批评（第 25 课） |
| Tool-call-based supervision（基于工具调用的监督） | "没有库的监督者" | 将监督者实现为直接工具调用以进行上下文控制 |
| Crew（团队） | "自主团队" | CrewAI 的基于角色的协作模式 |
| Flow（工作流） | "确定性工作流" | CrewAI 的事件驱动生产模式 |
