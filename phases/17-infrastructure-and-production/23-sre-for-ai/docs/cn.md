# AI 的 SRE——多智能体事件响应、操作手册与预测性检测（SRE for AI — Multi-Agent Incident Response, Runbooks, Predictive Detection）

> AI SRE 使用以基础设施数据（日志、操作手册、服务拓扑）为基础的 LLM 通过 RAG 自动化调查、文档和协调阶段。2026 年的架构模式是多智能体编排——专门的智能体（日志、指标、操作手册）由监督者协调；AI 提出假设和查询，人类批准判断决定。Datadog Bits AI 和 Azure SRE Agent 将此作为托管产品提供。操作手册在演变：NeuBird Hawkeye 使用对抗性评估（两个模型分析同一事件；一致 = 高置信度，不一致 = 不确定性）；操作记忆在团队变动中持续保存。自动修复保持谨慎：AI 建议，人类批准。完全自主操作范围很窄（重启 Pod，回滚特定部署），有严格护栏——任何销售"设置后忘记"的人都在过度承诺。新兴前沿：事件前预测。MIT 研究报告称，在历史日志 + GPU 温度 + API 错误模式上训练的 LLM 提前 10-15 分钟预测了 89% 的故障。预测：到 2026 年底，95% 的企业 LLM 将具有自动故障转移功能。

**类型：** 学习  
**语言：** Python（标准库，玩具多智能体事件分流模拟器）  
**前置知识：** Phase 17 · 13（可观测性）、Phase 17 · 24（混沌工程）  
**预计时间：** 约 60 分钟

## 学习目标

- 画出多智能体 AI SRE 架构：监督者 + 专门智能体（日志、指标、操作手册）+ 人类批准门控。
- 解释为什么自动修复是窄范围的（重启 Pod，回滚部署）而非宽泛的（重新架构服务）。
- 说出对抗性评估模式（NeuBird Hawkeye）：两个模型一致 = 高置信度；不一致 = 上升。
- 引用 MIT 89% 早期检测结果以及运营约束：没有驱动操作的预测只是仪表板。

## 问题所在

值班工程师在凌晨 3 点被呼叫。"结账流程错误率高。"他们检查 Datadog、Loki、三个操作手册、部署日志。30 分钟后，他们意识到根因是 KV 缓存峰值导致的 vLLM OOM。他们重启 Pod；错误消失了。

2026 年，那次调查的前 20 分钟是可以自动化的。按服务分组日志、关联最近部署、对比操作手册——这些都是 RAG + 工具使用。受监督的智能体可以在人类打开 Datadog 之前完成初步分流并提出假设。

完全自主修复是另一个问题。重启 Pod：安全。扩展 GPU 池：如果策略允许则安全。重新架构服务：绝对不行。这门学科的核心是划定这条窄线。

## 核心概念

### 多智能体架构

```
          事件
           │
           ▼
        监督者
      /    |    \
     ▼     ▼     ▼
日志智能体 指标智能体 操作手册智能体
     │     │     │
     └─────┴─────┘
           │
           ▼
      假设 + 证据
           │
           ▼
        人类批准
           │
           ▼
     操作（窄范围集合）
```

监督者将事件分解为子查询。专门智能体有工具访问权限（日志搜索、PromQL、文档检索）。监督者综合后向人类呈现假设 + 证据。人类批准或重新引导。

### 自动修复范围

**安全（窄范围）**：重启 Pod，回滚特定部署，在预批准范围内扩展池，启用预批准的特性标志。

**不安全（宽范围）**：更改服务拓扑，修改资源限制，部署新代码，更改 IAM，修改数据库。

任何销售"设置后忘记"的人都在过度承诺。随着 AI SRE 成熟，安全集合会增长，但边界是真实存在的。

### 对抗性评估（NeuBird Hawkeye）

两个模型独立分析同一事件。如果它们对根因达成一致，置信度高。如果它们不一致，向人类上升，并显示两个假设。简单的模式，有效过滤幻觉根因。

### 操作记忆

团队流动是传统 SRE 的无声杀手——部落知识随着人员离开而消失。AI SRE 将操作手册 + 事后分析存储在向量数据库中；智能体在每次新事件时检索。新工程师加入时，AI 拥有完整历史。

### 事件前预测

MIT 2025 研究：在历史日志、GPU 温度、API 错误模式上训练的 LLM 在测试集上提前 10-15 分钟预测了 89% 的故障。

现实核查：没有驱动操作的预测只是仪表板。运营问题是"当我们预测时，我们做什么？"预防性排空？呼叫器？自动扩展？答案取决于具体策略。

### 2026 年的产品

- **Datadog Bits AI** — Datadog 内的托管 SRE 副驾驶。
- **Azure SRE Agent** — Azure 原生。
- **NeuBird Hawkeye** — 对抗性评估 + 操作记忆。
- **PagerDuty AIOps** — 分流 + 去重。
- **Incident.io Autopilot** — 事件指挥官 + 协调。

### 操作手册即代码

操作手册从 Confluence 页面演变为带结构化章节（症状、假设、验证、操作）的版本化 Markdown。结构化操作手册提供更好的 RAG 检索。任何 AI SRE 部署的起点都是将非结构化操作手册转换为结构化的。

### 你应该记住的数字

- MIT 早期检测：89% 的故障，10-15 分钟提前量。
- 多智能体分流：监督者 +（日志、指标、操作手册）+ 人类。
- 安全自动修复集合：重启 Pod，回滚部署，在范围内扩展。
- 对抗性评估：两个模型独立；一致 = 高置信度。

1. 运行 `code/main.py`。如果日志和指标智能体不一致怎么办？监督者如何解决？

3. 编写结构化操作手册模板：章节、必填字段、验证命令。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| AI SRE | "值班智能体" | 基于 LLM 的事件调查 + 协调 |
| Supervisor agent（监督者智能体） | "编排器" | 将事件分解为子查询的顶层智能体 |
| Specialized agent（专门智能体） | "领域智能体" | 有工具访问权限的子智能体（日志、指标、操作手册） |
| Auto-remediation（自动修复） | "AI 修复它" | 窄范围预批准操作；不是宽泛的重新架构 |
| Operational memory（操作记忆） | "向量操作手册" | 向量数据库中的事后分析 + 操作手册用于 RAG |
| Adversarial eval（对抗性评估） | "双模型检查" | 独立分析；一致 = 高置信度 |
| NeuBird Hawkeye | "对抗性的那个" | 带对抗性评估 + 记忆模式的产品 |
| Bits AI | "Datadog 的 SRE 智能体" | Datadog 托管 AI SRE |
| Pre-incident prediction（事件前预测） | "早期检测" | 故障预测的 10-15 分钟提前量 |
