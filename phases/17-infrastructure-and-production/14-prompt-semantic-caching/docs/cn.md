# 提示词缓存与语义缓存经济学（Prompt Caching and Semantic Caching Economics）

> **定价快照日期：2026-04。** 以下数字来自本课发布时抓取的供应商价格表；在向下游引用前请对照链接文档核实。

> 缓存在两个层次上发生。L2（供应商级别）提示词/前缀缓存对重复前缀复用注意力 KV——Anthropic 的提示词缓存文档宣称在长提示词上可节省高达 90% 的成本和 85% 的延迟；对于 Claude 3.5 Sonnet，缓存读取为 0.30 美元/百万，而新鲜调用为 3.00 美元/百万，5 分钟 TTL，1 小时 TTL 选项有 2 倍写入溢价（docs.anthropic.com，2026-04）。OpenAI 提示词缓存自动对 ≥1024 token 的提示词生效，缓存输入定价约为新鲜输入的 10%（platform.openai.com，2026-04）；确切的每模型缓存费率取决于实时价格表。L1（应用级别）语义缓存在嵌入相似度命中时完全跳过 LLM。供应商宣称的"95% 准确率"指的是匹配正确性，而非命中率——生产中报告的命中率从 10%（开放式聊天）到 70%（结构化 FAQ）不等；两家供应商都没有发布官方基线，因此这些应视为社区遥测数据而非保证。生产陷阱：并行化会破坏缓存（在第一个缓存写入完成前发出的 N 个并行请求可能使支出膨胀数倍），以及前缀中的动态内容会完全阻止缓存命中。ProjectDiscovery 报告称，通过将动态文本移出可缓存前缀（2025-11），命中率从 7% 提升到 74%。

**语言：** Python（标准库，玩具两层缓存模拟器）  
**前置知识：** Phase 17 · 04（vLLM 服务内部原理）、Phase 17 · 06（SGLang RadixAttention）

## 学习目标

- 区分 L2 提示词/前缀缓存（供应商处的 KV 复用）和 L1 语义缓存（相似提示词绕过 LLM）。
- 解释 Anthropic 的 `cache_control` 显式标记和两种 TTL 选项（5 分钟 vs 1 小时）及其价格倍数。
- 给定命中率、提示词/响应混合和 token 价格，计算预期的月度节省。
- 说出将账单膨胀 5-10 倍的并行化反模式，以及导致命中率崩溃的动态内容反模式。

## 问题所在

你为 RAG 服务添加了提示词缓存。账单持平。你测量命中率；它是 7%。你的提示词看起来是静态的，但其实不然——系统提示词包含精确到分钟格式化的当前日期、请求 ID 和为多样性随机重排的示例。每个请求都写入一个新的缓存条目，读取为零。

另一个问题，你的智能体每个用户问题并行执行十个工具调用。所有十个在第一个缓存写入完成之前到达供应商。十次写入，零次读取。你的账单是"带缓存"本应花费的 5-10 倍。

缓存是一种协议，而非一个标志。两个层次，两种不同的故障模式。

## 核心概念

### L2——供应商提示词/前缀缓存

供应商为可缓存前缀存储注意力 KV，并在下一个匹配该前缀的请求时复用。你支付一次写入成本，读取几乎免费。

**Anthropic（Claude 3.5 / 3.7 / 4 系列）**：在请求中显式使用 `cache_control` 标记。你标记哪些块是可缓存的。TTL：5 分钟（写入成本为基础价格的 1.25 倍）或 1 小时（写入成本为基础价格的 2 倍）。缓存读取：Claude 3.5 Sonnet 上 0.30 美元/百万，而新鲜输入为 3.00 美元/百万——便宜 10 倍（docs.anthropic.com，截至 2026-04）。不同模型的费率不同（Opus/Haiku 单独发布）；务必对照实时定价页面核实。

**OpenAI**：对 ≥1024 个 token 的提示词自动缓存（platform.openai.com，2026-04）。无需显式标志。当前 gpt-4o/gpt-5 价格表上，缓存输入约比新鲜输入便宜 10 倍。文档和发行说明都没有发布官方命中率基线；社区报告在精心设计提示词时集中在 30-60% 左右。监控 `usage.cached_tokens` 来测量你自己的情况。

**Google（Gemini）**：通过显式 API 进行上下文缓存；100 万 token 上下文意味着缓存收益更大。

**自托管（vLLM、SGLang）**：Phase 17 · 06 介绍了 RadixAttention——在你自己的计算资源上使用相同的模式。

### L1——应用级语义缓存

在完全调用 LLM 之前，对提示词进行哈希，嵌入它，并查找相似的缓存请求（余弦相似度高于阈值，通常 0.95+）。命中时，返回缓存的响应。未命中时，调用 LLM 并缓存结果。

开源：Redis Vector Similarity、GPTCache、Qdrant。商业：Portkey Cache、Helicone Cache。

供应商的准确率声明指的是返回的缓存响应在语义上适当的频率——而非你命中的频率。生产命中率：

- 开放式聊天：10-15%。
- 结构化 FAQ/支持：40-70%。
- 代码问题：20-30%（小变体会破坏命中）。
- 重复提示词的语音智能体：50-80%（固定语音规范化集合）。

### 并行化反模式

你的智能体并行进行 10 次工具调用。所有 10 次都有相同的 4K token 系统提示词。Anthropic 的缓存写入是每请求的；第一个缓存写入在供应商看到提示词后约 300 毫秒完成。请求 2-10 在同一毫秒窗口内到达，每个都看到缓存未命中。你支付 10 次写入溢价，0 次读取折扣。

修复方案：使用顺序优先的批处理——单独发出请求 1，然后在请求 1 的缓存已填充后发出 2-10。给第一个工具调用增加 300 毫秒；节省 5-10 倍的账单。

### 动态内容反模式

你的系统提示词看起来像这样：

```
你是一个有用的助手。当前时间是 14:32:17。
用户 ID：abc123。今天是星期二...
```

每个请求都是唯一的。每个请求都写入。零次命中。

修复方案：将所有真正静态的内容移到可缓存前缀；在缓存边界之后追加动态内容：

```
[可缓存]
你是一个有用的助手。[规则、示例、指令]
[/可缓存]
[动态，不缓存]
当前时间：14:32:17。用户：abc123。
```

ProjectDiscovery 用这种方式将命中率从 7% 提升到 74% 并发布了详细分析。

### 叠加批处理 + 缓存用于夜间工作负载

批处理 API（Phase 17 · 15）在 24 小时周期内提供 50% 折扣。再加上缓存输入，额外获得约 10 倍折扣。夜间分类、标注和报告生成工作负载通过叠加可以将成本降至同步非缓存成本的约 10%。

### 你应该记住的数字

这些定价数据截取自 2026-04 链接的供应商文档，每隔几个月就会变化——在依赖它们之前请重新核实。

- Anthropic 缓存读取：Claude 3.5 Sonnet 上 0.30 美元/百万，约比新鲜输入便宜 10 倍（docs.anthropic.com）。
- Anthropic 缓存写入溢价：1.25 倍（5 分钟 TTL）或 2 倍（1 小时 TTL）。
- OpenAI 自动缓存：适用于 ≥1024 个 token 的提示词；缓存输入定价约为当前价格表新鲜输入的 10%（platform.openai.com）。
- 语义缓存命中率（社区报告）：开放式聊天约 10%；结构化 FAQ 高达约 70%。不是供应商文档化的基线。
- ProjectDiscovery：将动态内容移出前缀后命中率从 7% 提升到 74%（项目博客，2025-11）。
- 并行化反模式：典型报告当 N 个并行请求错过第一个缓存写入时，账单膨胀 5-10 倍。

## 练习

1. 运行 `code/main.py`。切换并行化标志。账单变化了多少？
2. 你的系统提示词中有日期。将其移出。展示前后的命中率数学计算。
3. 给定你的请求到达率，计算 1 小时 TTL（2 倍写入）vs 5 分钟 TTL（1.25 倍写入）的盈亏平衡点。
4. 语义缓存在 0.95 阈值下命中率为 20%。在 0.85 时命中率为 50%，但你看到错误的缓存响应。选择正确的阈值并论证。
5. 你每个用户问题并行发出 10 个子查询。重写为缓存友好的方式，同时不增加端到端延迟。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| L2 prompt cache（L2 提示词缓存） | "前缀缓存" | 供应商为重复前缀存储 KV |
| `cache_control` | "Anthropic 缓存标记" | 标记可缓存块的显式属性 |
| Cache write premium（缓存写入溢价） | "写入税" | 首次未命中到缓存的额外成本（1.25 倍或 2 倍） |
| L1 semantic cache（L1 语义缓存） | "嵌入缓存" | 调用 LLM 之前的应用级哈希和嵌入 |
| GPTCache | "LLM 缓存库" | 流行的 OSS L1 缓存库 |
| Cache hit rate（缓存命中率） | "命中数/总数" | 从缓存服务的请求比例 |
| Parallelization anti-pattern（并行化反模式） | "N 次写入陷阱" | N 个并行请求 N 次错过缓存 |
| Dynamic content trap（动态内容陷阱） | "提示词中有时间戳的陷阱" | 前缀中的动态字节破坏命中率 |
| RadixAttention | "副本内缓存" | SGLang 的前缀缓存实现 |
