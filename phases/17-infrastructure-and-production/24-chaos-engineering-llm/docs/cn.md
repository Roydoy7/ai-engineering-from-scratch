# LLM 生产的混沌工程（Chaos Engineering for LLM Production）

> 2026 年，LLM 的混沌工程是一门独立学科。在生产中运行实验的先决条件：定义好的 SLI/SLO、追踪+指标+日志可观测性、自动回滚、操作手册、值班人员。架构有四个平面：控制（实验调度器）、目标（服务、基础设施、数据存储）、安全（守卫 + 中止 + 流量过滤器）、可观测性（指标 + 追踪 + 日志）、反馈（输入 SLO 调整）。护栏是强制的：如果每日错误预算消耗 > 预期的 2 倍，燃耗率告警会暂停实验；抑制窗口 + 追踪 ID 关联对告警噪音进行去重。节奏：每周小型金丝雀 + SLO 审查；每月演练日 + 事后分析；每季度跨团队弹性审计 + 依赖关系映射。LLM 特有实验：内存过载、网络故障、供应商中断、格式错误的提示词、KV 缓存驱逐风暴。工具：Harness Chaos Engineering（LLM 生成推荐、爆炸半径缩减、MCP 工具集成）；LitmusChaos（CNCF）；Chaos Mesh（CNCF Kubernetes 原生）。

**类型：** 学习  
**语言：** Python（标准库，玩具混沌实验运行器）  
**前置知识：** Phase 17 · 23（AI 的 SRE）、Phase 17 · 13（可观测性）  
**预计时间：** 约 60 分钟

## 学习目标

- 说出五个混沌工程先决条件（SLI/SLO、可观测性、回滚、操作手册、值班），并解释为什么跳过任何一个都会破坏这种实践。
- 画出四个平面（控制、目标、安全、可观测性）以及反馈到 SLO 的循环。
- 列举五个 LLM 特有实验（内存过载、网络故障、供应商中断、格式错误的提示词、KV 驱逐风暴）。
- 根据技术栈选择工具——Harness、LitmusChaos、Chaos Mesh。

## 问题所在

传统技术栈的混沌测试已经成熟。LLM 技术栈增加了新的故障模式。带有毒化字符的 4K token 提示词使分词器停滞 12 秒。上游供应商发出 429；你的网关重试；你的服务在重试放大的并发下发生 OOM。突发负载下的 KV 缓存驱逐风暴导致级联重新预填充，使计算资源饱和。

这些都不会在单元测试中出现。混沌工程是你在用户之前发现它们的方式。

## 核心概念

### 先决条件

不要在没有以下条件的情况下在生产中运行混沌：

1. **SLI/SLO** — 定义好的服务级别指标和目标。
2. **可观测性** — 追踪、指标、日志，连接到仪表板。
3. **自动回滚** — Phase 17 · 20 的策略标志回滚。
4. **操作手册** — 结构化的，Phase 17 · 23。
5. **值班人员** — 有人响应。

缺少任何一项意味着混沌变成真实的事件。

### 四个平面 + 反馈

**控制平面** — 实验调度器（Litmus 工作流、Chaos Mesh 调度、Harness UI）。

**目标平面** — 服务、Pod、节点、负载均衡器、数据存储。

**安全平面** — 停止开关、抑制窗口、爆炸半径限制、错误预算门控。

**可观测性平面** — 正常指标 + 追踪 ID 关联，区分混沌引起的故障与自然故障。

**反馈循环** — 发现结果反馈到 SLO 调整、操作手册更新、代码修复。

### 护栏是强制的

- **燃耗率告警**：如果每日错误预算消耗超过预期的 2 倍，暂停实验。
- **抑制窗口**：实验期间静音爆炸半径内的非实验告警。
- **追踪 ID 关联**：所有实验引起的错误都带有标签，值班人员可以去重。

### 五个 LLM 特有实验

1. **内存过载** — 通过高并发发送长上下文请求，强制 KV 缓存抢占风暴。观察：服务是优雅降载还是崩溃？

2. **网络故障** — 切断推理网关与供应商之间的连接。观察：故障转移是否在 SLA 内启动？（Phase 17 · 19）

3. **供应商中断模拟** — OpenAI 100% 429。观察：路由是否故障转移到 Anthropic？（Phase 17 · 16，19）

4. **格式错误的提示词** — 注入使分词器停滞的负载（例如，深层嵌套的 Unicode，巨大的 UTF-8 码点）。观察：单个请求是否会锁定工作进程？

5. **KV 驱逐风暴** — 通过使 vLLM 块预算饱和来强制驱逐。观察：LMCache 是否恢复，还是服务降级？

### 节奏

- **每周** — 在暂存中进行小型金丝雀实验，可能是 5% 生产流量。
- **每月** — 针对特定场景的定期演练日；跨团队参与；事后分析。
- **每季度** — 跨团队弹性审计；依赖关系映射更新。

### 工具

- **Harness Chaos Engineering** — 商业产品；AI 生成实验推荐；爆炸半径缩减；MCP 工具集成。
- **LitmusChaos** — CNCF 毕业项目；基于 Kubernetes 工作流。
- **Chaos Mesh** — CNCF 沙盒；Kubernetes 原生 CRD 风格。
- **Gremlin** — 商业产品；广泛支持。
- **AWS FIS** / **Azure Chaos Studio** — 托管云产品。

### 从小处开始

第一个实验：在稳定流量下杀掉一个解码副本。观察重新路由和恢复。如果这个看起来安全且有效，再升级到网络混沌。

第一个 LLM 特有实验：注入一个供应商 429 持续 5 分钟。观察故障转移。大多数团队会发现他们的故障转移没有经过充分测试。

### 你应该记住的数字

- 四个平面：控制、目标、安全、可观测性。
- 燃耗率暂停：每日预算消耗超过预期 2 倍。
- 节奏：每周金丝雀、每月演练日、每季度审计。
- 五个 LLM 实验：内存、网络、供应商、格式错误提示词、KV 风暴。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| SLI / SLO | "服务目标" | 指标 + 目标；必需的先决条件 |
| Blast radius（爆炸半径） | "范围" | 实验影响的服务/用户集合 |
| Burn-rate alert（燃耗率告警） | "预算门控" | 当错误预算消耗率 > 预期 2 倍时触发 |
| Game day（演练日） | "每月演练" | 有计划的跨团队混沌演练 |
| LitmusChaos | "CNCF 工作流" | 毕业的 CNCF Kubernetes 混沌工具 |
| Chaos Mesh | "CNCF CRD" | CNCF 沙盒 Kubernetes 原生混沌 |
| Harness CE | "商业 AI 辅助" | 带 AI 推荐的 Harness 混沌 |
| Malformed prompt（格式错误的提示词） | "分词炸弹" | 使分词停滞的输入 |
| KV eviction storm（KV 驱逐风暴） | "抢占级联" | 大规模驱逐触发重新预填充 |
