# Jamba——混合SSM-Transformer

> 状态空间模型（SSM）和Transformer追求的是不同的东西。Transformer通过注意力以二次方代价换取质量。SSM通过递推实现线性时间推理和恒定内存，但在质量上落后。AI21的Jamba（2024年3月）和Jamba 1.5（2024年8月）将两者融合在同一个模型中：每7个Mamba层对应1个Transformer层，每隔一个块使用MoE，以及一个可以在单块80GB GPU上运行的25.6万词元上下文窗口。Mamba-3（ICLR 2026）用复数值状态空间和MIMO投影收紧了SSM一侧。本课端到端阅读两种架构，并解释为什么在纯SSM和纯Transformer长上下文尝试相继失败的情况下，混合方案在三年的扩展中存活了下来。

**类型：** 学习  
**语言：** Python（标准库，层混合计算器）  
**前置知识：** Phase 10·第14课（开源模型架构），Phase 10·第17课（原生稀疏注意力）

## 学习目标

- 解释Jamba块中的三个基本组件——Transformer层、Mamba层、MoE——以及1:7:间隔交替的方案
- 高层次地阐述SSM的递推结构，以及为什么它能实现恒定内存推理
- 计算Jamba模型在25.6万词元上下文下的KV缓存占用，与纯Transformer模型对比
- 说出Mamba-3的三项创新（指数梯形离散化、复数值状态更新、MIMO）以及每项针对的问题

## 问题所在

注意力对序列长度是二次方的。状态空间模型是线性的。这个差异会不断叠加：在25.6万词元时，Transformer的注意力图每头有650亿个条目；而SSM的循环状态无论序列长度如何都是固定大小的。

纯SSM模型（Mamba、Mamba-2）在小规模下与Transformer的困惑度持平，但在状态追踪任务上落后，在某些类别的上下文检索任务上失败。直觉是：SSM将历史压缩为固定状态，当历史很长时信息会泄漏。注意力能精确记住一切，但代价是二次方的计算量。

显而易见的修复方案：两者都用。在需要精确回忆的地方使用Transformer层，其他地方使用SSM层，然后调整比例。Jamba是第一个在生产规模上发布这种混合方案的模型（总参数520亿，激活120亿，25.6万上下文，单块80GB GPU）。Jamba 1.5将这个家族扩展到总3980亿/激活940亿。Mamba-3（ICLR 2026）是混合模型可以以此为基础重建的当前最佳纯SSM基线。

本课阅读所有三篇论文，建立"选择正确比例"的心智模型。

## 核心概念

### 一页纸讲清SSM

状态空间模型通过固定大小的状态`h`处理序列`x_1, ..., x_N`：

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

每一步，状态通过线性动态`A`演化，接收输入`B x_t`，并输出`C h_t`。`A, B, C`可以被学习。注意关键特性：计算`y_t`只需要`h_{t-1}`和`x_t`，不需要任何更早的`x`。内存是恒定的，每词元推理是O(1)的。

建模质量的关键在于`A`的结构。S4（Gu 2021）使用了高度结构化的矩阵，在训练时可以作为长卷积高效评估。Mamba（Gu, Dao 2023）将固定的`A, B, C`替换为数据相关的版本（"选择性"部分）。Mamba-2（2024）进一步简化了结构。Mamba-3（2026）在特定位置重新增加了复杂性。

关键特性：对于解码LLM，SSM层是注意力层的即插即用替代品，使用固定大小的每层状态而不是增长的KV缓存。

### Jamba块

Jamba块根据两个数字交替层：

- `l`：注意力对Mamba的比率。Jamba使用`l = 8`，意味着每7个Mamba层对应1个Transformer层（7个Mamba + 1个注意力 = 每组8层）
- `e`：MoE频率。Jamba使用`e = 2`，意味着每隔一层应用MoE

一个块内的层序列：

```
M  M  M  M  M  M  M  A    (7个Mamba + 1个注意力)
|  M  |  M  |  M  |  M    (| 标记应用了MoE的层)
```

每个Jamba块是8层。在4个块深度（共32层）时，你得到28个Mamba层和4个注意力层，其中16层使用MoE。

### 为什么是1:7的比率

AI21 进行了消融实验：什么样的注意力对Mamba比率能在每参数困惑度和长上下文评估的上下文回忆两方面都表现最好？

- 注意力太多（1:1）：质量提升，但内存和速度下降
- 注意力太少（1:15）：内存很好，但上下文检索失败
- 甜蜜点：1:7或1:8

直觉：Transformer层处理精确回忆和状态追踪，Mamba层处理廉价的大量处理。

### 位置编码

Mamba层自身通过递推具有位置感知能力。原始基于Mamba的混合模型中的注意力层没有使用RoPE——SSM层提供了位置信息。Jamba 1.5在注意力层中添加了RoPE以增强更长上下文的泛化能力，这是基于经验长上下文评估的后期改进。

### 内存预算

对于Jamba-1形状（32层：28个Mamba + 4个注意力，hidden 4096，32个注意力头）：

- KV缓存（仅注意力层）：在25.6万BF16下`2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB`。只有4个注意力层有贡献
- SSM状态：每词元前缀`28 * hidden * state_size`，但这对每层是固定大小，不随序列长度扩展。典型Mamba状态每特征16个，hidden 4096：`28 * 4096 * 16 * 2 = 3.7 MB`总计

对比一个32层的纯Transformer，相同hidden，完整MHA 32头：在25.6万BF16下`2 * 32 * 32 * 128 * 256k * 2 = 128 GB`。KV缓存缩减8倍。即使与大多数2024年模型使用的GQA(8)基线对比（`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`），Jamba 1:7混合的16 GB仍然小2倍。

这就是AI21所说"单块80GB GPU可用25.6万上下文"的含义。完整MHA纯Transformer的KV缓存装不下；即使是GQA基线也没有留给权重和激活的空间；而Jamba有。

### Mamba-3：2026年的纯SSM基线

Mamba-3（ICLR 2026，arXiv:2603.15569）在纯SSM一侧引入了三项创新：

1. **指数梯形离散化。** 用更具表达力的递推取代Mamba-2中的欧拉方法离散化。在核心递推内对状态输入应用类卷积操作，而不是对`x_t`进行外部卷积。

2. **复数值状态更新。** 此前的Mamba将状态矩阵从复数（S4）简化为实对角（Mamba）再到缩放单位矩阵（Mamba-2）。Mamba-3重新加入了复数值——等价于对状态进行数据相关的旋转嵌入。这恢复了此前实数值简化所损失的状态追踪能力。

3. **多输入多输出（MIMO）投影。** 使用矩阵值投影替代逐特征标量投影，提升建模能力和推理时的硬件利用率，同时不增加解码延迟。

在15亿参数规模下，Mamba-3相比Gated DeltaNet平均下游精度提升0.6个点；MIMO变体再增加1.2个点，总计提升1.8个点。在相同状态大小下，Mamba-3用一半状态就能匹配Mamba-2。

Mamba-3尚未在规模化的生产混合模型中发布——但它是下一代Jamba级模型SSM侧的明显候选者。

### 何时选择混合架构

混合模型胜出的场景：

- 上下文足够长，以至于纯Transformer KV缓存变得难以承受（6.4万词元以上）
- 任务混合了短程结构（适合SSM）和长程回忆（需要Transformer）
- 你希望在单GPU内存预算下部署，而Transformer的KV缓存本身就装不下

混合模型失利的场景：

- 上下文较短（1.6万词元以下）——SSM的开销被浪费，纯Transformer更好
- 任务需要全局注意力（深度推理、多文档交叉引用）——混合模型中注意力层的稀疏性会造成损害
- 你在扩展到万亿参数的前沿模型——纯Transformer + MLA + MoE（DeepSeek-V3风格）目前在能力竞赛中领先

### 竞争格局

| 模型 | 家族 | 规模 | 独特主张 |
|------|------|------|---------|
| Mamba-2 | 纯SSM | 30亿 | 线性时间，恒定内存 |

2026年格局：纯Transformer MoE在前沿占主导，但混合模型拥有25.6万词元以上上下文的利基市场。Mamba-3在状态追踪上的胜利可能会在下一代推动混合比率更低（更多SSM，更少注意力）。

## 实际使用

`code/main.py`是用于混合架构的内存计算器。给定SSM-Transformer比率和hidden大小/层数配置，它计算：

- 目标上下文下的KV缓存
- SSM状态内存
- 一系列模型形状在上下文N下的总内存

计算器支持：

- 纯Transformer基线（KV缓存随N增长）
- Jamba风格的1:7混合
- 纯SSM（完全没有KV缓存）

数字直接来自Jamba-1和Jamba-1.5论文中已发布的形状，对假想变体进行外推。

真实部署的集成注意事项：

- 大多数生产推理服务器（vLLM、SGLang）支持Jamba和Mamba——检查具体版本
- 在25.6万词元上下文时，Jamba的内存优势体现在并发请求吞吐量上——相同VRAM下能容纳的Jamba序列比Transformer序列更多
- Mamba-3作为独立模型尚未在生产中发布——仅15亿参数规模的研究预览

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| 状态空间模型（SSM） | "具有固定状态的递推" | 一个带有学习递推`h_t = A h_{t-1} + B x_t`的层；每词元恒定内存 |
| 选择性SSM（Selective SSM） | "Mamba的技巧" | 数据相关的A、B、C参数，在线性时间内给模型类似门控的选择性 |
| 注意力对Mamba比率 | "有多少注意力层" | 在Jamba中，`l = 8`意味着每7个Mamba层有1个注意力层 |
| Jamba块（Jamba block） | "8层组" | 一个注意力 + 七个Mamba + MoE在间隔位置 |
| SSM状态（SSM state） | "隐藏缓冲区" | 替代Mamba层KV缓存的固定大小每层状态 |
| 25.6万词元上下文 | "Jamba的旗舰数字" | Jamba-1能在单块80GB GPU上处理的序列长度；纯Transformer在这个大小下做不到 |
| Mamba-3 | "2026年的纯SSM" | 带有复数值状态+MIMO的当前最佳纯SSM架构；混合模型可以以此为基础重建 |
| MIMO | "多输入多输出" | Mamba-3创新，使用矩阵值投影而非逐特征标量投影 |
| 指数梯形离散化 | "Mamba-3的递推" | 比Mamba-2的欧拉方法离散化更具表达力的递推 |
| 混合架构（Hybrid architecture） | "注意力和SSM的混合" | 任何交替使用Transformer和SSM层的模型；Jamba是生产级典型 |
