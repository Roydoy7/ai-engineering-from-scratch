# 差分注意力（V2）

> Softmax注意力会把少量概率分配给每一个不相关的词元。在10万个词元的上下文里，这些噪声叠加起来会淹没有效信号。差分Transformer（Ye等人，ICLR 2025）通过将注意力计算为两个softmax之差来解决这个问题，从而消去共同的噪声基底。DIFF V2（微软，2026年1月）是面向生产栈的重写版本：解码延迟与基线Transformer持平，无需自定义CUDA核心，兼容FlashAttention。本课从V1到V2全程讲解，并给出一个可在纯stdlib Python中运行的差分运算玩具实现。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 7·第02课（自注意力），Phase 7·第15课（注意力变体），Phase 10·第14课（架构解析）  
**用时：** 约60分钟

## 学习目标

- 精确阐述softmax注意力为什么存在噪声基底，以及它为何随上下文长度增长
- 推导差分注意力公式，解释为什么做差能消去共同噪声分量同时保留信号
- 梳理V1到V2的变化：什么变快了，什么变简单了，什么变稳定了，以及每项改动对于生产级预训练为何必要
- 用纯Python从零实现差分注意力，并在合成信号+噪声查询上经验性地验证噪声消除特性

## 问题所在

标准softmax注意力有一个数学特性，在大规模下会变成一个实际操作上的麻烦。对于查询`q`，注意力权重是`softmax(qK^T / sqrt(d))`。Softmax永远无法产生精确的零——每个不相关的词元都会得到一些正的概率质量。这些剩余质量就是噪声，并且随上下文长度增长。在12.8万个词元的情况下，即使每个不相关词元只获得0.001%的概率，127,999个这样的词元合计贡献了约12%的总量。模型必须学会绕开一个随上下文增长的噪声基底。

这在实践中表现为注意力头干扰：长上下文RAG中的幻觉引用、10万词元检索任务上的"迷失在中间"失效，以及在32k词元以上的"大海捞针"基准测试上微妙的精度下降。差分Transformer论文（arXiv:2410.05258，ICLR 2025）量化了这一差距：DIFF Transformer在困惑度、长上下文精度和幻觉频率上均优于同等规模的基线。

DIFF V1有三个问题使它未能进入前沿预训练流程。它的值缓存在每次解码步骤中需要被加载两次，它需要破坏FlashAttention兼容性的自定义CUDA核心，而且它的逐头RMSNorm在70B及以上规模的长期训练中会引起不稳定。DIFF V2（微软unilm博客，2026年1月20日）修复了所有这三个问题。本课讲解两个版本，构建差分算子，并在玩具查询上对噪声消除进行基准测试。

## 核心概念

### Softmax的噪声基底

对于查询`q`和键`K = [k_1, ..., k_N]`，注意力权重为：

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

不存在任何`w_i`等于零的情况。如果`k_i`与`q`完全无关，分数`q . k_i`不是0——它在零附近以方差`||q||^2 / d`波动。经过softmax归一化后，每个不相关的词元仍然为加权和贡献`O(1/N)`。所有不相关词元的总贡献是`O((N-1)/N) = O(1)`——不是一个小量。

模型想要的是类似硬top-k的效果：对匹配词元赋予高权重，对其他所有词元赋予接近零的权重。Softmax太平滑，无法直接做到这一点。

### 差分思路

将每个头的Q和K投影分成两部分：Q = (Q_1, Q_2)，K = (K_1, K_2)。计算两个注意力图：

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

输出：

```
DiffAttn = (A_1 - lambda * A_2) V
```

做差会消去两个图共同拥有的任何噪声分布。如果两个图对12.7万个不相关词元都有近似均匀的权重（在随机初始化时确实如此），这些权重就会相互抵消。信号——对少数真正相关词元的峰值权重——只有在两个图中以相同幅度出现时才会相互抵消，而模型经过训练后就不会这样了。

`lambda`是每个头的一个可学习标量，参数化为`lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`。它可以为负。`lambda_init`默认为一个小的正数，如0.8。

### 为什么这与头戴式降噪类比

想象两个嘈杂的麦克风录制同一个声音。两者都接收到说话者加上相关的背景噪声。两者相减，共同的噪声就消失了。声音得以保留，因为两路信号在相位或幅度上有足够的差异，不会被完全抵消。每头的`lambda`正是学习这种平衡。

### V1与V2的区别

V1保持参数量与基线Transformer相等。为了每头获得两个查询，它将头维度减半。这损害了头的表达能力，更痛苦的是，每头的值缓存也减半了。解码时每步需要加载两次值缓存（每个softmax分支各一次）。结果：尽管参数量相当，解码速度比基线更慢。

V2将查询头的数量翻倍，KV头数量保持不变（参数从上投影层借取）。头维度与基线保持一致。做差之后，额外维度被投影回去，以匹配基线Transformer的O_W投影。同时发生三件事：

1. 解码速度与基线持平（KV缓存只加载一次）
2. FlashAttention无需修改即可运行（不需要自定义核心）
3. 解码时的算术强度提升（每从HBM加载的字节对应更多计算）

V2还去掉了V1用于稳定做差的逐头RMSNorm。在70B级别的预训练规模上，该RMSNorm会在训练后期引起不稳定。V2用一种更简单的初始化方案取代它，无需额外模块就能保持训练稳定。

### 何时使用

| 工作负载 | 收益 |
|---------|------|
| 长上下文RAG（64k以上） | 注意力图更清晰，幻觉引用更少 |
| 大海捞针基准测试 | 32k以上精度显著提升 |
| 多文档问答 | 跨文档干扰减少 |
| 8k代码补全 | 边际效益，不值得改变架构 |
| 短对话（4k以下） | 与基线实际上无法区分 |

价值随上下文长度增长。在4k词元时噪声基底足够小，标准注意力完全够用。在128k时它正在伤害你。

## 动手构建

`code/main.py`用纯Python实现差分注意力。一个具有已知信号+噪声结构的玩具查询让你能直接测量噪声消除比率。

### 第一步：标准softmax注意力

用标准库实现矩阵运算：列表的列表、手动矩阵乘法、带数值稳定减最大值的softmax。

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 第二步：将Q、K分成两半

V1风格：将头维度减半。V2风格：保持头维度，将头数翻倍。玩具实现使用V1以便于教学——数学完全相同，只是记账方式不同。

### 第三步：两个softmax分支+做差

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

注意：输出权重可以为负。这没问题——值缓存仍然处理有符号贡献。后续的V投影层吸收了符号。

### 第四步：噪声消除测量

构建一个长度为1024的合成序列。将信号词元放在已知位置，其余填充噪声。计算（a）标准softmax注意力在信号位置上的权重和（b）差分注意力权重。测量每种情况的信噪比。差分注意力能可靠地产生更高的信噪比，提升幅度为3到10倍，取决于两个分支被训练到多大程度的差异。

### 第五步：V1与V2参数量核算

给定配置（hidden=4096，heads=32，d_head=128），打印：

- 基线Transformer：Q、K、V各大小`hidden * hidden`，MLP为4 * hidden
- DIFF V1：Q、K各大小`hidden * hidden`，V大小`hidden * hidden`（不变），头维度内部减半。增加逐头`lambda`参数（O(heads * d_head)）
- DIFF V2：Q大小`2 * hidden * hidden`，K大小`hidden * hidden`，V大小`hidden * hidden`。额外维度在O_W投影前投影回去。增加相同的`lambda`参数

玩具程序测量V2的额外参数开销（每个注意力块大约`hidden * hidden`额外参数）并打印出来。

## 实际使用

截至2026年4月，DIFF V2还未在所有生产推理服务器中上线，但集成工作正在vLLM和SGLang中进行。同时该模式已出现在：

- 微软内部的长上下文生产模型中
- 多个以256k及以上上下文为目标的开源模型训练复现中
- 在交替层上结合DIFF注意力与滑动窗口注意力的混合架构中

**2026年适合使用的场景：**

- 从头训练一个以64k及以上有效上下文为目标的新模型。从一开始就加入差分注意力；之后重新训练代价很高
- 对一个长上下文模型进行微调，且"迷失在中间"的失效主导你的评估结果。对Q投影的LoRA可以近似DIFF结构

**不适合使用的场景：**

- 你在服务一个预训练好的密集模型，其长上下文性能已经稳定。重训练成本很少能从已有权重中收回
- 你的上下文始终在16k以下。噪声基底可以忽略不计

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| 差分注意力（Differential attention） | "两个softmax相减" | 将Q、K分成两半，计算两个softmax图，从第一个减去（lambda缩放的）第二个，然后乘以V |
| 噪声基底（Noise floor） | "softmax的非零尾部" | softmax分配给每个不相关词元的O(1/N)权重，在长上下文中累加为O(1) |
| lambda | "做差的缩放系数" | 逐头可学习标量，参数化为`exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`；可以为负 |
| DIFF V1 | "ICLR 2025版本" | 原始差分Transformer；将头维度减半以保持参数量，需要自定义核心，解码更慢 |
| DIFF V2 | "2026年1月的修复" | 将Q头数翻倍，KV头保持不变；解码速度与基线持平，兼容FlashAttention |
| 逐头RMSNorm（Per-head RMSNorm） | "V1的稳定器" | V1在做差后应用的额外归一化；V2将其移除以防止训练后期不稳定 |
| 信噪比（Signal-to-noise ratio） | "注意力浪费了多少" | 真实信号位置上的权重与不相关位置平均权重的比率 |
| 迷失在中间（Lost in the middle） | "长上下文失效模式" | 检索精度在长上下文中间位置文档上下降的经验现象——差分注意力减少这一现象 |
| 算术强度（Arithmetic intensity） | "每字节加载的FLOP数" | V2通过每次KV加载处理两倍查询在解码时提升了此值；对内存受限的解码很重要 |
