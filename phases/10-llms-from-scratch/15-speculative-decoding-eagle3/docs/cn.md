## 学习目标

- 用一句话陈述Leviathan定理，并证明推测解码循环产生的样本与直接从验证模型采样的分布完全相同
- 梳理从原版推测解码（Leviathan 2023）到EAGLE、EAGLE-2、EAGLE-3两年间的演进历程，说出每一步消除的具体局限
- 根据接受率`α`和草稿模型与验证模型的代价比`c`计算预期加速比，并为每种场景选择最优草稿长度`N`

## 问题所在

在H100上对70B模型做自回归解码，速度大约是每秒35个词元。GPU远未达到饱和。内存带宽是瓶颈：每个词元从HBM加载70B的权重，做一步运算，输出一个浮点数。计算单元大部分时间都在闲置。

推测解码把这变成了一个可以真正解决的吞吐量问题。廉价的草稿模型用N次小型前向传播提出N个词元。验证模型对前缀加上所有N个草稿一次性完成验证。如果验证模型在位置`i`处的分布与草稿吻合（吻合的统计含义我们稍后明确），则接受；否则拒绝，并从残差分布中采样一个修正词元。一次大模型前向传播能产生最多N+1个被接受的词元，而不是只有一个。

关键定理来自Leviathan、Kalman、Matias（ICML 2023）：输出分布与直接从验证模型采样完全相同。不是近似相同，是精确相同。这正是推测解码在生产中可用的全部理由——它是纯粹的延迟优化，没有任何质量代价。

Phase 7·第16课给了你数学。本课给你的是训练栈。好的草稿模型比廉价草稿模型多带来2倍加速。EAGLE、EAGLE-2和EAGLE-3（Li等人，2024–2025年）将"草稿=同族的小模型"变成了一门精确的工程学科。2026年生产推理服务器默认使用EAGLE-3。

## 核心概念

### 不变量：Leviathan拒绝采样

设`p(t)`为草稿模型在某个前缀下对下一词元的分布，`q(t)`为验证模型的分布。从`p`采样一个草稿词元`d`。以概率`min(1, q(d)/p(d))`接受。拒绝时，从残差分布`(q - p)_+ / ||(q - p)_+||_1`采样。最终的样本分布服从`q`。这一结论与`p`的好坏无关——`p`越差，拒绝越频繁，但输出仍然精确。

将N次这样的调用串联起来，使用一次验证模型对`prefix + d_1 + ... + d_N`的前向传播。验证模型同时返回`q_1, q_2, ..., q_{N+1}`。从左到右遍历。在位置`j`首次发生拒绝时，从`residual(q_j, p_j)`采样并停止。全部接受时，从`q_{N+1}`采样一个奖励词元。

### 加速比由什么决定

设`α`为每个草稿词元的预期接受率，`c = cost(draft) / cost(verifier)`为代价比。每次验证模型前向传播预期接受的词元数为：

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每个接受词元的预期总耗时为`(N * c + 1) / E[accepted]`。对`N`求最小值得到甜蜜点。对于`α = 0.8, c = 0.05`：最优`N`约为5到7，加速比为3.2倍。对于`α = 0.95, c = 0.02`：最优`N`约为8到10，加速比趋近5倍。

最大的杠杆是`α`。在固定`N = 5`的情况下，从`α = 0.6`（原版草稿）提升到`α = 0.9`（EAGLE-3），每次验证模型前向传播的预期接受词元数从2.2增加到4.1。相同的验证模型，吞吐量几乎提升2倍。

### 两年间的演进

**原版推测解码（Leviathan，2023年）。** 草稿模型是同族独立训练的小规模LLM。接入简单，`α ≈ 0.6`，加速比最高约2倍。

**EAGLE-1（Li等人，2024年）。** 草稿是一个微型Transformer，通常一到两层，以验证模型最后一层的隐藏状态作为输入，直接预测下一词元。由于草稿能看到验证模型的特征表示，其分布与验证模型更为接近。`α`提升至0.7到0.8。

**EAGLE-2（Li等人，2024年）。** 加入动态草稿树：不再提出N个词元的单一序列，而是提出一棵候选树，用一次验证模型前向传播（树注意力）对所有节点打分，沿最高概率路径行进。草稿长度变得自适应。路径级别的`α`超过0.85。

**EAGLE-3（Li等人，2025年，NeurIPS）。** 再增加两项改动。第一，完全去掉特征预测损失——EAGLE-1/2训练草稿去匹配验证模型的隐藏状态，这限制了数据能带来的帮助。EAGLE-3直接在词元预测上训练。第二，训练时测试（TTT）：草稿训练期间，像推理时那样将草稿自己的前一个预测反馈回来，跨多步进行。这对齐了训练和测试分布，防止误差累积。实测加速比：对话任务最高6.5倍，在H100上的SGLang批大小64时，吞吐量比原版提升38%。

### KV缓存回滚

验证一次会将验证模型的KV缓存扩展N个条目。如果在位置`j`发生拒绝，位置`j-1`之后的缓存内容就是错的。两种常见实现：写入暂存缓冲区，接受时提交（vLLM、TensorRT-LLM）；或维护物理KV缓存加逻辑长度，拒绝时截断。无论哪种方式，回滚代价是每层每头的字节数，与前向传播代价相比可以忽略不计。

对于EAGLE-2树搜索，验证模型用一个遵循树形拓扑的非因果掩码运行注意力。工程上有些繁琐，但计算本质上是一次带自定义掩码的标准Flash Attention调用。

### 2026年的草稿架构

| 策略 | 草稿类型 | `α` | 加速比 | 训练成本 |
|------|---------|-----|--------|---------|

## 动手构建

见`code/main.py`。这是包含所有组件的完整Leviathan推测解码循环：N步草稿生成、验证模型并行传播、逐位置拒绝、残差采样、奖励词元、KV回滚，以及验证输出分布与直接从`q`采样一致的经验检验。

### 第一步：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 第二步：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 第三步：完整的推测步骤

`spec_step`函数从`p`草稿生成N个词元，然后用一次并行的`q`评估对所有词元进行验证。对每个草稿词元应用拒绝规则，在首次拒绝时从残差分布中采样修正词元。如果全部接受，则从`q_{N+1}`输出一个奖励词元。

### 第四步：KV回滚记账

模拟器对每个工作单元跟踪一个逻辑`kv_length`。接受k个草稿时，`kv_length += k`。在位置`j`发生拒绝时，缓存已经写过`j`之后，但逻辑长度被设为`prefix_length + j + 1`——修正词元之后的位置。后续读取截断到逻辑长度。

### 第五步：Leviathan验证

运行50,000次推测解码步骤，统计接受词元的经验分布，与50,000次直接从`q`采样对比。卡方统计量应该远低于临界值。定理在实践中成立。

### 第六步：加速比与α的关系

通过对`p`施加不同幅度的扰动来调节草稿质量，测量`α`，然后绘制每次验证模型调用的预期词元数关于`α`和`N`的图。代码打印一张表，展示EAGLE-3级别的草稿质量（`α ≈ 0.9`）如何实现每次验证调用4到5个词元。

## 实际使用

使用EAGLE-3的生产级`vllm serve`：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

在H100上使用EAGLE-3的SGLang批大小64时：根据EAGLE-3论文，吞吐量比批大小64原版解码高出约38%。

**适合使用推测解码的场景：**

- 任何p50延迟比峰值吞吐量更重要的交互式对话负载
- 代码生成和结构化输出（JSON、SQL）——目标分布高度可预测，`α`超过0.9
- 长文本生成（数千词元）——摊销加速比持续有效

**不适合使用推测解码的场景：**

- 很小的模型（3B以下）——草稿模型比验证模型便宜得有限
- 批大小为1的CPU部署——草稿模型的内存开销可能得不偿失
- 高温度创意采样场景——`α`会急剧下降

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| Leviathan规则（Leviathan rule） | "min(1, q除以p)" | 以概率`min(1, q(d)/p(d))`做伯努利接受/拒绝，拒绝时从残差采样能精确保持验证模型的分布 |
| 残差分布（Residual distribution） | "(q减p)的正部，归一化" | `(q - p)_+`截断到零后再归一化——拒绝时正确的采样分布 |
| 接受率α（Acceptance rate α） | "草稿的正确率" | 拒绝规则下每词元的预期伯努利成功概率；支配所有加速比计算 |
| EAGLE-1 | "隐藏状态草稿" | 以验证模型最后一层隐藏状态为条件的微型Transformer草稿（Li等人，2024年） |
| EAGLE-2 | "动态草稿树" | EAGLE-1加上用树注意力在一次验证传播中打分的候选续写树 |
| EAGLE-3 | "训练时测试" | 去掉特征预测损失，在训练时将草稿的自身输出反馈回来，在直接词元预测上训练 |
| 训练时测试（TTT） | "曝光偏差修复" | 训练期间自回归地运行草稿，使训练和测试输入分布一致——与seq2seq的scheduled sampling直接类比 |
| KV回滚（KV rollback） | "撤销被拒绝的草稿" | 拒绝后将验证模型KV缓存重置到已接受前缀长度的记账操作 |
| 奖励词元（Bonus token） | "免费的那个" | 所有N个草稿都被接受时，从`q_{N+1}`额外采样一个词元，不需要额外的验证模型调用 |
| 树注意力（Tree attention） | "一次验证多个候选" | 使用遵循草稿树拓扑的非因果掩码的注意力；在一次前向传播中计算树中每个节点的`q_i` |
