# 多词元预测（MTP）

> 从GPT-2到Llama 3，所有自回归LLM都在每个位置上训练同一个损失：预测下一个词元。DeepSeek-V3在每个位置额外增加了一个损失：预测再下一个词元。这额外的140亿参数（在6710亿参数的模型上）通过梯度流蒸馏回主模型，训练好的MTP头在推理时被复用为推测解码的起草者，接受率超过80%。生成吞吐量1.8倍的提升就这样白来了。本课从DeepSeek技术报告中构建序列式MTP模块，计算损失和共享头部参数布局，并解释为什么MTP保留了因果链，而Gloeckle等人最初的并行MTP打破了它。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 10·第04课（预训练一个mini GPT），Phase 10·第15课（推测解码）  
**用时：** 约60分钟

## 学习目标

- 阐述MTP训练目标，推导跨预测深度的联合损失
- 解释Gloeckle等人的并行MTP头（2024年）与DeepSeek-V3的序列式MTP模块之间的区别，以及为什么序列式设计保留了因果链
- 计算在预训练中添加MTP模块所带来的参数量和内存开销
- 从零实现一个MTP模块：共享嵌入、逐深度Transformer块、投影层和共享输出头

## 问题所在

下一词元预测是标准的LLM训练目标。每个隐藏状态都只被监督预测一件事：紧接其后的词元。这是一个出奇弱的监督信号。序列中大部分信息延伸到一个词元之外——结构、连贯性、事实性、算术流程。模型必须通过在数万亿词元上累积一个个单词元信号来学习这些。

MTP的问题是：如果每个隐藏状态被监督同时预测多个未来词元会怎样？Gloeckle等人（Meta，2024年）证明这是有帮助的。他们的实现在主干网络顶部放了几个独立的输出头，每个头预测一个不同的偏移量。并行、简单，但这些头看到的是相同的隐藏状态，没有任何层次精炼——而且预测之间没有因果链接，因此无法用于推测解码。

DeepSeek-V3（2024年12月）将MTP重新设计为在每个预测深度保持因果链的序列式模块。模型从`h_i^(0)`预测`t+1`，然后从一个新的隐藏状态`h_i^(1)`预测`t+2`，这个新隐藏状态结合了`h_i^(0)`和`E(t+1)`嵌入，以此类推。每个深度都是自己的小型Transformer块。共享嵌入和共享输出头使参数开销保持适中。在DeepSeek-V3的规模上，MTP模块在6710亿主模型权重上额外增加了140亿参数。这2%的开销换来了更密集的训练信号，以及推理时现成可用的推测解码起草者。

本课从零构建单个MTP模块和D深度损失。数学整洁，实现150行代码。

## 核心概念

### 序列式MTP方案

DeepSeek-V3在主模型顶部添加了`D`个MTP模块。模块`k`（k = 1..D）预测深度`k`处的词元——即给定通过位置`i`的前缀时的`t_{i+k}`。

模块`k`由以下部分组成：

- 有自己注意力和MLP的Transformer块`T_k`
- 将前一深度隐藏状态与下一深度真实词元的嵌入结合的投影矩阵`M_k`
- 共享嵌入`E`（与主模型相同）
- 共享输出头`Out`（与主模型相同）

训练时，对于通过位置`i`的前缀，逐深度隐藏状态为：

```
h_i^(0) = 主模型主干在位置i的输出
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   k >= 1
```

逐深度预测为：

```
logits_{i+k} = Out(h_i^(k-1))   k = 1..D
```

对真实词元`t_{i+k}`的逐深度损失为交叉熵：

```
L_k = CE(logits_{i+k}, t_{i+k})
```

跨深度的联合损失：

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda`是一个小的权重因子——DeepSeek-V3在训练前10%使用0.3，之后使用0.1。总训练损失为`L_main + L_MTP`。

### 为什么是序列式而非并行式

Gloeckle的原始并行MTP有D个输出头，每个头直接应用于`h_i^(0)`。每个头从相同的主干隐藏状态预测`t_{i+k}`。这种方式训练效果不错，但各预测之间没有条件依赖关系。你无法用`head_1`的输出帮助`head_2`——这些头并行运行。

DeepSeek-V3的序列式设计从`h_i^(k-1)`加上实际的下一词元嵌入`E(t_{i+k})`构建`h_i^(k)`。这保留了因果链：为了预测`t_{i+k+1}`，深度`k+1`的模块能看到`t_{i+k}`处的内容。这在结构上与自回归解码器消耗自身输出完全相同——使MTP模块可以直接用作推测解码的起草者。

推理时：将`h_i^(k-1)`和起草的`t_{i+k}`送入模块`k+1`，得到`t_{i+k+1}`的预测。重复此过程。这恰恰就是EAGLE风格的起草，使用训练好的MTP模块作为起草网络。DeepSeek-V3报告在第一个MTP模块上的接受率超过80%，并实现约1.8倍加速。

### 参数量核算

对于隐藏维度`h`、词表大小`V`的模型：

- 主模型：数十亿参数，加上一个大小为`V * h`的输出头
- 共享输出头：复用主模型的头，无额外参数
- 共享嵌入：复用主模型的嵌入，无额外参数
- 每个MTP模块：
  - 投影矩阵`M_k`：`(2h) * h = 2h^2`
  - Transformer块`T_k`：注意力（MHA为`4h^2`）加MLP（SwiGLU比例8/3时通常为`8h^2`）。每块约`12h^2`

每个模块的额外参数总计约`14h^2`。对于DeepSeek-V3的`h = 7168`，D=1个模块：约`14 * 7168^2 ≈ 7.2亿`参数（理论值）。DeepSeek-V3报告14B——差距主要来自MTP模块中的Transformer块也继承了MoE结构，使每模块参数量膨胀。

### 推测解码的收益

预训练期间，MTP模块使训练慢了约10%（更多的前向计算、额外的损失）。收益是双重的：

1. 更密集的训练信号。每个隐藏状态看到D+1个监督目标。在MMLU、GSM8K、MATH、HumanEval上的实测效果：DeepSeek-V3的消融实验中各项指标有数个百分点的持续提升。

2. 推理时免费获得推测解码起草者。MTP模块已经被训练来预测接下来几个词元。将其作为起草网络复用，能实现80%以上的接受率。在该水平下，N=3或N=5的推测解码带来1.8倍吞吐量。训练时10%的代价在第一次运行推理时就回本了。

### 与EAGLE的关系

EAGLE在预训练之后单独训练一个小型起草模型。MTP将起草融入预训练。两种方法收敛到相似的接受率，但通过不同的流程：

| 维度 | EAGLE-3 | MTP（DeepSeek-V3） |
|------|---------|------------------|
| 何时训练 | 预训练之后 | 预训练期间 |
| 与已有权重向后兼容 | 是 | 否（需要重新训练） |
| 起草参数 | 1-2个Transformer层 | 1个Transformer块+投影层 |
| 接受率 | 0.88-0.92 | 深度1处0.80以上 |
| 加速之外的收益 | 仅推测解码 | 更密集训练信号+加速 |

## 动手构建

`code/main.py`端到端构建单个MTP模块：共享嵌入、投影层、Transformer块、共享输出头。然后在短合成序列上计算逐深度交叉熵损失，并按组件打印参数量。32个词元的玩具词表使数字便于阅读。

### 第一步：共享嵌入表

单个`vocab_size × hidden`的表被主模型和每个深度的每个MTP模块共用。不是第二个副本——就是同一个张量。

### 第二步：逐深度组合

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 沿特征维度拼接，再投影回hidden维度
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 向量相加作为简化
    projected = matvec(M_k, concat)
    return projected
```

真实的DeepSeek-V3将两个RMSNorm后的向量拼接为`[2h]`，再用`h × 2h`矩阵投影。玩具实现用向量相加简化，以保持stdlib的简洁。

### 第三步：深度k处的Transformer块

自注意力加MLP。玩具中使用单层线性注意力块和SwiGLU MLP，在不使用numpy的情况下保持结构可见。

### 第四步：共享输出头

复用主模型的输出投影。对词表的logits。

### 第五步：逐深度损失

softmax(logits)对偏移`k`处真实词元的交叉熵。用`lambda / D`缩放因子在各深度聚合。

### 第六步：参数量核算

打印总参数量、共享（嵌入、头部）参数量和每模块额外参数量。显示MTP额外参数与主模型大小的比率。

## 实际使用

MTP已集成到DeepSeek-V3（2024年12月）和DeepSeek-R1系列中。推理时：

- DeepSeek自己的服务栈开箱即用地将MTP模块用作推测解码器
- vLLM和SGLang截至2026年4月已有针对DeepSeek-V3 MTP的集成路径
- AMD的ROCm SGLang教程展示了一个具体的MTP推测解码配置，在V3检查点上实测1.8倍加速

**在新预训练中使用MTP的场景：**

- 你控制完整的预训练流程，并希望获得更密集的训练信号
- 你知道将大规模部署该模型，并希望免费获得推测解码
- 你的隐藏维度至少为4096——在10亿参数规模下，开销带来的损害大于收益

**不适合使用的场景：**

- 对已有预训练密集模型进行微调——MTP模块未经过训练
- 需要干净基线进行对比的研究模型——MTP改变了架构

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| MTP模块（MTP module） | "额外损失块" | 一个小型Transformer块加投影层，预测主模型前方`k`个位置的词元 |
| 预测深度（Prediction depth） | "哪个偏移量" | 整数`k`，使得模块`k`从通过位置`i`的前缀预测`t_{i+k}` |
| 并行MTP（Parallel MTP） | "Gloeckle风格" | 在相同主干隐藏状态上的D个独立头，没有条件链 |
| 序列式MTP（Sequential MTP） | "DeepSeek-V3风格" | 每个模块以前一深度的隐藏状态加下一词元嵌入为条件；保留因果链 |
| 共享输出头（Shared output head） | "复用主模型头部" | MTP模块调用主模型的LM头，而非单独的输出投影 |
| 共享嵌入（Shared embedding） | "复用主表" | 相同的词表嵌入表在所有地方使用；没有重复参数 |
| 投影矩阵M_k（Projection matrix M_k） | "组合隐藏状态+下一词元" | 将前一隐藏状态和目标词元嵌入折叠为下一深度输入的`h × 2h`线性层 |
| 联合损失L_MTP（Joint loss L_MTP） | "平均额外损失" | 逐深度交叉熵损失的算术平均，以`lambda`缩放 |
| 深度1处的接受率（Acceptance rate at depth 1） | "MTP起草的正确率" | D=1 MTP模块的top-1预测与主模型top-1预测相同的比率；DeepSeek-V3上超过80% |
| Lambda权重（Lambda weighting） | "额外损失的重要性" | 逐深度缩放因子；DeepSeek-V3训练开始时为0.3，之后为0.1 |
