# DeepSeek-V3架构逐步解析

> Phase 10·第14课介绍了每个开源模型都会转动的六个架构旋钮。DeepSeek-V3（2024年12月，总参数6710亿，激活参数370亿）把六个旋钮全都转了，还额外加了四个：多头潜在注意力（MLA）、无辅助损失的负载均衡、多词元预测（MTP）和DualPipe训练。本课从头到尾阅读DeepSeek-V3的架构，并从公布的配置中推导出每一项参数量。学完之后，你能解释为什么6710亿/370亿的比率是正确的赌注，以及为什么MLA + MoE的组合比任何单一方案在前沿都更优。

## 问题所在

DeepSeek-V3是第一个架构与Llama系列有实质差异的前沿开源模型。Llama 3 405B是"转动了六个旋钮的GPT-2"。DeepSeek-V3是转动了所有六个旋钮再加四个额外旋钮的GPT-2。阅读Llama 3配置是阅读DeepSeek配置的热身，但深层结构——注意力块的形状、路由逻辑、训练时目标——有足够大的差异，值得单独解析。

学会它的回报：DeepSeek-V3的开放权重发布改变了开源模型中"前沿能力"的含义。这个架构是2026年许多训练运行正在复制的蓝图。理解它是任何接触前沿LLM训练或推理工作的基本门槛。

## 核心概念

### 不变的内核，再次强调

DeepSeek-V3仍然是自回归的。它仍然堆叠解码器块。每个块仍然有注意力+MLP+两个RMSNorm。MLP中仍然使用SwiGLU。仍然使用RoPE。Pre-norm。权重共享嵌入。与每个Llama或Mistral相同的基线。

### 关键变化：MLA代替GQA

从Phase 10·第14课你知道GQA通过在Q头组之间共享K和V来缩减KV缓存。多头潜在注意力（MLA）更进一步：K和V被压缩成一个共享的低秩潜在表示（`kv_lora_rank`），然后在每个头上动态解压。KV缓存只存储潜在表示——通常是每词元每层512个浮点数，而不是8 × 128 = 1024个浮点数。

在12.8万词元的上下文下，DeepSeek-V3使用MLA（每词元每层一个共享潜在`c^{KV}`；K和V都通过上投影从这个潜在表示派生，上投影可以被吸收进后续的矩阵乘法）：

```
kv_cache = num_layers * kv_lora_rank * max_seq_len * bytes_per_element
         = 61 * 512 * 131072 * 2
         = 7.6 GB
```

一个假想的GQA基线（Llama 3 70B形状，8个KV头，头维度128）需要：

```
kv_cache = 2 * 61 * 8 * 128 * 131072 * 2
         = 30.5 GB
```

在12.8万词元的上下文下，MLA比Llama 3 70B风格的GQA缓存小4倍。

权衡：MLA在每次注意力计算时增加一个解压步骤（每头）。额外的计算量与节省的带宽相比很小。长上下文推理的净收益为正。

### 路由：无辅助损失的负载均衡

MoE路由器决定哪些top-k专家处理每个词元。朴素的路由器会将太多工作集中在少数几个专家上，让其他专家闲置。标准修复方案：添加一个惩罚负载不均衡的辅助损失项。这有效，但会略微降低主任务的性能。

DeepSeek-V3引入了无辅助损失的方案。在路由器logit上添加逐专家偏置项，在训练期间通过一个简单规则调整：如果专家`e`过载，减小`bias_e`；如果欠载，增大它。没有额外的损失项，训练保持干净，专家负载保持均衡。

对主损失的影响：没有可测量的影响。对MoE架构的影响：更简洁，没有需要调整的辅助损失超参数。

### MTP：更密集的训练+免费的起草者

从Phase 10·第18课你知道DeepSeek-V3添加了D=1的MTP模块，预测两个位置之后的词元。推理时，训练好的模块被用于推测解码的起草，接受率超过80%。训练时，每个隐藏状态在D+1=2个目标上受到监督，提供了更密集的信号。

参数量：在6710亿主模型之上额外增加140亿。开销：2.1%。

### 训练：DualPipe

从Phase 10·第19课你知道DualPipe是一种双向流水线，将前向和反向块与跨节点全对全通信重叠。在DeepSeek-V3的2048块H800规模下，它找回了1F1B会损失在流水线气泡上的约24.5万GPU小时。

### 配置，逐字段解读

以下是DeepSeek-V3配置（简化版）：

```
hidden_size: 7168
intermediate_size: 18432   (前几层的密集MLP隐藏层大小)
moe_intermediate_size: 2048 (专家MLP隐藏层大小)
num_hidden_layers: 61
first_k_dense_layers: 3    (前3层使用密集MLP)
num_attention_heads: 128
num_key_value_heads: 128   (在MLA下正式等于num_heads，
                           但真正的压缩在kv_lora_rank中)
kv_lora_rank: 512          (MLA潜在维度)
num_experts: 256            (每块的MoE专家数量)
num_experts_per_tok: 8      (top-8路由)
shared_experts: 1           (每块始终激活的共享专家)
max_position_embeddings: 163840
rope_theta: 10000.0
vocab_size: 129280
mtp_module: 1               (深度1处的1个MTP模块)
```

逐项解读：

- `hidden_size=7168`：嵌入维度
- `num_hidden_layers=61`：总块深度
- `first_k_dense_layers=3`：前3个块使用大小为18432的密集MLP，其余58个使用MoE
- `num_attention_heads=128`：128个查询头
- `kv_lora_rank=512`：K和V被压缩到这个潜在维度，并在每头上解压
- `num_experts=256, num_experts_per_tok=8`：每个MoE块有256个专家，路由top-8
- `shared_experts=1`：在256个路由专家之上，1个始终激活的专家为每个词元做出贡献，可以理解为确保每个词元都能得到可靠处理的"密集基底"
- `moe_intermediate_size=2048`：每个专家的MLP隐藏层大小，比密集MLP小，因为一共有256个专家

### 参数量核算

完整计算在`code/main.py`中。主要数字：

- 嵌入层：`vocab * hidden = 129280 * 7168 ≈ 9.3亿`
- 前3个密集块：带MLA的注意力（每块约1.44亿）+密集MLP（每块约2.6亿）+归一化层。总计约12亿
- 58个MoE块：带MLA的注意力（1.44亿）+ 256个专家各自（每个3000万）+ 1个共享专家（3000万）+归一化层。每块包含所有专家约79.5亿。58个MoE块总计4610亿
- MTP模块：140亿

总计：约4760亿核心架构 + 140亿MTP + 已发布的6710亿数字还包含额外的结构性参数（偏置张量、专家特定组件、共享专家缩放等）。计算器重现的数字在已发布值的3-5%以内——差异来自DeepSeek报告附录第2节中记录的细粒度核算。

每次前向传播的激活参数：

- 注意力：每层1.44亿 × 61 = 88亿（所有层都激活）
- MLP激活：前3层密集（3 × 2.6亿 = 7.8亿），58个MoE层各激活8个路由 + 1个共享 + 路由开销。每层激活MLP约2.6亿。总计：3 × 2.6亿 + 58 × 2.6亿 ≈ 159亿
- 嵌入层+归一化层：12亿
- 总激活：约260亿核心 + 140亿MTP（已训练但推理时不总运行）≈ 370亿

### 6710亿/370亿比率

18倍稀疏比率（激活参数是总参数的5.5%）。DeepSeek-V3是发布开放权重中激活率最稀疏的前沿MoE模型。Mixtral 8x7B的比率是13/47（28%），密度高得多。Llama 4 Maverick的比率是17B/400B（4.25%），与之相当。DeepSeek的赌注是：在前沿规模下，更多专家加更低的激活比率能产生更好的每激活FLOP质量。

### 后续：R1和V4

DeepSeek-R1（2025年）是在V3主干上进行的推理训练运行。R1使用相同的架构。改变的是后训练方案（在可验证任务上的大规模强化学习），而不是预训练架构。

DeepSeek-V4（如果发布）预计将保留MLA + MoE + MTP，并添加DSA（DeepSeek稀疏注意力），即Phase 10·第17课中NSA的后继者。传承是稳定的：架构级创新积累；每个版本转动更多旋钮。

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| MLA（多头潜在注意力） | "Multi-Head Latent Attention" | 将K和V压缩成共享低秩潜在表示（kv_lora_rank，通常512），在每个头上动态解压；KV缓存只存储潜在表示 |
| kv_lora_rank | "MLA压缩维度" | K和V共享潜在表示的大小；DeepSeek-V3使用512 |
| 前k个密集层（First k dense layers） | "早期层保持密集" | 前几个MoE模型层跳过MoE路由器，运行密集MLP以保持稳定性 |
| num_experts_per_tok | "Top-k路由" | 每个词元激活多少个路由专家；DeepSeek-V3使用8 |
| 共享专家（Shared experts） | "始终激活的专家" | 无论路由结果如何都处理每个词元的专家；DeepSeek-V3使用1个 |
| 无辅助损失路由（Auxiliary-loss-free routing） | "偏置调整负载均衡" | 训练期间调整逐专家偏置项以保持专家负载均衡，无需添加损失项 |
| MTP模块（MTP module） | "额外预测头" | 从`h^(1)`和`E(t+1)`预测`t+2`的Transformer块；更密集的训练，免费的推测解码起草 |
| DualPipe | "双向流水线" | 将前向/反向计算与跨节点全对全通信重叠的训练调度 |
| 激活参数比率（Active parameter ratio） | "稀疏度" | active_params / total_params；DeepSeek-V3达到5.5% |
| FP8训练 | "8位训练" | 以FP8格式进行训练存储和大部分计算操作；相比BF16大约减半内存，质量损失很小 |
