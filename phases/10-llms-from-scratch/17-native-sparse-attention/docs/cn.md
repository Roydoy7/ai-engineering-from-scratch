# 原生稀疏注意力（DeepSeek NSA）

> 在6.4万个词元的情况下，注意力计算占据解码延迟的70%至80%。每个开源模型实验室都有解决方案。DeepSeek的NSA（ACL 2025最佳论文）是那个真正站稳脚跟的方案：三个并行注意力分支——压缩粗粒度词元、选择性保留的细粒度词元以及用于局部上下文的滑动窗口——通过一个学习得到的门控机制组合。它对硬件友好（内核对齐），原生可训练（在预训练中有效，不是推理时强行附加），在6.4万词元的解码任务上比FlashAttention更快，同时匹配甚至超越全注意力的质量。本课端到端构建三个分支，并展示为什么稀疏性是端到端可微的。

**类型：** 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 7·第12课（KV缓存、Flash Attention），Phase 7·第15课（注意力变体），Phase 10·第16课（差分注意力）  
**用时：** 约60分钟

## 学习目标

- 阐述NSA的三个注意力分支以及每个分支捕获的内容
- 解释为什么NSA是"原生可训练"的，而此前的稀疏注意力方法只能用于推理
- 以压缩块大小和选择top-k为函数，计算NSA在6.4万词元上下文下相对于全注意力节省的计算量
- 在纯stdlib Python中对短合成序列实现三分支组合，并验证门控权重的行为

## 问题所在

在序列长度N下，全注意力的时间代价为`O(N^2)`，每层KV缓存为`O(N)`。在6.4万个词元时，计算量和内存带宽数字是灾难性的。NSA论文中给出的理论估计：在6.4万词元时，注意力计算占总解码延迟的70%至80%。所有下游指标——首词元时间（TTFT）、词元每秒、每百万词元成本——都被注意力计算主导。

稀疏注意力是显而易见的答案。此前的尝试分为两类。固定模式稀疏性（滑动窗口、跨步式、块局部）会丢失信息，在长距离回忆任务上失败。推理时稀疏性（KV缓存剪枝、H2O、StreamingLLM）被应用于预训练时使用密集注意力的模型，只能恢复潜在加速的一小部分，因为模型从未被要求通过稀疏模式路由信息。

原生稀疏注意力（Yuan等人，DeepSeek + 北京大学 + 华盛顿大学，ACL 2025最佳论文，arXiv:2502.11089）两者兼顾：模型在预训练过程中学习稀疏模式，实现为一种真正在推理时带来计算节省的内核对齐算法。两年后，NSA或其直接后继者将成为每个前沿长上下文模型的默认注意力机制。

## 核心概念

### 三个并行分支

对于每个查询，NSA对KV缓存的三个不同视图各运行一次注意力：

1. **压缩分支。** 词元按大小为`l`（通常为32或64）的块分组。每个块通过一个小型学习MLP压缩为单个摘要词元。查询对这些压缩词元进行注意力计算，获得整个序列的粗粒度视图。

2. **选择分支。** 利用压缩分支的注意力分数，找出与当前查询最相关的top-k个块。读取这些块中未压缩的细粒度词元，查询对所有这些词元进行注意力计算。可以把压缩分支注意力看作选择操作的路由信号。

3. **滑动窗口分支。** 查询对最近的`W`个词元（通常为512）进行注意力计算，以获取局部上下文。该分支捕获其他两个分支可能遗漏的密集短程模式（句法、局部指代消解）。

三个分支的输出通过一个学习得到的逐位置门控机制组合：

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win`是由查询上的小型MLP产生的门控权重。它们不需要加和为1——可以独立地对各分支加权。

### 为什么说它是"原生可训练"的

选择步骤（top-k块）是离散操作。离散操作会阻断梯度流。此前的稀疏注意力工作要么跳过通过选择操作的反向传播（限制了训练），要么使用推理时无法产生真正稀疏性的连续松弛方法。

NSA绕开了这个问题：压缩分支注意力本身就是对整个序列的可微粗粒度注意力。top-k操作只是复用压缩分支的顶部注意力分数来决定加载哪些细粒度块。梯度通过压缩分支的分数流动（这些分数同时影响压缩输出和选择逻辑），被选中块对最终输出的贡献也是可微的。不可微的`top_k`操作在前向计算图上是无操作——它只控制从内存中加载哪些块。

这就是为什么NSA可以端到端地用于预训练。模型学习通过三个分支联合路由信息，产生一种在推理时真正能带来预期加速的稀疏模式。

### 硬件对齐的内核

NSA的内核为现代GPU内存层次结构而设计。内核按GQA分组加载查询（外层循环），按组获取对应的稀疏KV块（内层循环），并在SRAM上运行注意力。由于每个查询组看到相同的被选中块（选择是按查询组进行的，而不是按查询头），KV加载在整个组中被摊销。算术强度保持较高水平。

论文报告在6.4万词元解码上，Triton内核比FlashAttention快9倍，且加速比随序列长度增长。前向和反向内核均已提供。

### 计算预算

设`N`为序列长度，`l`为压缩块大小，`k`为top-k选择数量，`w`为滑动窗口，`b`为被选中块大小（通常等于`l`）。

- 压缩分支：每个查询`O(N/l)`个键，总计`O(N * N / l)`
- 选择分支：每个查询`O(k * b)`个键，总计`O(N * k * b)`
- 滑动分支：每个查询`O(w)`个键，总计`O(N * w)`

总计：`O(N * (N/l + k*b + w))`

取`N = 64000, l = 64, k = 16, b = 64, w = 512`：每查询代价为`1000 + 1024 + 512 = 2536`个键。全注意力为`64000`个键。25倍计算量减少。

取`N = 128000, l = 64, k = 16, b = 64, w = 512`：每查询代价为`2000 + 1024 + 512 = 3536`个键。全注意力为`128000`个键。36倍减少。收益随序列长度增长，这正是重点所在。

### 对比同类方法

| 方法 | 可微 | 真实推理加速 | 长程回忆 |
|------|------|------------|---------|
| 仅滑动窗口 | 是 | 是 | 失败 |
| 跨步/块稀疏 | 是 | 是 | 部分 |
| KV剪枝（H2O、StreamingLLM） | 不适用（推理时） | 是 | 部分 |
| MoBA（Moonshot） | 部分 | 是 | 好 |
| NSA | 是（原生） | 是（6.4万时9倍） | 匹配全注意力 |

MoBA（Moonshot，arXiv:2502.13189）同期发表，采用类似的三优于一思路，将MoE原理应用于注意力块。NSA和MoBA是2026年长上下文预训练的两个值得了解的架构。

## 动手构建

`code/main.py`对短合成序列实现三个分支并展示：

- 压缩MLP（教学起见使用简单的均值池化基线；真实NSA使用学习MLP）
- 由压缩分支分数驱动的top-k块选择
- 对最后`w`个词元的滑动窗口注意力
- 门控组合
- 与全注意力对比的计算量打印

### 第一步：将词元压缩成块

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

### 第二步：压缩分支注意力

对压缩键运行查询的softmax注意力。压缩分支分数同时作为top-k选择的信号。

### 第三步：top-k块选择

选取`k`个分数最高的压缩块的索引，从这些块中加载原始未压缩的词元，并对其运行注意力。

### 第四步：滑动窗口注意力

取最后`w`个词元，对其运行标准注意力。

### 第五步：门控+组合

查询上的小型MLP产生三个门控权重。最终输出是三个分支输出的加权和。

### 第六步：计算量统计

打印每个查询在每个分支中注意到的键数量及总量，与`N`（全注意力）对比。在1024词元的合成序列上取`l = 32, k = 4, w = 128`，NSA每个查询看到`32 + 128 + 128 = 288`个键，而全注意力为1024个——少了3.5倍。

## 实际使用

NSA已在DeepSeek自己的长上下文预训练流程中使用。截至2026年4月，在公开推理栈中的集成状态：

- **DeepSeek内部**：原生使用，发布的权重采用NSA或其后继者DSA（DeepSeek稀疏注意力）
- **vLLM**：针对DeepSeek-V3.x权重的实验性NSA支持正在开发中
- **SGLang**：已发布NSA基准测试；生产路径跟随vLLM
- **llama.cpp / CPU**：不支持；内核分解的开销在CPU吞吐量下不值得

**适合使用NSA的场景：**

- 以6.4万词元以上上下文为目标，有充足计算预算的预训练或继续训练
- 推理DeepSeek自己的长上下文检查点——这些权重是NSA原生的

**不适合使用的场景：**

- 服务现有的密集注意力预训练模型——不经过继续训练无法追加NSA
- 上下文在16k以下——三分支的开销超过节省的计算量
- 批大小为1的交互式对话——延迟敏感的解码有收益，但仅在长上下文时

## 关键术语

| 术语（英文） | 人们怎么说 | 实际含义 |
|-------------|-----------|---------|
| 压缩分支（Compressed branch） | "粗粒度视图" | 对块平均键进行注意力计算，每查询O(N/l)个键，提供全局上下文 |
| 选择分支（Selected branch） | "Top-k块" | 对压缩分支分数最高的`k`个块中细粒度词元的注意力 |
| 滑动窗口（Sliding window） | "局部上下文" | 对最近`W`个词元的注意力，用于短程模式 |
| 原生可训练性（Native trainability） | "预训练时带上稀疏性" | 稀疏模式在预训练期间学习，而不是在推理时强行附加 |
| 压缩块大小l（Compression block size l） | "粗粒度视图的分组大小" | 多少词元合并为一个摘要；通常为32到64 |
| Top-k | "保留的块数" | 未压缩词元会被读取的压缩块数量；通常为16 |
| 滑动窗口W（Sliding window W） | "局部注意力半径" | 通常为512；更短会损害局部连贯性，更长会浪费计算 |
| 分支门控（Branch gate） | "如何混合三个分支" | 逐位置MLP输出，对三个分支的贡献加权 |
| 硬件对齐（Hardware alignment） | "对内核友好的稀疏性" | 稀疏模式的选择确保GPU内核能实现理论上的加速比 |
| DSA | "NSA的后继者" | DeepSeek稀疏注意力，DeepSeek系列中NSA的继承架构 |
