# 指令遵循作为对齐信号（Instruction-Following as Alignment Signal）

> 所有后续对 RLHF 的批判都是在针对这个流水线进行论证。在研究优化压力如何扭曲代理指标之前，你必须先看清这个代理指标是什么。InstructGPT（Ouyang 等人，2022 年）定义了参考架构：在指令-响应对上进行监督微调，在成对偏好排名上训练奖励模型，以及以 SFT 策略的 KL 惩罚对奖励模型进行 PPO 训练。1.3B 的 InstructGPT 比 175B 的 GPT-3 更受偏好。这个单一结果就是 2026 年每家前沿实验室仍然采用 RLHF 形状的后训练流水线的原因。

**类型：** 学习  
**语言：** Python（标准库，玩具三阶段流水线）  
**前置知识：** Phase 10 · 06（SFT）、Phase 10 · 07（RLHF）、Phase 10 · 08（DPO）  
**预计时间：** 约 45 分钟

## 学习目标

- 说出 InstructGPT 流水线的三个阶段及每个阶段使用的损失函数。
- 解释为什么一个 1.3B 的指令微调模型在人类偏好评估上胜过了原始的 175B GPT-3。
- 说明第三阶段的 KL 惩罚所防范的内容，以及去掉它为何会导致模式追求行为。
- 描述对齐税以及 Ouyang 等人用来对抗它的 PPO-ptx 缓解方法。

## 问题所在

预训练语言模型会补全文本。它们不会回答问题。让 GPT-3"写一个反转列表的 Python 函数"，你经常会得到另一个提示词，因为大部分训练分布是网页文本，而网页文本的延续还是网页文本。模型在做它的工作——这个工作本身是错的。

每家认真的实验室用来修复这个问题的代理指标是人类偏好。两个补全结果交给评判者；评判者选择更好的那个；奖励模型学习评判者的偏好。然后 RL 循环将策略向奖励模型高分的输出移动。这就是 InstructGPT 的全部论点，三句话说完。论文其余部分都是工程细节。

## 核心概念

### 第一阶段：监督微调（SFT）

收集提示词-响应对，其中响应是善意人类会写的内容。Ouyang 等人使用了标注者和 OpenAI API 提供的 13k 个提示词。在这些数据上用标准交叉熵损失微调基础模型。

SFT 给你的：模型现在会回答问题，而不是继续完成问题。它没有给你的：当多个答案都合理时，关于评判者更偏好哪个答案的任何信号。

### 第二阶段：奖励模型（RM）

对于每个提示词，从 SFT 模型中采样 K 个补全。标注者对其进行排名。训练一个奖励模型，对任何提示词-响应对进行评分，使得当 `y_w` 优于 `y_l` 时：

```
L_RM = -log sigmoid(r(x, y_w) - r(x, y_l))
```

这就是 Bradley-Terry 成对偏好损失。RM 通常从 SFT 模型初始化，将 LM 头替换为标量头。

奖励模型规模小：6B 对于 175B 的 InstructGPT 已经足够。它们也很脆弱——论文第 5 节主要是关于小规模下出现的奖励黑客行为。

### 第三阶段：带 KL 惩罚的 PPO

定义目标函数：

```
J(pi) = E_{x~D, y~pi(.|x)} [ r(x, y) ] - beta * KL(pi(.|x) || pi_SFT(.|x))
```

用 PPO 最大化。KL 项使 `pi` 不会过度偏离 SFT 策略。没有它，优化器会找到对抗性样本——在 RM 下高分的字符串，是因为 RM 从未见过它们，而非因为人类真正偏好它们。

KL 系数 `beta` 是最重要的 RLHF 超参数。太低：奖励黑客。太高：相比 SFT 没有改进。

### 对齐税

RLHF 之后，模型更受人类偏好，但在标准基准上退化（SQuAD、HellaSwag、DROP）。Ouyang 等人称之为对齐税，并用 PPO-ptx 修复：将预训练梯度混入 RL 目标，使模型不会忘记如何完成从未被奖励的下游任务。

```
J_ptx(pi) = J(pi) + gamma * E_{x~D_pretrain} [ log pi(x) ]
```

PPO-ptx 成为标准。Anthropic、DeepMind 和 Meta 都使用某种变体。

### 结果

1.3B 的 InstructGPT（SFT + RM + PPO-ptx）在约 70% 的情况下被标注者认为优于 175B 的基础 GPT-3。差距在来自生产流量的隐藏测试提示词上更大。从这个数字可以读出两点：

1. 对齐是与能力不同的维度。175B 模型能力更强；1.3B 模型对齐更好；标注者更偏好对齐的那个。
2. 能力下限由基础模型决定。你无法通过 RLHF 让基础模型掌握它从未见过的事实。

### 为什么这是 Phase 18 的参考起点

后续课程的每个批判——奖励黑客（第 2 课）、DPO（第 3 课）、迎合性（第 4 课）、CAI（第 5 课）、潜伏智能体（第 7 课）、对齐伪装（第 9 课）——都是在针对这个流水线的某个部分进行论证。奖励黑客攻击第 2 阶段。DPO 将第 2 和第 3 阶段合并。CAI 替换了人类标注者。迎合性表明标注者是一个有偏见的信号。对齐伪装表明策略可以完全绕过第 3 阶段。没有先把这个流水线装进脑海，就无法理解这些批判。

## 使用它

`code/main.py` 在玩具偏好数据上模拟三个阶段。基础"策略"是行动 {A, B, C} 上有偏的硬币。第一阶段 SFT 模拟标注者在 200 个提示词上的行动。第二阶段从 500 个成对排名中拟合 Bradley-Terry 奖励模型。第三阶段对 SFT 策略使用 KL 惩罚运行简化的 PPO 更新。你可以观察奖励上升、KL 散度增长、策略漂移——你也可以关闭 KL 项，看到奖励黑客在 50 步更新内出现。

观察点：

- `beta = 0.1` vs `beta = 0.0` 时的奖励轨迹。
- 训练步骤中的 KL(pi || pi_SFT)。
- 与标注者偏好相比的最终行动分布。

## 练习

1. 运行 `code/main.py`。设置 `beta = 0.0` 并报告 200 步 PPO 后的行动分布。用一段话解释模式追求行为。

2. 修改奖励模型以对行动 B 有 +0.5 的偏差（模拟奖励 bug）。用 `beta = 0.1` 运行 PPO。KL 惩罚是否能防止策略利用这个偏差？在什么 `beta` 值时利用行为变得明显？

3. 阅读 Ouyang 等人（arXiv:2203.02155）图 1。通过运行 PPO 1、5、20、100 步并测量相对于 SFT 模型的偏好，复现标注者偏好曲线。

4. 论文第 4.3 节报告 1.3B InstructGPT 在约 70% 的情况下击败 175B GPT-3。为什么在隐藏生产提示词上的比率会比标注者自己的提示词上高？

5. 在相同偏好数据上用 DPO（Phase 10 · 08）替换 PPO 损失。比较最终策略漂移（到 SFT 的 KL）和最终奖励。在相同奖励下，哪种方法漂移更远？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| SFT | "指令微调" | 第一阶段：在提示词-响应对上进行交叉熵微调 |
| Reward model（奖励模型） | "RM" | 在（提示词，响应）上用 Bradley-Terry 成对标签训练的标量回归器 |
| Bradley-Terry | "成对偏好损失" | -log sigmoid(r_w - r_l)；将成对排名简化为二分类 |
| KL penalty（KL 惩罚） | "正则化项" | `beta * KL(pi \|\| pi_SFT)` — 使 RL 策略保持在 SFT 锚点附近 |
| PPO-ptx | "带预训练混合的 PPO" | 在 PPO 目标中加入部分预训练对数似然，以抵消对齐税 |
| Alignment tax（对齐税） | "RLHF 回归" | RLHF 后标准基准的下降，RLHF 没有针对这些基准进行目标化 |
| Labeler preference（标注者偏好） | "基准真相" | 人类排名的样本；RM 是这一指标的统计代理，不是"人类价值观"的代理 |
