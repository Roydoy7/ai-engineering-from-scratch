# 红队测试：PAIR 与自动化攻击（Red-Teaming: PAIR and Automated Attacks）

> Chao、Robey、Dobriban、Hassani、Pappas、Wong（NeurIPS 2023，arXiv:2310.08419）。PAIR——提示词自动迭代细化——是标准的自动化黑盒越狱方法。一个带有红队系统提示词的攻击者 LLM 迭代地为目标 LLM 提出越狱方案，将尝试和响应积累在自己的聊天历史中作为上下文反馈。PAIR 通常在 20 次查询内成功，效率比 GCG（Zou 等人的 token 级梯度搜索）高几个数量级，且无需白盒访问。PAIR 现在是 JailbreakBench（arXiv:2404.01318）和 HarmBench 的标准基线，与 GCG、AutoDAN、TAP 和说服性对抗提示词并列。

**类型：** 构建  
**语言：** Python（标准库，针对玩具目标的模拟 PAIR 循环）  
**前置知识：** Phase 18 · 01（指令遵循）、Phase 14（智能体工程）  
**预计时间：** 约 75 分钟

## 学习目标

- 描述 PAIR 算法：攻击者系统提示词、迭代细化、上下文反馈。
- 解释为什么当目标是黑盒时，PAIR 严格比 GCG 更高效。
- 说出四种其他自动化攻击基线（GCG、AutoDAN、TAP、PAP）并说出每种的一个区别特征。
- 描述 JailbreakBench 和 HarmBench 评估协议，以及每种下"攻击成功率"的含义。

## 问题所在

红队测试过去是一项手动活动。少数专家测试人员构建对抗性提示词并追踪哪些有效。这无法扩展：攻击成功率需要统计样本，而目标在每次模型发布时都是移动靶。PAIR 将红队测试操作化为针对黑盒目标的优化问题。

## 核心概念

### PAIR 算法

输入：
- 目标 LLM T（我们正在攻击的模型）。
- 裁判 LLM J（评分响应是否为越狱）。
- 攻击者 LLM A（红队优化器）。
- 目标字符串 G："以 [有害指令] 回应"。
- 预算 K（通常为 20 次查询）。

循环，k 从 1 到 K：
1. A 以目标 G 和迄今为止的（提示词、响应）对历史为输入。
2. A 发出新提示词 p_k。
3. 将 p_k 提交给 T；接收响应 r_k。
4. J 根据目标对（p_k, r_k）评分。
5. 如果分数 >= 阈值，停止——发现越狱。
6. 否则，将（p_k, r_k）附加到 A 的历史；继续。

经验结果（NeurIPS 2023）：对 GPT-3.5-turbo、Llama-2-7B-chat 的攻击成功率 > 50%；成功的平均查询次数在 10-20 范围内。

### 为什么 PAIR 高效

GCG（Zou 等人，2023 年）通过梯度搜索对抗性 token 后缀；它需要白盒模型访问，并产生不可读的后缀。PAIR 是黑盒的，产生可以跨模型迁移的自然语言攻击。PAIR 的上下文反馈让攻击者从每次拒绝中学习；GCG 没有等价物（每次新的 token 更新都必须重新发现先前的进展）。

### 相关自动化攻击

- **GCG（Zou 等人，2023 年，arXiv:2307.15043）。** 对抗性后缀的 token 级梯度搜索。白盒，可迁移，产生不可读字符串。
- **AutoDAN（Liu 等人，2023 年）。** 在层次目标引导下对提示词进行进化搜索。
- **TAP（Mehrotra 等人，2024 年）。** 带剪枝的攻击树——分支多个 PAIR 风格的推出。
- **PAP（Zeng 等人，2024 年）。** 说服性对抗提示词——将人类说服技巧编码为提示词模板。

### JailbreakBench 和 HarmBench

两者（2024 年）都标准化了评估：

- JailbreakBench（arXiv:2404.01318）。100 种跨越 10 个 OpenAI 策略类别的有害行为。攻击成功率（ASR）作为主要指标。需要裁判（GPT-4-turbo、Llama Guard 或 StrongREJECT）。
- HarmBench（Mazeika 等人，2024 年）。510 种跨越 7 个类别的行为，带有语义和功能危害测试。比较 18 种攻击对 33 个模型。

ASR 通常在固定查询预算下报告。比较攻击需要匹配预算；200 次查询下 90% ASR 与 20 次查询下 85% ASR 不可比较。

### 对 2026 年部署的重要性

每家前沿实验室现在都在发布前对生产模型运行 PAIR 和 TAP。ASR 轨迹出现在模型卡片（第 26 课）和安全案例附录（第 18 课）中。该攻击并不罕见——它是标准基础设施。

### 这在 Phase 18 中的位置

第 12 课是自动化攻击基础。第 13 课（多样本越狱）是互补的长度利用。第 14 课（ASCII 艺术/视觉）是编码攻击。第 15 课（间接提示注入）是 2026 年的生产攻击面。第 16 课涵盖防御工具的对应品（Llama Guard、Garak、PyRIT）。

## 使用它

`code/main.py` 构建了一个玩具 PAIR 循环。目标是一个拒绝"明显"有害提示词的模拟分类器（关键词过滤器）。攻击者是一个基于规则的细化器，尝试改述、角色扮演框架和编码。裁判对响应评分。你观察攻击者在约 5-15 次迭代内对关键词过滤器成功，对语义过滤器失败。

## 交付它

本课产出 `outputs/skill-attack-audit.md`。给定红队评估报告，它审计：运行了哪些攻击（PAIR、GCG、TAP、AutoDAN、PAP），每种在什么预算下，使用哪个裁判，针对哪个有害行为集（JailbreakBench、HarmBench、内部）。

## 练习

1. 运行 `code/main.py`。测量三种内置攻击者策略的平均成功查询次数。解释每种利用的目标防御假设。

2. 实现第四种攻击者策略（例如，翻译为另一种语言，base64 编码）。报告新策略对关键词过滤器目标和语义过滤器目标的新的平均成功查询次数。

3. 阅读 Chao 等人 2023 年图 5（PAIR vs GCG 比较）。描述尽管 PAIR 具有效率优势，但 GCG 更受青睐的两种场景。

4. JailbreakBench 针对固定目标集报告 ASR。设计一个额外的指标，测量攻击多样性（成功提示词的方差）。解释为什么多样性对防御评估很重要。

5. TAP（Mehrotra 2024）通过分支 + 剪枝扩展了 PAIR。勾勒对 `code/main.py` 的 TAP 风格扩展，并描述计算成本与成功率的权衡。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| PAIR | "自动化越狱" | 提示词自动迭代细化；攻击者-LLM + 裁判-LLM 循环 |
| GCG | "梯度越狱" | 对抗性后缀的白盒 token 级梯度搜索 |
| Attack success rate（攻击成功率，ASR） | "k 次查询时的越狱率" | 主要指标；必须与查询预算和裁判身份一起报告 |
| Judge LLM（裁判 LLM） | "评分者" | 对响应是否满足有害目标进行评分的 LLM |
| JailbreakBench | "评估" | 带有标记类别的标准化有害行为集 |
| HarmBench | "更广泛的基准" | 510 种行为，功能 + 语义危害测试 |
| TAP | "攻击树" | 带有分支 + 剪枝的 PAIR；以更高计算量获得更好 ASR |
