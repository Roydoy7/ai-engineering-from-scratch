# 谈判与议价（Negotiation and Bargaining）

> 智能体就资源、价格、任务分配和条款进行谈判。2026 年的基准测试结果很清晰：NegotiationArena（arXiv:2402.05863）显示 LLM 可以通过角色操纵（"迫切需要"）将回报提高约 20%；《衡量语言模型的议价能力》（arXiv:2402.15813）显示买家比卖家更难，且规模无济于事——他们的 **OG-Narrator**（确定性报价生成器 + LLM 叙述者）将成交率从 26.67% 提升至 88.88%；大规模自主谈判竞赛（arXiv:2503.06416）进行了约 18 万次谈判，发现**隐藏思维链**的智能体通过向对手隐藏推理过程而获胜；Bhattacharya 等人 2025 年基于哈佛谈判项目指标的研究将 Llama-3 列为最有效、Claude-3 最具攻击性、GPT-4 最公平。本课实现合同网协议（FIPA 的前身，第 02 课），连接 LLM 风格的买家/卖家，运行 OG-Narrator 风格的分解，并测量每种结构选择如何影响成交率。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 16 · 02（FIPA-ACL 源流）、Phase 16 · 09（并行群体网络）  
**预计时间：** 约 75 分钟

## 问题所在

两个智能体需要就价格达成一致。如果仅靠纯语言提示，2024-2026 年的 LLM 在严格参数化的议价任务中成交率出乎意料地低（arXiv:2402.15813 约 27%）。规模无法解决问题：GPT-4 在议价上并没有比 GPT-3.5 *结构性地*更好；它只是在*议价的语言*上更好。

根本问题在于 LLM 混淆了两项工作——决定报价和叙述报价。OG-Narrator 将两者分离：一个确定性的报价生成器计算数字动作；LLM 只负责叙述。成交率跃升至约 89%。

这呼应了一个经典的多智能体发现：将机制与通信层解耦会获胜。合同网协议（FIPA，1996 年；Smith，1980 年）是参考性的任务市场机制。将 LLM 插入叙述槽，你就得到了一个现代的 LLM 驱动的任务市场。

## 核心概念

### 合同网协议，一段话说清

Smith 1980 年的合同网协议：一个**管理者**广播**提案征集（cfp）**；**投标者**用包含报价的**propose** 消息回应；管理者选出获胜者，向获胜者发送 **accept-proposal**，向失败者发送 **reject-proposal**。获胜者执行工作。可选消息：**refuse**（投标者拒绝提案）。FIPA 将这一机制编码为 `fipa-contract-net` 交互协议。

### 为什么 OG-Narrator 获胜

《衡量语言模型的议价能力》（arXiv:2402.15813）观察到：

- LLM 经常违反议价规则（以荒谬的价格报价，忽视对方的可能协议区间 ZOPA）。
- 它们的锚定效果很差（接受糟糕的首次报价；以象征性而非战略性的幅度还价）。
- 规模本身无法解决这些问题。更大的模型能用更合理的语言表达类似的战略错误。

OG-Narrator 分解：

```
           ┌──────────────────┐        ┌──────────────────┐
  状态   → │   报价生成器     │  价格→ │    LLM 叙述者    │ → 消息
           │   （确定性）     │        │  （撰写人类风格  │
           │                  │        │   的配套内容）   │
           └──────────────────┘        └──────────────────┘
```

报价生成器是一种经典的谈判策略：Rubinstein 议价模型、Zeuthen 策略，或者简单的针对价格的以牙还牙。LLM 负责叙述。消息包含确定性的价格和自然语言的框架表达。

成交率之所以跃升，是因为：
- 价格始终在议价区间内。
- 锚定是战略性的，而非情绪性的。
- LLM 做了它擅长的事：写作。

### NegotiationArena 的发现

arXiv:2402.05863 提供了权威基准测试。主要发现：

- LLM 可以通过采用角色（"我迫切需要在周五前卖掉这个"）将回报提高约 20%——角色操纵是真实的战术。
- 公平/合作型智能体会被对抗性智能体利用；防御需要明确的反姿态。
- 对称配对在约 40% 的基准场景中收敛到不公平的结果。

这不是"LLM 是糟糕的谈判者"，而是"LLM 的谈判方式太像人类了，包括那些可被利用的部分"。

### 思维链隐藏

大规模自主谈判竞赛（arXiv:2503.06416）对多种 LLM 策略进行了约 18 万次谈判。获胜者向对手隐藏了自己的推理过程：

- 如果一个智能体将"我只接受到 75 美元；我的保留价是 70 美元"打印到公开可见的草稿区，对手就会读到它。
- 获胜者私下计算策略；输出渠道只包含报价和必要的最少叙述。

这是 2026 年对经典博弈论的呼应（Aumann 1976 关于理性与信息）：暴露你的私人估值会降低回报。LLM 不会凭直觉意识到这一点，会愉快地在推理追踪中输入自己的保留价，而这些推理追踪会对对手可见。

工程要点：将私人草稿区上下文与公开消息上下文分开。这不是可选的。

### Bhattacharya 等人 2025 年——模型排名

基于哈佛谈判项目指标（原则性谈判、BATNA 尊重、利益互惠）：

- **Llama-3** 在达成交易上最有效（成交率 + 回报）。
- **Claude-3** 是最具攻击性的谈判者（高锚定、后期让步）。
- **GPT-4** 是最公平的（在不同配对中回报方差最小）。

这是 2025 年的快照。重点不是 2026 年 4 月哪个模型获胜——而是不同的基础模型具有持久的谈判风格。异质集成（第 15 课）将此作为多样性来源之一。

### 通过合同网 + LLM 进行任务分配

合同网在 LLM 多智能体中的现代再利用：

1. 管理者智能体将任务分解为单元。
2. 向工作者智能体广播带有任务描述的 `cfp`。
3. 每个工作者返回一个报价：`(price, eta, confidence)`，其中 price 可以是 token 数、计算单元或金额。
4. 管理者选出获胜者（单个或多个，取决于任务）并授予。
5. 被拒绝的工作者可以自由竞标其他任务。

这在超过 100 个工作者时依然能很好地扩展，因为协调是广播-响应式的，而非同步聊天。在生产中使用：Microsoft Agent Framework 的编排模式，以及一些 LangGraph 实现。

### LLM 利益相关者交互谈判

NeurIPS 2024 引入了带有**秘密分数**和**最低接受阈值**的多方可评分游戏。每个利益相关者都有私人效用；LLM 必须从消息中推断这些效用。这是两方议价向 N 方联盟形成的推广。与具有异质工作者能力的生产任务市场相关。

### 叙述 vs 机制规则

综合 2024-2026 年的所有谈判基准测试，一致的工程规则是：

> 让 LLM 叙述。不要让 LLM 计算报价。

如果报价需要是一个数字（价格、ETA、数量），就从谈判状态确定性地生成它，并让 LLM 生成框架表达。如果报价需要是一个提案结构（任务分解、角色分配），就让 LLM 起草，但在发送之前根据 Schema 和约束条件进行验证。

## 构建它

`code/main.py` 实现了：

- `ContractNetManager`、`ContractNetTask`、`Bid` — 管理者 + 投标者，广播 cfp，收集提案，授予。
- `og_narrator_bargain(state, rng)` — OG-Narrator 买家：确定性的 Zeuthen 风格让步，朝向中间价格。
- `seller_response(state, rng)` — 确定性的卖家还价策略（两种风格的结构性基准真相）。
- `naive_llm_bargain(state, rng)` — 模拟纯 LLM 议价者：价格方差高，经常超出 ZOPA。
- 测量：对 1000 次试验计算成交率，每次试验重新采样保留价。

运行：

```
python3 code/main.py
```

预期输出：朴素 LLM 的成交率约 65-75%；OG-Narrator 的成交率约 85-95%；15-25 个百分点的差距是将报价生成与叙述分解的结构性优势。另外还有一个带三个投标者和一个任务的合同网任务市场分配示例。

## 使用它

`outputs/skill-bargainer-designer.md` 设计一个议价协议：谁生成报价（确定性还是 LLM）、谁叙述、私人草稿区如何与公开消息分离，以及如何监控成交率。

## 交付它

生产议价检查清单：

- **单独的草稿区。** 私人状态永远不会进入对手的上下文。这是不可谈判的。
- **确定性报价生成。** 价格、数量、ETA：计算得出，不要通过提示词生成。
- **验证所有传入报价**是否符合 Schema。在协议边界拒绝超出 ZOPA 的报价。
- **限制轮次。** 最多 3-5 轮；在陷入僵局时上升级别至调解者。
- **持续监测成交率和回报方差。** 下降的成交率是症状——通常是提示词漂移或对手侧攻击。
- **记录所有被拒绝的提案**及确定性的拒绝理由。对于合同网管理者，落选的投标者需要了解原因。

## 练习

1. 运行 `code/main.py`。确认 OG-Narrator 在成交率上优于朴素 LLM。差距有多大？
2. 实现**基于角色的回报提升**（arXiv:2402.05863）——买家在叙述中采用"这周迫切需要购买"的角色，报价生成器保持不变。成交率或回报会改变吗？
3. 实现思维链**隐藏**：维护一个不传递给对手的私人草稿区字符串。如果你意外泄露了它（通过交换渠道来模拟），会发生什么？
4. 将合同网扩展为带底价的 N 投标者拍卖。当所有报价都超过底价时，管理者如何在最低价格和最高质量之间做出选择？你选择哪种授予规则，为什么？
5. 阅读 Bhattacharya 等人 2025 年关于哈佛谈判项目指标的研究。实现两种不同风格的议价者（攻击性 vs 公平型）。测量在对称和非对称配对下的回报方差。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Contract Net（合同网） | "任务市场" | Smith 1980，FIPA 1996。cfp + propose + accept/reject。经典任务市场机制。 |
| ZOPA | "可能协议区间" | 买家最高价和卖家最低价之间的重叠。超出此区间的报价无法成交。 |
| BATNA | "谈判协议的最佳替代方案" | 如果此次交易失败的备用选项。决定你的保留价。 |
| OG-Narrator | "报价生成器 + 叙述者" | 分解：确定性报价，LLM 叙述。 |
| Zeuthen strategy（Zeuthen 策略） | "风险最小化让步" | 根据风险限制做出让步的经典报价生成器。 |
| Rubinstein bargaining（Rubinstein 议价） | "交替报价均衡" | 带有折现的无限期议价的博弈论模型。 |
| CoT concealment（思维链隐藏） | "隐藏你的推理" | arXiv:2503.06416 中的获胜者保留私人草稿区；公开渠道只显示报价。 |
| Persona manipulation（角色操纵） | "情感姿态" | arXiv:2402.05863：使用迫切感/紧迫感角色可获得约 20% 的回报提升。 |
