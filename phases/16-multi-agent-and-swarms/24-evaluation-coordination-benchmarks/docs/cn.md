# 评估与协调基准（Evaluation and Coordination Benchmarks）

> 五个 2025-2026 年的基准覆盖了多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025，arXiv:2503.01935）评估星形/链式/树形/图形拓扑，采用里程碑 KPI；**图形拓扑最适合研究任务**，认知规划可增加约 3% 的里程碑达成率。**COMMA** 评估多模态非对称信息协调；包括 GPT-4o 在内的最先进模型难以超越随机基线。**MedAgentBoard**（arXiv:2505.12371）覆盖四类医疗任务，常常发现多智能体并不优于单一 LLM。**AgentArch**（arXiv:2509.10769）对结合工具使用、记忆与编排的企业智能体架构进行基准测试。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含跨越 41 个代码库的 1865 道题，涵盖商业应用、B2B 服务和开发工具；前沿模型在 Pro 上得分约 23%，而在 Verified 上超过 70%——这是对数据污染问题的现实校验。Claude Opus 4.7（2026 年 4 月）在 Pro 上报告的分数为 **64.3%**（使用了明确的智能体团队协调；Anthropic 尚未发布原始资料，视为初步数据）；Verdent（智能体脚手架）在 Verified 上达到 **76.1% pass@1**（[Verdent 技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是 2026 年社区的焦点会议。本课基于 MARBLE 的指标进行构建，运行拓扑与指标的扫描对比，并固化"仅仅通过 SWE-bench Verified 不能作为泛化能力的证据"这一规则。

**类型：** 学习  
**语言：** Python（标准库）  
**前置知识：** Phase 16 · 15（投票与辩论拓扑）、Phase 16 · 23（故障模式）  
**预计时间：** 约 75 分钟

## 问题所在

当一篇论文声称"我们的多智能体系统更好"时，问题是：在什么方面更好，在什么任务上，用什么方式测量？2023-2024 年的多智能体评估时代是一片混乱——每个人都选择自己的指标、自己的基线和自己的任务集。2025-2026 年的基准强加了结构秩序。

没有共享基准，就无法有意义地比较两个多智能体系统。更糟糕的是，没有保留基准，前沿模型可能会造成数据污染。SWE-bench Verified 在 2025 年中期已被部分污染进入训练语料；前沿分数虚高；Pro 就是为了作为无污染的现实校验而设计的。

本课列举五个 2026 年的标准基准，说明每个基准测量什么，并教你批判性地解读基准声明。

## 核心概念

### MultiAgentBench（MARBLE）——ACL 2025

arXiv:2503.01935。在研究、编程和规划任务上评估四种协调拓扑（星形、链式、树形、图形）。基于里程碑的 KPI 追踪部分进度，而不只是最终成功。

测量结果：

- **图形**拓扑最适合研究场景；支持任意-任意的互相批评。
- **链式**最适合逐步细化的编程任务。
- **星形**最适合快速事实整合。
- 图形拓扑在约 4 个智能体之后出现**协调税**。
- **认知规划**在各拓扑上增加约 3% 的里程碑达成率。

适用场景：你想对协调拓扑进行苹果对苹果的比较时。MARBLE 仓库（https://github.com/ulab-uiuc/MARBLE）提供了评估器。

### COMMA——多模态非对称信息

覆盖智能体具有不同观察模态且必须在没有完整信息共享的情况下进行协调的任务。报告的结果令人不安：包括 GPT-4o 在内的前沿模型难以在 COMMA 的智能体-智能体协作任务上超越**随机基线**。信号是多智能体模态训练不足、评估不足——LLM 能合理处理单模态合作；多模态协调则崩溃。

适用场景：你的系统有多模态或非对称信息协调。COMMA 的零结果是测量前不要妄下声明的警告。

### MedAgentBoard——领域压力测试

arXiv:2505.12371。四类医疗任务：诊断、治疗规划、报告生成、患者沟通。比较多智能体 vs 单一 LLM vs 传统规则系统。

发现：多智能体在大多数类别上并不优于单一 LLM。多智能体优势的范围很窄——当子任务明显可分离时，任务分解有帮助（诊断 + 治疗）；当协调开销超过专业化收益时，则会起反作用（报告生成）。

适用场景：你的领域有明确的单一 LLM 基线。如果 MedAgentBoard 的结论可以推广，许多提出的多智能体系统都是过度设计的。

### AgentArch——企业架构

arXiv:2509.10769。企业环境中工具使用、记忆和编排层层叠加。基准隔离了每一层的贡献：添加工具能提升多少？添加记忆呢？添加多智能体编排呢？

适用场景：你在设计企业智能体栈并需要为每一层进行论证时。AgentArch 帮助避免购买无法量化价值的功能。

### SWE-bench Pro——现实校验

arXiv:2509.16941。跨越 41 个代码库的 1865 道题，涵盖商业应用、B2B 服务和开发工具。设计为使用更新的训练截止日期以保持**无污染**。前沿模型在 Pro 上得分约 23%，而在 Verified 上超过 70%。差距就是污染的信号。

2026 年 4 月的得分：
- Claude Opus 4.7 在 Pro 上：**64.3%**（使用了明确的智能体团队协调；Anthropic 尚未发布原始资料，视为初步数据）。
- Verdent（智能体脚手架）在 Verified 上：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。
- 无智能体脚手架的前沿模型在 Pro 上的原始分数：约 23-35%（[SWE-bench Pro 论文](https://arxiv.org/abs/2509.16941)）。

结论："我们超越了 SWE-bench Verified"不再是能力的证据。Pro 是当前的门控测试。智能体团队脚手架在 Pro 上产生了可测量的提升（约 30-40 个百分点的差距），这是 2026 年多智能体协调最强的实证论据之一。

### AAAI 2026 WMAC

AAAI 2026 Bridge Program——多智能体协调研讨会（https://multiagents.org/2026/）。2026 年多智能体 AI 研究的社区焦点。接受的论文和研讨会论文集是评估新方法的标准场所；对于生产决策，优先参考 WMAC 接受的声明，而非 arXiv 预印本。

### 批判性解读基准声明——2026 年检查清单

当有人声称多智能体结果时：

1. **哪个基准，哪个划分？** SWE-bench Verified 与 Pro 的差异巨大。在错误划分上报告的数字毫无意义。
2. **污染检查。** 基准是否在模型训练截止日期之后发布？如果不是，要谨慎对待。
3. **基线比较。** 与单一 LLM 基线、与随机、与先前的多智能体工作相比。不是"与同一系统的未调优版本相比"。
4. **统计显著性。** N 次试验、p 值、置信区间。前沿模型方差大；单次运行具有误导性。
5. **任务多样性。** 一个任务还是多个？泛化能力对生产很重要。
6. **成本披露。** 每个任务的 token 数、挂钟时间。20 倍成本的 90% 解决方案是业务决策，而非能力声明。

### 现有基准都没有很好测量的内容

- **长时域协调。** 数天的挂钟交互。当前所有基准运行时间都很短。
- **对抗性韧性。** 当一个智能体是恶意或被攻陷时会发生什么？
- **部署中的漂移。** 基准是静态的；生产分布会变化。
- **成本归一化性能。** 大多数基准只报告原始准确率，而非每美元准确率。

为你真正关心的维度构建自己的内部基准，通常是正确的选择。

## 构建它

`code/main.py` 是一个非交互式演示：

- 模拟 3 个多智能体系统在一个玩具任务上的表现。
- 为每个系统计算 MARBLE 风格的里程碑指标。
- 通过从"训练"集中保留任务来运行污染检查。
- 明确地与随机基线进行比较。
- 打印基准声明的评分卡。

运行：

```bash
python3 code/main.py
```

预期输出：包含原始准确率、里程碑达成率、每任务成本、与随机基线的差值，以及污染检查说明的系统评分卡。

## 使用它

`outputs/skill-benchmark-reader.md` 读取任何多智能体基准声明并应用审查检查清单。输出：评级和注意事项。

## 交付它

生产评估规范：

- **构建内部基准**，反映你的实际生产分布。公开基准可提供参考，但不能替代内部基准。
- **在每个比较中包含随机基线。** 如果你在协调任务上无法以大幅优势超越随机，该任务的提法可能有问题。
- **在准确率旁报告成本。** Token 成本和挂钟时间。运维团队两者都需要。
- **每季度重建基准。** 生产分布会变化；过时的基准会造成误导。
- **避免针对已发布基准过拟合。** 如果你的团队专门为 SWE-bench Pro 数字优化，你将在生产上出现退步。

## 练习

1. 运行 `code/main.py`。识别三个模拟系统中哪一个的每里程碑成本最好。它与原始准确率最高的系统相符吗？
2. 阅读 MultiAgentBench（arXiv:2503.01935）。对于你自己的任务领域，决定 MARBLE 会推荐四种拓扑中的哪一种。从论文结果中给出理由。
3. 阅读 SWE-bench Pro 论文。是什么具体机制使其对污染具有抵抗力？同样的技术能否应用于你关心的其他基准？
4. 阅读 COMMA 关于多模态协调的发现。设计一个简单的多模态协调任务，可以加入你的内部基准。什么算作有用的信号？
5. 将基准声明检查清单应用于一篇最新多智能体论文的核心结果。你会给这个声明打什么评级？

| COMMA | "多模态基准" | 多模态非对称信息协调；前沿模型难以超越随机基线。 |
