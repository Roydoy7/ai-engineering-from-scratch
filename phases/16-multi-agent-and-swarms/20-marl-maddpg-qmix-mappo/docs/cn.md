# MARL——MADDPG、QMIX、MAPPO（MARL — MADDPG, QMIX, MAPPO）

> 多智能体协调的强化学习传统，在 2026 年仍然影响着 LLM 智能体系统。**MADDPG**（Lowe 等人，NeurIPS 2017，arXiv:1706.02275）引入了集中式训练、去中心化执行（CTDE）：每个 critic 在训练时看到所有智能体的状态和行动；测试时只运行本地 actor。适用于合作、竞争和混合场景。**QMIX**（Rashid 等人，ICML 2018，arXiv:1803.11485）是带有单调混合网络的价值分解；每个智能体的 Q 值组合成联合 Q，使 `argmax` 可以干净地分布计算——在星际争霸多智能体挑战（SMAC）上占主导地位。**MAPPO**（Yu 等人，NeurIPS 2022，arXiv:2103.01955）是带有集中式价值函数的 PPO；在粒子世界、SMAC、谷歌研究足球、Hanabi 上仅需最少的调参就"出人意料地有效"。这些算法支撑着必须去中心化执行的智能体团队的训练策略。MAPPO 是 **2026 年合作 MARL 的默认基线**。本课在一个小型网格世界玩具上构建三种算法，在接触 LLM 智能体训练之前将这三个核心思想内化于心。

**类型：** 学习  
**语言：** Python（标准库，小型无 NumPy 实现）  
**前置知识：** Phase 09（强化学习）、Phase 16 · 09（并行群体网络）  
**预计时间：** 约 90 分钟

## 问题所在

LLM 智能体系统越来越多地在训练智能体间协调的策略：何时让步，何时行动，调用哪个同伴。告诉你如何训练这类策略的文献是多智能体强化学习（MARL），它早于 LLM 浪潮，有一小套主导算法。

在没有模式词汇的情况下阅读 MARL 论文是痛苦的。集中式训练与去中心化执行（CTDE）、价值分解和集中式 critic 不是流行词——它们是对特定问题的具体答案：

- 独立 RL（每个智能体单独学习）从每个智能体的角度看是非平稳的。效果差。
- 集中式 RL（一个智能体控制所有）无法扩展，且违反执行约束。
- CTDE 兼得两者之长：用全局信息训练，用本地策略部署。

## 核心概念

### 论文使用的三个环境

- **粒子世界（multi-agent particle env）。** 简单的 2D 物理，包含合作/竞争任务。MADDPG 的原始测试床。
- **星际争霸多智能体挑战（SMAC）。** 合作式微操，部分观察。QMIX 的测试床。离散行动，连续状态。
- **谷歌研究足球、Hanabi、MPE。** MAPPO 的基线。

不同环境有不同的行动/观察类型，算法相应选择。

### MADDPG（2017）——CTDE 模式

每个智能体 `i` 有一个 actor `mu_i(o_i)`，将其自身的观察映射到行动。每个智能体还有一个 critic `Q_i(x, a_1, ..., a_n)`，在训练时看到所有观察和所有行动。actor 通过策略梯度对 critic 的评估进行更新。

```
actor 更新：  grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic 更新：  对 Q_i(x, a_1..n) 进行 TD，给定下一状态联合估计
```

为什么用 CTDE：训练时我们知道所有人的行动；我们利用这一点来减少每个 critic 的方差。部署时，每个智能体只看到 `o_i` 并调用 `mu_i(o_i)`。

失效模式：critic 随 N 个智能体增长（输入包含所有行动）。没有近似的情况下，超过约 10 个智能体就无法扩展。

### QMIX（2018）——价值分解

仅用于合作。全局奖励是每个智能体 Q 值的单调函数之和：

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证了 `argmax_a Q_tot` 可以通过每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这**恰好就是去中心化执行属性**——你所需要的。训练时，混合网络从每个智能体的 Q 值生成 `Q_tot`。

QMIX 为何在 SMAC 上获胜：合作式星际争霸微操具有同质智能体、本地观察、全局奖励——完美适合价值分解。

失效模式：单调性约束是限制性的；某些任务具有非单调可分解的奖励结构（一个智能体为团队牺牲）。扩展版本（QTRAN、QPLEX）放宽了这一限制。

### MAPPO（2022）——被忽视的默认选择

多智能体 PPO：带有集中式价值函数的 PPO。每个智能体有自己的策略；所有智能体共享（或有每智能体的）价值函数，这些价值函数看到完整状态。Yu 等人 2022 年在五个基准上将 MAPPO 与 MADDPG、QMIX 及其扩展进行了比较，发现：

- MAPPO 在粒子世界、SMAC、谷歌研究足球、Hanabi、MPE 上与离策略 MARL 方法持平或更优。
- 需要最少的超参数调节。
- 训练稳定；在不同随机种子上可复现。

社区在这篇论文之前低估了在策略 MARL。2026 年，MAPPO 是合作 MARL 的默认基线；任何新方法都必须超过它。

### LLM 智能体工程师为何应该关注

三种直接用途：

1. **路由器训练。** 一个元智能体选择哪个子智能体处理任务。这是一个带有 N 个去中心化子智能体和一个集中式路由器的 MARL 问题。MAPPO 适用。
2. **角色涌现。** 在生成式智能体模拟中，训练智能体随时间采用互补角色是一个变相的 MARL 问题。QMIX 风格的价值分解通过构造强制互补性。
3. **多智能体工具使用。** 当智能体共享工具并竞争预算时，通过 CTDE 训练它们会产生遵守资源约束的可部署本地策略。

实际注意事项：2026 年，大多数生产 LLM 智能体系统通过提示词而非训练来引导策略。当你有（a）大量交互数据、（b）清晰的奖励信号、（c）投资训练基础设施的意愿时，MARL 才会发挥作用。

### CTDE 作为超越 RL 的设计模式

即使不进行训练，CTDE 也是一个有用的架构模式：

- 在*设计时*，假设完整的团队可见性。
- 在*运行时*，强制去中心化执行：每个智能体只看到 `o_i`。

这种模式迫使你明确保持每个智能体的状态，并提前考虑部分可观察性。许多生产多智能体系统默默地到处假设共享状态——CTDE 规范可以防止这一点。

### 非平稳性问题

当多个智能体同时学习时，每个智能体的环境（包括其他人的策略）是非平稳的。经典单智能体 RL 的证明失效。本课中的 MARL 算法都解决了这个问题：

- MADDPG：全局 critic 看到所有行动，因此其价值估计是平稳的。
- QMIX：价值分解将学习移到联合 Q 空间，其中最优性是有明确定义的。
- MAPPO：集中式价值函数抑制了来自他人策略变化的方差。

在 LLM 智能体系统中，非平稳性表现为"我的智能体上个月还能用，现在上游那个智能体改了，我的就行为异常了"。用 CTDE 训练 MARL 是原则性的修复；提示词层面的修复更快但持久性更差。

### 本课不涵盖的内容

实际训练网络是 Phase 09 的主题。本课构建脚本化策略版本，在没有梯度更新的情况下演示 CTDE、价值分解和集中式价值模式。目标是在你拿起完整的 MARL 库（PyMARL、MARLlib、RLlib 多智能体）之前将这些模式内化。

## 构建它

`code/main.py` 实现了三种模式演示，全部在一个微型 2 智能体合作网格世界上：

- 环境：2 个智能体在 4×4 网格上，一个奖励物品。奖励 = 1 如果任意智能体到达物品；任务结束。
- `IndependentAgents` — 每个智能体将其他人视为环境。基线。
- `MADDPGStyle` — 集中式 critic 计算联合价值；actor 策略从中更新。脚本化策略改进。
- `QMIXStyle` — 带有单调混合器的价值分解。
- `MAPPOStyle` — 集中式价值函数；策略对共享基线进行更新。

四种版本都运行相同的回合并报告平均到达目标所需步数。CTDE 变体收敛到比独立基线更短的路径。

运行：

```
python3 code/main.py
```

预期输出：独立智能体平均需要约 6 步；CTDE 变体收敛到约 3.5 步（4×4 网格的最优是 3 步）。尽管是脚本化策略，模式差异仍然明显。

## 使用它

`outputs/skill-marl-picker.md` 是一个技能，为给定的多智能体任务选择 MARL 算法：合作 vs 竞争、同质 vs 异质、行动空间类型、规模、奖励信号。

## 交付它

生产中的 MARL 很少见。当你确实使用它时：

- **从 MAPPO 开始。** 2022 年的论文将其确立为基线；先复现它可以节省数周追逐更花哨方法的时间。
- **记录每个智能体的观察和行动流。** 没有每智能体追踪，调试 MARL 是无望的。
- **将训练代码与执行代码分开。** CTDE 是一种规范；让执行路径真正只看到 `o_i`。
- **奖励塑形警告。** MARL 对奖励设计极其敏感。塑形中有一个协调 bug，智能体就会学会利用它。运行对抗性测试。
- **对于 LLM 智能体**，首先考虑提示词层面的策略。只有当交互数据 + 奖励信号 + 基础设施都具备时，才投资 MARL 训练。

## 练习

1. 运行 `code/main.py`。测量独立智能体和 MAPPO 风格智能体之间的步数差距。在 6×6 网格上差距是增大还是缩小？
2. 实现竞争变体：两个智能体，一个物品，只有第一个到达的获得奖励。哪种模式能干净地处理竞争？历史上是 MADDPG。
3. 阅读 MADDPG（arXiv:1706.02275）第 3 节。用你自己的话将精确的 critic 更新规则以伪代码象征性地实现。
4. 阅读 MAPPO（arXiv:2103.01955）。作者为什么认为集中式价值 + PPO 在他们的基准上优于离策略 MARL？列出三个最有力的主张。
5. 将 CTDE 作为设计模式应用于一个假想的 LLM 智能体系统（例如，研究智能体 + 摘要者 + 程序员）。设计时可用但运行时不可用的联合信息是什么？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| MARL | "多智能体 RL" | 多智能体系统的强化学习。 |
| CTDE | "集中式训练，去中心化执行" | 用全局信息训练；用本地策略部署。 |
| MADDPG | "多智能体 DDPG" | 带有看到所有观察 + 行动的每智能体 critic 的 CTDE。 |
| QMIX | "价值分解" | 每智能体 Q 值的单调混合。合作式。 |
| MAPPO | "多智能体 PPO" | 带有集中式价值函数的 PPO。2026 年默认基线。 |
| Value decomposition（价值分解） | "个体 Q 的加和" | 联合 Q 表示为每智能体 Q 的单调函数。 |
| Non-stationarity（非平稳性） | "移动的目标" | 随着其他智能体学习，每个智能体的环境都在变化。MARL 的核心问题。 |
| On-policy / off-policy（在策略/离策略） | "从当前/回放中学习" | PPO 是在策略（MAPPO）；DDPG 和 Q 学习是离策略。 |
| SMAC | "星际争霸多智能体挑战" | 合作式微操基准；QMIX 的主场。 |
