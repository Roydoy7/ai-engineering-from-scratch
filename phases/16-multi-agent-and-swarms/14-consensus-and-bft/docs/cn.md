# 智能体共识与拜占庭容错（Consensus and Byzantine Fault Tolerance for Agents）

> 经典分布式系统 BFT 遭遇随机性 LLM。2025-2026 年间，三个研究方向浮现：**CP-WBFT**（arXiv:2511.10400）通过置信度探针为每票加权；**DecentLLMs**（arXiv:2507.14928）采用无领导者架构，结合并行工作者提案和几何中位数聚合；**WBFT**（arXiv:2505.05103）将加权投票与层次结构聚类相结合，将节点分为核心节点和边缘节点。《AI 智能体能达成共识吗？》（arXiv:2603.01213）给出了诚实的实证结果：即便是标量一致性，在今天也很脆弱——单个欺骗性智能体就能破坏整个智能体混合体的共识。BFT 是必要的，但还不够。本课构建一个最小化的 BFT 协议，注入三种智能体特定攻击（拜占庭撒谎、谄媚服从、相关错误单一文化），并测量每种共识变体的应对效果。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** Phase 16 · 07（心智社会与辩论）、Phase 16 · 13（共享记忆）  
**预计时间：** 约 75 分钟

## 问题所在

你有 N 个 LLM 智能体，每个都产出一个答案。它们意见不一。多数投票选出了错误答案，因为两个智能体是相关的（相同的基础模型、相同的训练数据、相同的失效模式）。第三个智能体碰巧以一种新颖的方式犯了错——于是多数派是一个虚假的多数派。

现在加入一个欺骗性智能体：它故意撒谎。或者加入一个谄媚性智能体：它同意最后发言的人。在经典 BFT 中，假设拜占庭节点是 `f < n/3` 的一部分，行为方式任意。2026 年的现实是：LLM 节点即便在诚实的情况下也是随机的，在各模型之间存在相关性，并受到彼此输出的影响。你无法将它们视为独立的伯努利投票者。

经典 BFT（PBFT，1999 年）并没有错——只是不完整。它处理任意的位翻转，但不处理"三个诚实的智能体因为共享训练数据而共享一个幻觉"的情况。本课从 PBFT 的基础出发，在此之上叠加三种 2025-2026 年的改进。

## 核心概念

### 经典 BFT 给你什么

实用拜占庭容错（Castro & Liskov，OSDI 1999）能容忍 `f < n/3` 的拜占庭节点。该协议有三个阶段（预准备、准备、提交）和两个原语（签名消息、法定人数证书）。在 `n >= 3f + 1` 个诚实或恶意节点中就单一值达成一致。

保证很强，但假设前提是：

1. **故障独立。** 拜占庭节点不协调。
2. **诚实节点真的诚实。** 诚实输出的正确性不是问题；协议只是对齐分歧。
3. **问题有基准真相答案。** 在错误事实上达成共识仍然是共识。

LLM 智能体违反了这三个假设。运行同一基础模型的两个智能体共享故障。"诚实的" LLM 仍然会产生幻觉。对于模糊的问题，"真相"就是智能体决定的——没有外部神谕。

### 三种 LLM 特定攻击

**拜占庭撒谎。** 一个智能体故意输出错误答案。经典 BFT 在 `f < n/3` 时能处理这种情况。

**谄媚服从。** 一个智能体在投票前阅读其他人的答案，并与最后发言者保持一致。不是恶意的，但与最大声的声音相关。经典 BFT 无法防止这种情况，因为该智能体通过了每一次签名检查。

**相关错误单一文化。** 三个智能体共享同一个基础模型。它们幻觉出相同的错误答案。多数派是错误的。经典 BFT 无法提供帮助，因为这三个智能体都在"诚实地"一致。

### 2025-2026 年的应对

**CP-WBFT**（arXiv:2511.10400）——置信度探针加权 BFT。每个投票者在答案上附加一个置信度探针（自我报告的概率，或单独校准模型的预测）。投票权重随置信度缩放。报告在完全图上 BFT 改善了 +85.71%。缓解措施针对：谄媚服从（服从性智能体在其主动提出的立场上置信度往往较低）。

**DecentLLMs**（arXiv:2507.14928）——无领导者。工作者智能体并行提案，评估者智能体对提案评分，最终答案是评分位置的几何中位数。在 `f < n/2` 时具有鲁棒性。缓解措施针对：拜占庭撒谎和相关错误（几何中位数对离群值具有鲁棒性，拉向密集集群，而不是模型偏向的平均值）。

**WBFT**（arXiv:2505.05103）——带层次结构聚类的加权 BFT。投票权重由响应质量加上从历史中学习的信任分数来分配。将智能体分为核心节点和边缘节点；核心节点必须先达成共识，边缘节点随后跟进。缓解措施针对：可扩展性（核心共识规模小且速度快）以及部分针对单一文化（核心节点可以被选择为多样化）。

### 实证研究：《AI 智能体能达成共识吗？》（arXiv:2603.01213）

该论文在多个前沿模型中测量标量一致性（LLM 智能体就单一数值达成一致）。发现令人不安：

- 即使没有对手，LLM 智能体在许多基准测试中的标量问题上不一致率也超过 30%。
- 一个采用欺骗性角色的单一智能体可以将智能体混合体的共识从诚实基线拉偏 40 多个百分点。
- 不一致率与模型多样性相关——异质集成的不一致程度超过同质集成（好：不相关错误），但达成一致的速度也更慢（坏：达成一致的时间更长）。

关键结论：BFT 给你提供了对齐输出的机制，但它不能告诉你对齐后的输出是否正确。与验证（Phase 16 · 08 角色专业化）、多样性（Phase 16 · 15 辩论变体）和评估者智能体（Phase 16 · 24 基准测试）相结合。

### 精简后的核心协议

LLM 智能体的最小化 BFT 轮次：

```
1. 任务到达；每个智能体 i 产出答案 a_i
2. 每个智能体附加置信度探针 c_i 在 [0, 1] 内
3. 聚合者从所有 n 个智能体收集 (a_i, c_i)
4. 聚合者按语义集群分组（等价答案）
5. 聚合者计算每个集群 C 的权重：
     w(C) = sum_{i in C} c_i
6. 胜者 = 权重最大的集群，如果 max > threshold * sum(c_i)
   否则：重试或上升级别
7. 少数集群与来源一起记录，供事后审计
```

语义聚类步骤是 LLM 特定的改动。"研究报告的 4.2%" 和"4.2% 的改进"是同一个集群。朴素的字符串相等检查会错过这一点。在生产中，使用廉价的嵌入模型或显式规范化。

### 阈值调节

`threshold` 参数决定何时接受，何时重试。太低：你接受弱多数。太高：你永远不接受任何东西。实证范围：对于 `n=5-7` 个智能体，0.5-0.67；对于更小的 `n`，更高。低于阈值时，升级到人类或不同的智能体集成。

### 共识无法提供帮助的场景

- **模糊问题。** 如果问题没有基准真相，共识就是一种意见。应该如实说明。
- **复合问题。** "写代码并解释它"——两个答案。分别对每个进行投票。
- **对抗性多轮。** 如果智能体能观察先前的轮次并模仿（Du 2023 辩论），它们会开始无论真相如何都相互同意。限制轮次（通常 2-3 轮）。

## 构建它

`code/main.py` 实现了：

- `AgentVoter` — 带有（答案，置信度）的脚本化策略。
- `MajorityVote` — 经典多数票。
- `CPWBFT` — 带语义聚类的置信度加权投票。
- `DecentLLMs` — 对评分提案进行几何中位数聚合。
- `Scenario` — 在三种攻击模式下运行每种聚合器。

实现的攻击模式：

1. `byzantine`：一个智能体以高置信度撒谎。
2. `sycophancy`：一个智能体复制它看到的第一个答案，并匹配置信度。
3. `monoculture`：三个智能体以中等置信度共享一个错误答案（相关错误）。

运行：

```
python3 code/main.py
```

预期输出：一个（攻击，聚合器）→ 最终答案的表格，正确答案高亮显示。多数票在单一文化案例中失败。CPWBFT 的置信度加权缓解了谄媚服从。DecentLLMs 的几何中位数在单一文化人口少于一半时拉向诚实集群。

## 使用它

`outputs/skill-consensus-designer.md` 为多智能体集成设计共识协议：聚类方法、加权方式、阈值，以及对低于阈值的轮次的升级策略。

## 交付它

在发布任何共识机制之前：

- **至少用上面三种攻击模式进行测试。** 你的协议应该可预测地失败，而不是静默地失败。
- **记录每个少数集群**及其来源。少数集群是你对相关错误的早期预警系统。
- **强制执行有界轮次。** 不要"持续辩论直到达成一致"——那会奖励谄媚性。
- **将一致性与正确性分离。** 共识输出交给验证者；验证者独立于集成之外。
- **监控一致率。** 急剧上升意味着服从偏差；急剧下降意味着模型漂移。

## 练习

1. 运行 `code/main.py`。确认多数票在单一文化攻击中失败，但当单一文化置信度低于 0.7 时，CPWBFT 能部分缓解。
2. 添加第四种攻击模式：**沉默弃权**——一个智能体拒绝回答（"我不知道"）。每种聚合器应如何处理弃权？实现你的选择。
3. 将语义聚类从字符串规范化换成嵌入相似度（使用任何开源嵌入模型）。对谄媚服从攻击会发生什么？
4. 阅读 CP-WBFT（arXiv:2511.10400）。实现置信度探针校准步骤（一个单独的校准模型检查每个智能体自我报告的置信度）。测量在单一文化场景中的准确率提升。
5. 阅读《AI 智能体能达成共识吗？》（arXiv:2603.01213）。复现一个简化的标量一致性实验：三个智能体、一个标量问题、欺骗性角色提示词。CPWBFT 或 DecentLLMs 能捕获它吗？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| BFT | "拜占庭容错" | Castro-Liskov 1999 年协议，用于在 `f < n/3` 的任意故障下达成共识。 |
| Byzantine（拜占庭） | "任何坏行为" | 一个可以撒谎、丢消息、静默失败的节点——除了安全崩溃之外的一切。 |
| Confidence probe（置信度探针） | "你有多确定？" | 附加到投票上的自我报告或校准器预测的概率。 |
| Semantic clustering（语义聚类） | "同一答案，不同措辞" | 在计票前对等价答案进行分组。 |
| Geometric median（几何中位数） | "鲁棒中心" | 最小化到样本点距离之和的点。对离群值具有鲁棒性，不像均值那样容易被影响。 |
| Monoculture（单一文化） | "相同的模型，相同的失败" | 当智能体共享训练数据或基础模型时产生的相关错误。 |
| Sycophantic conformity（谄媚服从） | "同意大声的声音" | 一个智能体的投票偏向第一个/最大声发言的人。 |
| Core/Edge（核心/边缘） | "层次化 BFT" | WBFT 的分割：先完成小型核心共识，边缘节点随后跟进。限制延迟。 |
