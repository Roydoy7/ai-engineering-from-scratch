# FIPA-ACL 的遗产与言语行为（Heritage of FIPA-ACL and Speech Acts）

> 在 MCP 之前，在 A2A 之前，有 FIPA-ACL。2000 年，IEEE 智能物理智能体基金会批准了一种包含二十个语用行为、两种内容语言和一套交互协议（合同网、订阅/通知、请求-当）的智能体通信语言。它从工业界淡出，因为本体论开销对 Web 来说太重，但 LLM 驱动的多智能体系统的复兴正在悄悄重新实现相同的想法——只是没有正式语义：JSON 契约代替语用行为，自然语言代替本体论。本课认真阅读 FIPA-ACL，这样你就能看出哪些 2026 年的协议决策是重新发明，哪些是新颖之处，以及当前浪潮将在哪里重新发现 2000 年代已经解决的问题。

**类型：** 学习  
**语言：** Python（标准库）  
**前置知识：** Phase 16 · 01（为什么需要多智能体）  
**预计时间：** 约 60 分钟

## 问题所在

2026 年的智能体协议格局很繁忙：工具用 MCP，智能体用 A2A，企业审计用 ACP，去中心化信任用 ANP，自然语言内容用 NLIP，还有 CA-MCP 和几十个研究提案。每个规范都宣称自己是基础性的。

诚实的解读是，它们中的大多数都在重新发现一棵非常具体的二十年前的决策树。奥斯汀（1962）和塞尔（1969）的言语行为理论给了我们"话语就是行动"。KQML（1993）将其转化为线路协议。FIPA-ACL（2000 年批准）产生了参考标准化：二十个语用行为、内容语言 SL0/SL1、合同网和订阅-通知的交互协议。JADE 和 JACK 是 Java 参考平台。这项努力在 2010 年左右消退，因为本体论开销太重而 Web 赢得了胜利。

当你看 MCP 的 `tools/call`、A2A 的任务生命周期或 CA-MCP 的共享上下文存储时，你看到的是 FIPA 决策的更软化、JSON 原生的翻版。了解这一遗产告诉你两件事：哪些新"创新"实际上是重新发明，以及旧的失败模式将在哪些地方被新规范重新发现。

## 核心概念

### 言语行为，一段话

奥斯汀注意到有些句子不是描述世界——而是改变世界。"我承诺。""我请求。""我宣告。"他称这些为语用行为。塞尔将五个类别形式化：断言性、指示性、承诺性、表达性、宣告性。KQML（Finin 等，1993）使这对软件智能体变得可操作：消息是语用行为（动作）加内容（动作涉及的内容）。FIPA-ACL 清理了 KQML 的不足，并围绕二十个语用行为进行了标准化。

### 二十个 FIPA 语用行为（部分列表）

| 语用行为 | 意图 |
|---------|------|
| `inform` | "我告诉你 P 是真的" |
| `request` | "我请求你做 X" |
| `query-if` | "P 是真的吗？" |
| `query-ref` | "X 的值是什么？" |
| `propose` | "我提议我们做 X" |
| `accept-proposal` | "我接受提议" |
| `reject-proposal` | "我拒绝提议" |
| `agree` | "我同意做 X" |
| `refuse` | "我拒绝做 X" |
| `confirm` | "我确认 P 是真的" |
| `disconfirm` | "我否认 P" |
| `not-understood` | "你的消息无法解析" |
| `cfp` | "征求 X 的提案" |
| `subscribe` | "当 X 变化时通知我" |
| `cancel` | "取消正在进行的 X" |
| `failure` | "我尝试了 X 但失败了" |

完整列表在 `fipa00037.pdf`（FIPA ACL 消息结构）中。重点不是记住它——重点是这些每一个都对应于 LLM 协议最终会重新添加的一个原语。

### 标准 FIPA-ACL 消息

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

七个字段承载协议信封；一个字段（`content`）承载有效载荷。其余字段正是每次你将重试、线程和本体论附加到 JSON 协议时重新发明的内容。

### 两个遗留平台

**JADE**（Java 智能体开发框架，1999-2020s）是使用最广泛的 FIPA 兼容运行时。智能体扩展基类，交换 ACL 消息，在容器内运行，并使用"行为"进行协调。交互协议库提供了合同网、订阅-通知、请求-当和提议-接受。

**JACK**（面向智能体的软件，商业）在 FIPA 消息之上强调 BDI（信念-愿望-意图）推理。更正式，采用较少。

一旦 Web 栈吃掉了多智能体使用案例，两者都衰落了。MCP 和 A2A 是 2026 年的运行时"容器"。

### 为什么 FIPA 消退了

- **本体论开销。** FIPA 需要共享本体论来解析 `content`。就本体论达成一致是一个多年的标准化过程。Web 只使用 HTTP + JSON。
- **没人使用的形式语义。** SL（语义语言）给出了严格的真值条件，但大多数生产系统使用自由形式内容并忽略了形式主义。
- **工具锁定。** JADE 只支持 Java；JACK 是商业的。多语言团队绕开了两者。
- **互联网赢得了栈。** REST，然后 JSON-RPC，然后 gRPC 取代了 ACL 的传输。

### LLM 复兴是精简版 FIPA

将 FIPA `request` 与 MCP `tools/call` 比较：

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

相同的信封，不同的语法。两者都携带：谁、对谁、意图、有效载荷、关联 id。两者都不是对另一方的革命——它们是对同一设计的不同权衡。

Liu 等（"智能体互操作协议调查：MCP、ACP、A2A、ANP"，arXiv:2505.02279）的 2025 年调查明确了这一谱系：MCP 对应工具使用言语行为，A2A 对应智能体对等言语行为，ACP 对应审计轨迹言语行为，ANP 对应去中心化身份扩展。新规范是带 JSON 语法和更宽松语义的 ACL 后代。

### 权衡，明确陈述

**FIPA 给你而现代规范丢弃的：**

- 形式语义——你可以证明 `inform` 意味着发送者相信内容。
- 语用行为的标准目录——你不必重新争论"我们应该有 `cancel` 吗？"。
- 几十年的交互协议模式——合同网、订阅-通知、提议-接受——具有已知的正确性属性。

**现代规范给你而 FIPA 没有的：**

- 与每个现代工具兼容的 JSON 原生有效载荷。
- LLM 无需手工编写本体论即可解释的自然语言内容。
- Web 栈传输（HTTP、SSE、WebSocket）。
- 通过自描述文档的能力发现（MCP `listTools`、A2A 智能体卡）。

更宽松的意图语义以便更容易实现。这正是确切的权衡。

### 值得迁移的交互协议

FIPA 提供了约 15 种交互协议。三种值得引入 LLM 多智能体系统：

1. **合同网协议（CNP）。** 管理者发出 `cfp`（征求提案）；竞标者以 `propose` 响应；管理者接受/拒绝。这是标准的任务市场模式（Phase 16 · 16 谈判）。
2. **订阅/通知。** 订阅者发送 `subscribe`；发布者在主题变化时发送 `inform`。这是 2026 年的每条事件总线。
3. **请求-当。** "当条件 Y 成立时做 X。"带前提条件的延迟动作。2026 年的类比是耐久工作流引擎中的延迟任务（Phase 16 · 22 生产扩展）。

每种都干净地映射到现代消息队列、HTTP + 轮询或 SSE 流。

### 丢弃本体论时会出什么问题

没有共享本体论，智能体从自然语言内容推断含义。有据可查的 2026 年失败模式是**语义漂移**：两个智能体对同一个词（`"customer"`）使用微妙不同的概念，接收者的智能体根据错误的解释行动，没有模式验证器捕获它。FIPA 的本体论要求本会在解析时拒绝消息。

在不完全本体论的情况下的缓解措施：

- `content` 上的 JSON Schema——在线路层拒绝结构性错误。
- 类型化工件（A2A）——拒绝错误的模式。
- 信封中的明确语用行为——即使在内容是自然语言时也使意图明确。

### 2026 年的规范，映射到言语行为遗产

| 现代规范 | FIPA 类比 | 保留的内容 | 丢弃的内容 |
|---------|----------|-----------|-----------|
| MCP `tools/call` | `request` | 明确意图、关联 id | 形式语义、本体论 |
| MCP `resources/read` | `query-ref` | 明确意图、关联 id | 形式语义 |
| A2A 任务生命周期 | 合同网 + 请求-当 | 异步生命周期、状态转换 | 形式完整性保证 |
| A2A 流事件 | 订阅/通知 | 异步推送 | 类型谓词订阅 |
| CA-MCP 共享上下文 | 黑板（Hayes-Roth 1985） | 多写者共享内存 | 逻辑一致性模型 |
| NLIP | 自然语言内容 | LLM 原生 | 模式 |

从上到下阅读表格，模式是：保留结构原语，丢弃形式主义，让 LLM 覆盖歧义。

## 构建它

`code/main.py` 实现了一个纯标准库 FIPA-ACL 转换器。它对标准 ACL 信封进行编码和解码，并展示每个 MCP/A2A 消息形状如何还原为相同的七个字段。演示：

- 将五个 MCP 风格和 A2A 风格的消息编码为 FIPA-ACL。
- 将 FIPA-ACL 解码回现代等价物。
- 使用 `cfp`、`propose`、`accept-proposal`、`reject-proposal` 在一个管理者和三个竞标者之间运行一个玩具合同网谈判。

运行：

```
python3 code/main.py
```

输出是一个并排跟踪，显示每个现代消息的 2026 年 JSON 形式和 FIPA-ACL 形式，然后是合同网竞标的往返。相同的协议原语在往返中保留；只有语法不同。

## 使用它

`outputs/skill-fipa-mapper.md` 是一个读取任何智能体协议规范并产生 FIPA-ACL 映射的技能。在采用新协议之前使用它来回答："这是真正的新东西，还是带 JSON 语法的 `inform`？"

## 交付它

不要把 FIPA-ACL 带回来。把它的清单带回来：

- 每条消息的意图原语（语用行为）是什么？
- 是否有用于请求-响应和取消的关联 id？
- 是否有明确的内容语言（JSON-RPC、纯文本、结构化类型工件）？
- 交互协议是一等的吗，还是你从头重新实现合同网？
- 当两个智能体对内容含义有分歧时（语义漂移）会发生什么？

在将任何新协议发布到生产之前，记录这五个问题。

## 练习

1. 运行 `code/main.py`。观察往返编码。识别哪个 FIPA 语用行为对应于 `tools/call`、`resources/read` 和 A2A 任务创建。
2. 用 `cancel` 语用行为扩展合同网演示，让管理者在竞标中途撤回任务。`cancel` 解决了单独重试无法解决的什么失败案例？
3. 阅读 FIPA ACL 消息结构（http://www.fipa.org/specs/fipa00037/）第 4.1-4.3 节。选择本课未涵盖的一个语用行为，并描述其现代 JSON-RPC 类比。
4. 阅读 Liu 等，arXiv:2505.02279。对于 MCP、A2A、ACP、ANP 中的每一个，列出它们保留和丢弃的 FIPA 语用行为家族。
5. 在你自己的系统中为 `request` 语用行为的 `content` 字段设计一个最小 JSON-Schema。该模式给你提供了纯自然语言没有的什么，代价是什么？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Speech act（言语行为） | "做某事的话语" | 奥斯汀/塞尔：话语作为行动。ACL 的理论父本。 |
| FIPA | "那个旧 XML 东西" | IEEE 智能物理智能体基金会。2000 年标准化了 ACL。 |
| ACL | "智能体通信语言" | FIPA 的信封格式：语用行为 + 内容 + 元数据。 |
| Performative（语用行为） | "动词" | 消息的意图类：`inform`、`request`、`propose`、`cfp` 等。 |
| KQML | "FIPA 的前身" | 知识查询和操作语言（1993）。更简单，更窄。 |
| Ontology（本体论） | "共享词汇" | 内容语言讨论的概念的形式定义。 |
| SL0 / SL1 | "FIPA 内容语言" | 语义语言级别 0 和 1——正式内容语言家族。 |
| Contract Net（合同网） | "任务市场" | 管理者发出 cfp；竞标者提议；管理者接受。标准交互协议。 |
| Interaction protocol（交互协议） | "消息模式" | 具有已知正确性的语用行为序列：请求-当、订阅-通知等。 |
