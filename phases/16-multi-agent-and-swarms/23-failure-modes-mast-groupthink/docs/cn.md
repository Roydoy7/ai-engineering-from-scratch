# 故障模式——MAST、群体思维、单一文化与级联错误（Failure Modes — MAST, Groupthink, Monoculture, Cascading Errors）

> 2026 年的参考分类体系是 **MAST**（Cemri 等人，NeurIPS 2025，arXiv:2503.13657），源自对 7 个最先进开源多智能体系统的 1642 条执行轨迹分析，显示**故障率高达 41-86.7%**。三大根本类别：**规格问题**（41.77%）——角色歧义、任务定义不清；**协调失败**（36.94%）——通信中断、状态不同步；**验证缺口**（21.30%）——缺失验证、无质量检查。**群体思维**系列（arXiv:2508.05687）补充了：单一文化崩溃（相同基础模型 → 相关错误）、从众偏见（智能体相互强化彼此的错误）、心智理论缺陷、混合动机动态、级联可靠性故障。级联示例：支付失败引发订单重试，订单重试触发库存重试，库存服务因 10 倍负载在数秒内崩溃——需要熔断器。记忆污染：一个智能体的幻觉进入共享记忆，下游智能体将其视为事实；准确度逐渐衰减，根因诊断极为痛苦。**STRATUS**（NeurIPS 2025）报告通过专门的检测/诊断/验证智能体实现了 1.5 倍的缓解成功率提升。本课将故障模式作为一等工程目标来处理。

## 问题所在

多智能体系统在真实任务上的故障率高达 41-86.7%（Cemri 等人 2025 年对 7 个开源多智能体系统进行了实测）。这个问题无法靠"再加几个智能体"来解决。故障有其结构性原因。MAST 分类体系提供了分类框架。本课将每个类别映射到具体的检测、诊断和缓解模式，让这些数字不再看起来随机。

2026 年的生产实践是将故障模式作为设计输入。你的架构在能够指出每个 MAST 类别并说出你部署的缓解措施之前，都不算"足够好"。

## 核心概念

### MAST 类别

**规格问题（41.77% 的故障）。** 智能体的任务定义不够严谨。示例：

- 角色歧义：两个智能体都认为自己是审查者。
- 任务描述不足："总结这个"，而用户想要的是特定视角。
- 成功标准隐含：智能体无法判断自己是否成功。

缓解措施：
- 编写明确的角色契约。每个智能体的提示词说明它做什么，*以及它不做什么*。
- 每个任务配备验收测试。在智能体启动之前，定义"完成看起来是 X"。
- 预检规格检查：一个单独的智能体在派发之前审查任务定义。

**协调失败（36.94%）。** 通信或状态故障。

示例：
- 两个智能体在没有同步的情况下更新共享状态。
- 智能体之间的消息丢失（队列故障、超时）。
- 状态漂移：智能体 A 认为任务已完成；智能体 B 还在执行中。

缓解措施：
- 带乐观并发的版本化共享状态。
- 关键消息的显式确认（重试直到确认）。
- 定期状态同步检查点；及早检测漂移。

**验证缺口（21.30%）。** 没有对输出进行独立检查。

示例：
- 一个智能体声称成功；没有人验证。
- 链式智能体，每个都信任前一个的输出。
- 对涌现的组合行为缺少测试覆盖。

缓解措施：
- 独立验证者智能体（第 13 课）。只读，独立的来源访问。
- 显式的交接契约："A 的输出必须通过检查器 C，B 才能开始。"
- 结果日志，用于事后分析。

### 群体思维系列（arXiv:2508.05687）

当智能体同质化或相互模仿时出现的五种相关故障：

**单一文化崩溃（Monoculture collapse）。** 相同的基础模型或训练数据 → 相关错误。当三个智能体共用一个 LLM 时，它们共享其幻觉。

**从众偏见（Conformity bias）。** 智能体向最响亮或最自信的同伴靠拢，即使对方是错的。

**心智理论缺陷（Deficient ToM）。** 智能体无法对彼此的信念建模；协调崩溃（第 18 课）。

**混合动机动态（Mixed-motive dynamics）。** 激励部分对齐的智能体会漂向让所有人都不满意的折中中间值。

**级联可靠性故障（Cascading reliability failures）。** 一个组件的错误模式触发了依赖组件的错误模式。

### 级联示例——重试风暴

2026 年的经典故障模式：

```
支付服务 10% 的请求失败
   ↓
订单智能体重试支付（指数退避但处理粗糙）
   ↓
每次重试都是一次新的订单-库存检查
   ↓
库存服务看到 2 倍正常负载
   ↓
库存服务开始超时
   ↓
每个订单都重试库存检查
   ↓
库存服务看到 10 倍正常负载
   ↓
集群崩溃
```

修复是经典方案：**熔断器**。当下游错误率超过阈值时，用缓存或默认结果短路。再加上每个请求的有限重试预算。

熔断器是少数几个可以直接从分布式系统借用而无需修改的多智能体故障缓解措施之一。

### 记忆污染（回顾）

来自第 13 课：一个智能体的幻觉成为共享记忆中的事实；下游智能体基于被污染的事实进行推理。用 MAST 的术语来说，这是共享记忆层的验证缺口。

逐渐的准确度衰减是症状。系统不会崩溃；你会看到缓慢的漂移，根因诊断极为痛苦。

缓解措施：追加日志、溯源、不可写的验证者。第 13 课已经介绍过。

### STRATUS——用于故障检测的专门智能体

STRATUS（NeurIPS 2025）报告，当你部署以下方案时，缓解成功率提升 1.5 倍：

- **检测智能体。** 监视症状模式（高不一致性、重试峰值、准确度漂移）。
- **诊断智能体。** 根据症状，从 MAST 分类体系推断可能的根因。
- **验证智能体。** 应用缓解措施后，检查症状是否消除。

这是 SRE 风格的事件响应，应用于智能体系统。三种角色都可以是带有专门提示词的 LLM 智能体。

### 故障模式审计

2026 年的最佳实践是每年（或每个主要版本）进行一次故障模式审计：

1. **轨迹采样。** 收集约 1000 条真实执行轨迹。
2. **分类。** 对每条轨迹的故障，映射到 MAST + 群体思维类别。
3. **计算按类别的故障率。** 哪些类别在你的系统中占主导地位？
4. **缓解措施排名。** 哪种修复能消除最多故障？
5. **选择 2-3 项缓解措施。** 实施；下个季度重新审计。

这种规范比具体选择更重要。没有审计，故障会融入噪音中，永远无法得到系统性的处理。

### 当系统静默失败时

最危险的故障类别是静默的正确性故障。响亮地失败的系统（崩溃、异常、告警）可以被监控。产生貌似合理但错误输出的系统无法通过异常日志检测到。这就是为什么验证缺口是每次故障成本最高的类别，尽管按数量计算只占 21.30%。

投资于：
- 基于采样的人工审查。
- 黄金数据集回归测试。
- 对重要输出进行跨智能体交叉检验。

### 立即故障与缓慢故障

有些故障是即时的；有些是缓慢的。即时故障（超时、schema 不匹配、认证错误）检测成本低。缓慢故障（记忆污染、单一文化漂移、角色歧义）检测和预防成本高。

2026 年的工程方向：对缓慢故障的代理指标进行监控，从而在漂移成为可见错误之前就能捕获。一致率、重试率、输出长度分布，以及连续智能体版本之间的编辑距离，都是有用的代理指标。

## 构建它

`code/main.py` 实现了：

- `FailureTaxonomy` — 将模拟的事件分类到 MAST + 群体思维类别。
- `CircuitBreaker` — 经典模式；当错误率超过阈值时断开。
- `RetryStormSimulator` — 展示级联故障；开关熔断器进行对比。
- `DetectionAgent` — 脚本化的 STRATUS 风格症状匹配器。

运行：

```
python3 code/main.py
```

预期输出：
- 无熔断器的重试风暴：库存错误爆炸式增长（模拟）。
- 有熔断器：在阈值处截断；提供降级模式响应。
- 检测智能体标记出该模式并命名 MAST 类别。

## 使用它

`outputs/skill-mast-auditor.md` 对多智能体系统运行 MAST 风格的故障模式审计。轨迹 → 分类 → 缓解排名。

## 交付它

生产中的故障模式规范：

- **每季度进行 MAST 审计。** 不是每年。随着系统增长，类别会发生变化。
- **到处部署熔断器。** 对任何依赖服务的每个出站调用都要部署。默认开断阈值设为 5-10% 错误率。
- **黄金数据集。** 小而高质量、经过人工审计的数据集。每周进行回归测试。
- **STRATUS 三元组。** 检测 + 诊断 + 验证智能体监控生产环境。先只部署检测智能体；当症状出现噪音时再添加诊断智能体。
- **故障预算。** 按类别设定故障率的显式 SLO。超出预算触发停止发布的讨论。

## 练习

1. 运行 `code/main.py`。确认熔断器能够截断重试风暴。改变故障阈值并观察权衡。
2. 实现一个**缓慢故障代理**：3 个并行智能体的一致率。当它急剧下降时，触发告警。通过逐渐关联智能体输出来模拟单一文化漂移。
3. 阅读 Cemri 等人（arXiv:2503.13657）。选择他们 7 个多智能体系统中的一个，映射其前 3 个故障类别。这与 MAST 的预测相比如何？
4. 阅读群体思维论文（arXiv:2508.05687）。识别五种模式中哪一种在生产中最难检测。提出一个代理指标。
5. 为你熟悉的某个特定多智能体系统设计一个 STRATUS 风格的检测-诊断-验证三元组。检测智能体监视哪些症状？诊断智能体推荐哪些缓解措施？验证智能体如何确认它们有效？

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| MAST | "2026 年的分类体系" | Cemri 2025；3 个根本类别 + 14 种子故障类型。 |
| Specification Problem（规格问题） | "角色歧义" | 任务或角色定义不足；智能体不知道该做什么。 |
| Coordination Failure（协调失败） | "状态漂移" | 智能体之间的通信或同步故障。 |
| Verification Gap（验证缺口） | "没有人检查" | 输出在没有独立验证的情况下被接受。 |
| Groupthink family（群体思维系列） | "同质化故障" | 单一文化、从众、心智理论缺陷、混合动机、级联。 |
| Monoculture collapse（单一文化崩溃） | "相同模型，相同幻觉" | 来自共享基础模型或训练数据的相关错误。 |
| Retry storm（重试风暴） | "级联错误放大" | 一次故障触发重试，进而放大下游负载。 |
| Circuit breaker（熔断器） | "错误率时快速失败" | 当错误率超过阈值时断开；用默认值短路。 |
| STRATUS | "事件响应三元组" | 检测 + 诊断 + 验证智能体。1.5 倍缓解成功率。 |
| Memory poisoning（记忆污染） | "幻觉传播" | 共享记忆事实被污染；下游智能体基于毒化内容推理。 |
