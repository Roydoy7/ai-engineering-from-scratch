# AI Scientist v2——研讨会级别的自主研究（AI Scientist v2 — Workshop-Level Autonomous Research）

> Sakana 的 AI Scientist v2（Yamada 等，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、写作、提交。它是第一个让生成的论文在 ICLR 2025 研讨会通过同行评审的系统。独立评估（Beel 等）发现 42% 的实验因编码错误而失败，文献综述经常将已有概念错误标记为新颖。Sakana 自己的文档警告代码库会执行 LLM 生成的代码，并建议 Docker 隔离。这幅图像的两半都是重点。

**类型：** 学习  
**语言：** Python（标准库，研究循环状态机玩具）  
**前置知识：** Phase 15 · 03（AlphaEvolve）、Phase 15 · 04（DGM）  
**预计时间：** 约 60 分钟

## 问题所在

研究是一个开放式任务。与 AlphaEvolve 的算法搜索或 DGM 以基准为边界的自我修改不同，研究结果没有机器可检查的正确性标准。论文由审查者而非单元测试来评判。这使得循环更难关闭——如果能关闭的话也更有价值，因为研究是复利进步所在。

AI Scientist v1（Sakana，2024）通过从人类编写的模板开始关闭了循环。LLM 在固定脚手架内填充实验。AI Scientist v2（Yamada 等，2025）通过使用带有视觉语言模型批评循环的主动式树搜索删除了模板要求。该系统生成想法、实现实验、生成图表、撰写论文，并对审查者反馈进行迭代。

同行评审判决：一篇 v2 生成的论文在 ICLR 2025 研讨会被接受（附有披露）。独立评估判决：该系统远非可靠。两者都是真的。

## 核心概念

### 架构

1. **想法生成。** LLM 以主题和先前文献为条件提出研究想法。v1 使用模板；v2 在假设空间上使用主动式搜索。
2. **新颖性检查。** 文献检索步骤检查想法是否已发表。这是 Beel 等人评估发现错误标记的步骤——已有方法经常被归类为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败被反馈到重试循环中。在 Beel 等人的测量中，42% 的实验在此阶段因编码错误而失败。
5. **图表生成。** 视觉语言模型读取生成的图表并为了清晰度重写它们。这是 v2 的关键技术补充。
6. **写作。** LLM 起草论文，与内部审查者迭代。
7. **可选：提交。** 论文提交到会议。

### 研讨会接受结果意味着什么

一篇 v2 生成的论文在 ICLR 2025 研讨会通过了同行评审。作者向项目委员会披露了论文的来源。这次接受是一个数据点；它不是声称系统"做研究"的许可证。

重要背景：研讨会论文的门槛低于主会议论文。同行评审是嘈杂的；任何给定日期的一小部分提交被接受。一次成功是概念证明，而非可靠性声明。2026 年 Nature 论文记录了端到端循环，本身是由人类研究者共同撰写的；这不是"系统写了一篇 Nature 论文"。

### 独立评估发现了什么

Beel 等人（arXiv:2502.14297）进行了外部评估。主要发现：

- **实验失败。** 42% 的实验因编码错误（错误导入、形状不匹配、未定义变量）而失败。重试循环捕获了一些，但不是全部。
- **新颖性错误标记。** 文献检索步骤经常将已有概念标记为新颖。这是研究中的幻觉等价物。
- **呈现质量差距。** 视觉语言图表批评生成了发布级别的视觉效果，掩盖了底层实验的弱点。

最后一个发现对本阶段最重要。一个产生令人信服输出而不做令人信服研究的系统比明显失败的系统更危险，而非更安全。评估必须到达底层声明，而不是停在图表上。

### 沙箱逃逸问题

Sakana 自己的仓库 README 警告：

> 由于该软件的性质，它执行 LLM 生成的代码，我们无法保证安全。存在危险包、不受控的网络访问和产生非预期进程的风险。使用风险自负，考虑 Docker 隔离。

这是未验证领域自主性的操作形态。LLM 写代码；代码运行；代码可以做进程被允许做的任何事情。没有硬性限制文件系统、网络和进程动作的沙箱，任何自主研究智能体都可以泄露数据、消耗计算或重写自身。

AlphaEvolve 的沙箱情况更容易，因为其评估器是严格的。AI Scientist v2 的循环以开放式目标运行开放式代码。这就是为什么它需要更强的隔离（最低限度 Docker；优选 seccomp/gVisor）以及在任何提交离开系统之前对每个提交进行人工审查。

### v2 在前沿技术栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|------|------|---------|--------|---------|
| AlphaEvolve | 算法 | 代码 | 单元 + 基准 | 受评估器严格性限制 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励黑客 |
| AI Scientist v2 | 研究论文 | 文本 + 代码 + 图表 | 同行评审（弱） | 实验失败、错误标记、润色掩盖弱点 |

v2 在三者中拥有最弱的自动评估器、最宽的输出表面，以及到达公共工件的最短路径。操作控制（沙箱、审查、披露）正在做大多数安全工作。

## 使用它

`code/main.py` 将 v2 循环模拟为状态机：想法 → 新颖性检查 → 实验 → 图表 → 写作 → 审查 → 接受或迭代。每个状态都有从 Beel 等人发现中提取的可配置失败概率。对 N 个循环运行模拟器并计数：

- 有多少想法到达提交。
- 有多少提交会有一个精美论文掩盖的关键实验缺陷。
- 重试预算如何在质量与产量之间进行权衡。

## 交付它

`outputs/skill-ai-scientist-sandbox-review.md` 是在任何研究循环智能体生成的内容离开沙箱之前的两关审查清单。

## 练习

1. 使用默认参数运行 `code/main.py`。多少比例的循环运行产生"干净"的论文？多少比例产生一篇有实验失败缺陷但图表批评掩盖了的论文？

2. 默认值已经使用 Beel 等人的 42% / 25%。使用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 重新运行，然后使用 `--experiment-failure 0.60 --novelty-mislabel 0.40`。两次运行之间，精美但有缺陷的份额如何变化？

3. 阅读 Sakana 的 AI Scientist v2 仓库 README 关于沙箱要求的部分。说出你会为多天自主运行应用的两个额外限制（除了 Docker 之外）。

4. 阅读 Beel 等人第 4 节关于呈现质量差距的内容。设计一个额外的评估器，能够捕获看起来精美但实验有缺陷的论文。

5. 提出一个比"博士阅读每篇论文"更好扩展的研究智能体输出人工审查协议。识别瓶颈并围绕它设计。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| AI Scientist v1 | "Sakana 的模板化研究智能体" | 在固定脚手架中填充实验 |
| AI Scientist v2 | "无模板研究智能体" | 带 VLM 图表批评的主动式树搜索 |
| Agentic tree search（主动式树搜索） | "分支研究智能体" | 并行扩展多个实验计划；通过内部批评者剪枝 |
| Vision-language critique（视觉语言批评） | "VLM 润色图表" | 多模态模型读取图表并为了清晰度重写它们 |
| Literature retrieval（文献检索） | "新颖性检查" | 搜索先前工作以确认想法新颖性——已记录会错误标记 |
| Polish masking（润色掩盖） | "漂亮论文，破碎研究" | 呈现质量超过实验质量；隐藏弱点 |
| Sandbox escape（沙箱逃逸） | "LLM 代码突破" | 智能体执行的代码做了循环设计者未打算的事情 |
