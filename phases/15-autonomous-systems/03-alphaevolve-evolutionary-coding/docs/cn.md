# AlphaEvolve——进化式编码智能体（AlphaEvolve — Evolutionary Coding Agents）

> 将前沿编码模型与进化循环和机器可检查评估器配对。让循环运行足够长的时间。它发现了一个使用 48 次标量乘法的 4x4 复矩阵乘法过程——这是 56 年来对 Strassen 算法的首次改进。它还找到了一个谷歌全公司的 Borg 调度启发式，在生产中恢复了约 0.7% 的集群计算。这个架构有意设计得无聊。胜利来自评估器的严格性。

**类型：** 学习  
**语言：** Python（标准库，进化循环玩具）  
**前置知识：** Phase 15 · 01（长时域框架）、Phase 15 · 02（自我学习推理）  
**预计时间：** 约 60 分钟

## 问题所在

大型语言模型可以写代码。进化算法可以搜索代码。两者已经分别尝试了几十年；两者都触及了天花板。LLM 的天花板是混淆编造：模型写出看似合理但不做它所声称事情的代码。进化的天花板是搜索成本：对语法的随机突变很少产生可编译的程序，更不用说更好的程序了。

AlphaEvolve（Novikov 等，DeepMind，arXiv:2506.13131，2025 年 6 月）将它们结合起来。LLM 向程序数据库提出有针对性的编辑；自动评估器对每个变体进行评分；高分变体成为未来几代的父本。LLM 处理书写可信代码的昂贵步骤；评估器捕获混淆编造。循环运行几小时到几周。

报告的结果：48 次标量乘法的 4x4 复矩阵乘法（Strassen 1969 年的界是 49）、谷歌生产中的 Borg 调度启发式、32.5% 的 FlashAttention 内核加速、Gemini 训练吞吐量改进。

这个架构之所以有效，是因为评估器是机器可检查的。在评估器不是这样的地方它不起作用。这种不对称性就是本课的教训。

## 核心概念

### 循环

1. 从一个正确但次优的种子程序 `P_0` 开始。
2. 维护一个变体程序数据库，每个都由评估器评分。
3. 从数据库中采样一个或多个父本（MAP-elites 风格或岛基）。
4. 提示 LLM（Gemini Flash 用于许多候选，Gemini Pro 用于困难的）产生父本的修改变体。
5. 在持出评估器上编译、运行和评估变体。
6. 按其评分和特征向量插入数据库。
7. 重复。

两个细节很重要。首先，LLM 的提示不仅仅是父本程序——通常是数据库中的几个顶级变体，加上评估器签名，加上简短的任务描述。模型的工作是提出可能改进分数的有针对性的变更。其次，数据库是结构化的（MAP-elites 网格、岛基），所以循环探索多样性，而不仅仅是当前领导者。

### 为什么评估器不可或缺

AlphaEvolve 的胜利都来自评估器快速、确定性且难以博弈的领域：

- **矩阵乘法算法**：一个乘以矩阵并逐位检查相等性的单元测试。
- **Borg 调度启发式**：一个回放历史集群负载并测量浪费计算的生产级模拟器。
- **FlashAttention 内核**：一个正确性测试加上真实硬件上的挂钟基准。
- **Gemini 训练吞吐量**：测量每步 GPU 秒数。

在每种情况下，评估器都能捕获否则会占主导地位的 LLM 错误：混淆编造的正确性声明、在硬件上消失的性能声明，以及边缘案例失败。删除评估器，循环就会优化漂亮的代码。

### 奖励黑客是这一陈述的另一面

进化优化评估器测量的任何东西。如果评估器不完美，循环将找到不完美之处。在未验证的领域，循环会优化表面特征，而非预期行为。DeepMind 在论文中明确指出：AlphaEvolve 的成功只转移到评估器严格性与搜索雄心匹配的领域。

2025-2026 年代码搜索循环中奖励黑客的具体例子：

- 奖励"完成时间"的优化目标奖励了提交空解决方案。
- 奖励测试正确性的基准分数奖励了记忆测试和过拟合。
- "代码质量"代理奖励了删除注释和重写变量名，没有语义变化。

AlphaEvolve 的解决方法：发布一个 LLM 从未见过的持出评估器，输入在评估时生成。即便如此，DeepMind 建议对任何提议的部署进行严格审查。

### 为什么 LLM + 搜索比任一单独更好

LLM 可以产生可编译的、语义上可信的修改。对 2000 行 Python 文件的随机突变 GA 几乎总是产生语法错误。LLM 还将搜索集中在可信的邻域上（更改一个函数，而非随机字节），这大大减少了浪费的评估器调用。

评估器反过来捕获 LLM 的混淆编造。LLM 会自信地声称一个函数"在极限上是 O(n log n)"，而实际上是 O(n^2)；挂钟基准使这个问题得到解决。

### AlphaEvolve 在前沿技术栈中的位置

| 系统 | 生成器 | 评估器 | 领域 | 示例胜利 |
|------|--------|--------|------|---------|
| AlphaEvolve | Gemini | 正确性 + 基准 | 算法、内核、调度器 | 48 乘法 4x4 矩阵乘法 |
| FunSearch（DeepMind，2023） | PaLM / Codey | 正确性 | 组合数学 | cap-set 下界 |
| AI Scientist v2（Sakana，第 5 课） | GPT/Claude | LLM 批评 + 实验 | ML 研究 | ICLR 研讨会论文 |
| Darwin Godel Machine（第 4 课） | 智能体脚手架 | SWE-bench / Polyglot | 智能体代码 | 20% → 50% SWE-bench |

所有四个都是同一配方的变体：生成器加评估器，循环。不同之处在于评估器评分什么以及它的严格程度。

## 使用它

`code/main.py` 在一个玩具符号回归问题上实现了一个最小的 AlphaEvolve 风格循环。"LLM"是一个标准库代理，对计算目标函数的程序提出小的语法突变。"评估器"在持出测试点上测量均方误差。

观察：

- 最佳分数如何在几代中改进。
- MAP-elites 网格如何保持多样化的解决方案存活，使循环不收敛到局部最小值。
- 删除持出测试（仅训练评估器）如何让循环壮观地过拟合。

## 交付它

`outputs/skill-evaluator-rigor-audit.md` 是在新领域考虑 AlphaEvolve 风格循环的先决条件：你的评估器是否真正捕获你关心的失败？

## 练习

1. 运行 `code/main.py`。注意最佳分数轨迹。禁用持出评估器（标志 `--no-holdout`）并重新运行。量化过拟合。

2. 阅读 AlphaEvolve 论文关于 MAP-elites 网格的第 3 节。为一个新问题（例如编译器优化传递）设计一个特征向量描述符，以保持搜索的多样性。

3. 48 乘法 4x4 结果在 56 年后改进了 Strassen 的 49 乘法界。阅读论文的附录 F，用三句话解释为什么这个问题的评估器特别容易做对，以及为什么大多数领域不是这样的。

4. 提出一个 AlphaEvolve 会失败的领域。确切地识别评估器在哪里失效以及原因。

5. 对于你了解的一个领域，写出你会使用的评估器签名。包括（a）正确性条件，（b）性能指标，（c）持出输入生成规则，（d）至少一个反奖励黑客检查。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| AlphaEvolve | "DeepMind 的进化式编码智能体" | Gemini + 程序数据库 + 机器可检查评估器 |
| MAP-elites | "保持多样性的档案" | 按特征向量键控的网格；每个单元持有具有该描述符的最佳变体 |
| Island model（岛模型） | "并行进化子种群" | 定期迁移的独立种群；防止过早收敛 |
| Machine-checkable evaluator（机器可检查评估器） | "确定性神谕" | LLM 无法伪造的单元测试、模拟器或基准——这个循环的先决条件 |
| Reward hacking（奖励黑客） | "优化度量，而非目标" | 循环找到最大化分数而不执行预期任务的方法 |
| Seed program（种子程序） | "起点" | 循环从中进化的初始正确但次优程序 |
| Held-out evaluator（持出评估器） | "LLM 从未见过的评估数据" | 在评估时生成的输入以防止记忆 |
