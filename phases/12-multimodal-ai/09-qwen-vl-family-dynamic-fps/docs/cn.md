# Qwen-VL 系列与动态帧率视频（Qwen-VL Family and Dynamic-FPS Video）

> Qwen-VL 系列——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——是 2026 年最具影响力的开放视觉-语言模型谱系。每一代都做出了单一的决定性架构押注，开放生态在十二个月内纷纷跟进：通过 M-RoPE 实现原生动态分辨率、带绝对时间对齐的动态帧率采样、ViT 中的窗口注意力，以及结构化的智能体输出格式。到 Qwen3-VL，方案已趋于稳定：带原生宽高比输入的 2D-RoPE-ViT 编码器、接入大型 Qwen3 语言基座的 MLP 投影器，以及将 OCR、目标定位和智能体行为作为一等目标的训练阶段。本章按时间顺序解读这一系列，让你理解每个设计旋钮为何在其所处的位置。

**类型：** 学习  
**语言：** Python（标准库，M-RoPE 编码器 + 动态帧率采样器）  
**前置知识：** Phase 12 · 06（图块打包）  
**预计时间：** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三轴旋转（时间、高度、宽度），并解释为什么三个轴都是必要的。
- 为视频选择动态帧率采样策略，权衡每秒 token 数与事件检测准确率。
- 按顺序说出 Qwen-VL 四代升级及其各自实现了什么。
- 构建 Qwen2.5-VL 风格的 JSON 智能体输出格式，并解析 VLM 响应中的结构化工具调用。

## 问题所在

Qwen-VL 于 2023 年 8 月发布，直接针对 LLaVA-1.5 和 BLIP-2。Qwen 团队瞄准的差距有三个：分辨率、视频和结构化输出。

**分辨率：** LLaVA-1.5 在 336×336 下运行。对照片没问题，对中文发票或密集电子表格截图毫无用处。Qwen-VL 的首项创新是 448×448 和定位边界框输出，让模型能指向物体。

**视频：** Video-LLaMA 堆叠逐帧编码器并送给 LLM，适用于短片段，不适合时序轴是核心信号的多分钟视频。Qwen 团队需要一个理解时间的单一编码器。

**结构化输出：** LLaVA 输出自由格式文本。智能体需要 JSON。Qwen-VL 在显式 JSON 输出格式上训练，包括以文本形式表示的边界框坐标。

每一代 Qwen-VL 都在这三个轴之一上延伸。

## 核心概念

### Qwen-VL（2023 年 8 月）

第一代：OpenCLIP ViT-bigG/14 作为编码器（25 亿参数），LLama 兼容的 Q-Former（单步，256 个查询），Qwen-7B 基础模型。贡献：

- 448×448 分辨率（当时开放 VLM 的最先进水平）。
- 目标定位：在包含显式坐标 token 输出的图文对上训练。"猫在 `<box>(112, 204), (280, 344)</box>`"。
- 从一开始就进行中英文双语训练。

当时的基准：英文与 GPT-4V 竞争，中文占优势。定位监督是真正的亮点。

### Qwen2-VL（2024 年 9 月）——M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率 ViT 编码器替换了固定分辨率 + Q-Former 组合。关键变化：

- **原生动态分辨率。** ViT 接受任何可被 28 整除的 H×W（图块 14，带 2× 空间合并）。1120×672 的图像（40×24 合并图块）产生 960 个视觉 token。不调整大小，不平铺，不缩略图。
- **M-RoPE（多模态 RoPE）。** 每个 token 携带三维位置（t, h, w）而非一维。对图像 t=0，对视频 t=帧索引。RoPE 按每个轴的频率旋转查询/键向量。没有位置嵌入表。
- **MLP 投影器。** 丢弃 Q-Former；对合并的图块 token 使用 2 层 MLP。
- **动态帧率视频。** 视频默认以 1-2 FPS 采样，但模型接受任意帧数。

结果：Qwen2-VL-7B 在多个多模态基准上匹配 GPT-4o，在 DocVQA 上超越（94.5 vs 88.4）。架构变化是决定性的举措。

### Qwen2.5-VL（2025 年 2 月）——动态帧率 + 绝对时间

Qwen2.5-VL 的重大转变是视频。动态帧率不仅仅是"需要时采样更多帧"。论文正式化了：

- **绝对时间 token。** 不使用位置索引（第 0、1、2 帧…），而使用实际时间戳。"在 0:04，猫跳起来。"模型看到与帧 token 交错的 `<time>0.04</time>` token。
- **动态帧率。** 慢镜头以 1 FPS 采样，动作场景以 4+ FPS 采样。用户或训练者选择；M-RoPE 自适应。
- **ViT 中的窗口注意力。** 空间注意力加窗口（在块内局部化）以提升吞吐量；每隔几层进行全局注意力。
- **显式 JSON 输出格式。** 在工具调用数据上训练：`"{\"tool\": \"click\", \"coords\": [380, 220]}"`。开箱即用，可用于智能体。
- **MRoPE-v2 缩放。** 位置随最大输入尺寸缩放，使 10 分钟视频不会耗尽频率范围。

基准：Qwen2.5-VL-72B 在大多数视频基准上击败 GPT-4o，在文档上与 Gemini 2.0 持平，并创下 GUI 定位的开放模型最先进水平（ScreenSpot：84% 准确率，GPT-4o 为 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是巩固而非革新的增量升级：更大的 LLM 骨干（Qwen3-72B）、扩展的训练数据、改进的 OCR、通过 Qwen3"思考模式"增强的推理能力。ViT 和 M-RoPE 保持不变。论文专注于数据和训练改进，而非架构。

**谱系要点：** 到 2025 年，Qwen-VL 架构已趋于稳定。后续几代扩展算力和数据，而非原语。

### M-RoPE 的数学

经典 RoPE 使用成对坐标通过位置 `m` 旋转维度为 `d` 的查询 `q`：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分为三个频段。假设 `d = 96`，将 32 维分配给时间、32 维给高度、32 维给宽度。每个频段按其自身的轴位置旋转。位置 (t=5, h=10, w=20) 的图块在其三个频段上分别获得旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t = text_index, h = 0, w = 0`（或归一化选择），保持兼容性。视频帧使用 `t = frame_time, h = 行, w = 列`。单张图像使用 `t = 0`。

好处：一个位置编码，无需分支代码或不同的位置表，即可处理文本、图像和视频。

### 动态帧率采样逻辑

给定时长为 `T` 秒的视频和目标 token 预算 `B`：

1. 计算可负担的最大帧率：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选择满足 `fps <= fps_max` 的目标帧率。
3. 如果运动幅度大（光流启发或用户显式要求），选择更高帧率；运动幅度小则选较低帧率。
4. 以选定的帧率均匀采样；在帧之间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式训练了这一逻辑；推理时用户通过 `fps` 参数控制。一段 60 秒的动作序列，以 4 FPS 采样，每帧 81 个 token = 19440 个 token，在 32k 上下文中可以处理。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练明确针对结构化工具调用：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的：对模型输出进行 JSON.parse。相比之下，自由格式的"在 (1024, 512) 处点击"需要正则表达式和歧义处理。这一转变是 Qwen2.5-VL 的 ScreenSpot 分数从 Qwen2-VL 的 55% 跳升到 84% 的原因。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| M-RoPE | "多模态 RoPE" | 在隐藏维度中带有时间、高度、宽度频段的三维旋转位置嵌入。 |
| 动态帧率（Dynamic FPS） | "智能采样" | 根据运动、时长和 token 预算为每段视频选择的帧采样率。 |
| 绝对时间 token（Absolute time token） | "时间戳 token" | 在序列中交错的 `<time>t</time>`，使模型看到实际秒数而非帧索引。 |
| 窗口注意力（Window attention） | "局部注意力" | 为提速将空间自注意力限制在小窗口内；周期性添加全局注意力。 |
| 结构化智能体输出（Structured agent output） | "JSON 模式" | 训练数据监督，教 VLM 输出带坐标和工具名称的可解析 JSON。 |
| min_pixels / max_pixels | "分辨率边界" | Qwen2.5-VL 每请求控制，限制总像素数进而限制 token 数。 |
| 定位（Grounding） | "指向它" | 以文本 token 形式输出边界框坐标；自 Qwen-VL v1 起使用。 |
