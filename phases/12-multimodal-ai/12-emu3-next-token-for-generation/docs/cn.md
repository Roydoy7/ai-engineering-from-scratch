# Emu3：用下一个 Token 预测生成图像和视频（Emu3: Next-Token Prediction for Image and Video Generation）

> BAAI 的 Emu3（Wang 等，2024 年 9 月）本应终结扩散 vs. 自回归之争。一个 Llama 风格的仅解码器 Transformer，只在下一个 token 预测目标上训练，跨文本 + VQ 图像 token + 3D VQ 视频 token 的统一词汇表，在图像生成上击败 SDXL，在感知上击败 LLaVA-1.6。没有 CLIP 损失，没有扩散调度。推理时使用无分类器引导来提升质量，但核心训练目标是带教师强制的下一个 token 预测。发表于 Nature。本章解读 Emu3 的核心论点——更好的分词器加规模就是你需要的一切——并与扩散方法对比。

**类型：** 学习  
**语言：** Python（标准库，3D 视频分词器数学 + 自回归采样器骨架）  
**前置知识：** Phase 12 · 11（Chameleon）  
**预计时间：** 约 120 分钟

## 学习目标

- 解释为什么 Emu3 的单一损失下一个 token 目标有效，尽管长期以来普遍认为图像质量需要扩散。
- 描述 3D 视频分词器：时空 VQ 码本是什么样子，为什么图块跨越时间维度。
- 在（训练算力、推理成本、质量上限）三个维度对比 Emu3 vs Stable Diffusion XL。
- 说出同一个 Emu3 模型扮演的三个角色：Emu3-Gen（图像生成）、Emu3-Chat（感知）、Emu3-Stage2（视频生成）。

## 问题所在

2024 年之前的传统智慧：图像生成需要扩散。论据：离散图像 token 会损失太多信息无法重建细节，而自回归采样在数千个 token 上会累积误差。Stable Diffusion、DALL-E 3、Imagen、Midjourney 都使用某种形式的扩散。Chameleon（Lesson 12.11）在小规模上部分推翻了这一论断，但质量上未能匹敌 SDXL。

Emu3 正面迎击这一论点。主张：更好的视觉分词器 + 足够的规模 + 下一个 token 损失 = 在同一模型中同时做感知并击败扩散的图像生成。

这个赌注在发布时颇具争议。两年后，开源统一生成家族（Emu3、Show-o、Janus-Pro、Transfusion）已成为研究的默认路径；生产前沿模型似乎也在使用某种变体。

## 核心概念

### Emu3 分词器

关键成分是视觉分词器。Emu3 训练了一个自定义的 IBQ 类分词器（逆瓶颈量化器，SBER-MoVQGAN 家族），每个 token 的分辨率缩减为 8×8。512×512 的图像变成 64×64 = 4096 个码本大小为 32768 的 token。

这比 Chameleon 的每张 512×512 图像 1024 个 token（K=8192）多，但每 token 更便宜（更小的码本查找，更简单的编解码器）。关键指标：重建 PSNR 达到 30.5 dB，与 Stable Diffusion 连续潜在空间的 32 dB 接近。

对于视频：3D VQ 分词器将时空图块（4×4×4 像素）编码为一个整数。以 8 FPS 录制的 4 秒短片有 32 帧；在 256×256 下，空间缩减 4 倍、时间缩减 4 倍，token 数为 (256/4) × (256/4) × (32/4) = 64 × 64 × 8 = 32768 个 token。

分词器质量是上限。Emu3 的贡献部分在于"我们训练了一个非常好的分词器"。

### 单一损失训练

Emu3 使用一个目标：在文本 token、2D 图像 token 和 3D 视频 token 共享词汇表上进行下一个 token 预测。训练期间权重按模态特定因子加权以平衡贡献，但损失函数完全相同。

在以下混合数据上训练：
- 图像生成：`<文字描述> <image> 图像 token </image>`
- 图像感知：`<image> 图像 token </image> <问题> 文字 token`
- 视频生成：`<文字描述> <video> 视频 token </video>`
- 视频感知：类比。
- 纯文本：标准 NTP。

模型从数据分布中学习何时输出图像 token 而非文字 token。生成能力从模型在 `<image>` 标签之后预测图像 token 中涌现。

### 无分类器引导与温度

无分类器引导（CFG）在推理时能大幅改善自回归图像生成质量。Emu3 使用了它：生成两次——一次带完整描述，一次带空描述——用引导权重（通常 3.0-7.0）混合 logit。这是扩散中同样使用的 CFG 技巧，移植到了自回归场景。

温度很重要：太高出现伪影，太低导致模式坍缩。Emu3 推荐的温度：感知任务为 1.0，图像生成为 0.8。

### 三种角色，一个模型

Emu3 以三种功能上不同的 API 发布，但底层只有一套权重：

- **Emu3-Gen。** 图像生成。输入文本，输出图像 token。
- **Emu3-Chat。** 视觉问答和图像描述。输入图像（token），输出文本。
- **Emu3-Stage2。** 视频生成和视频视觉问答。输入文本或视频，输出文本或视频。

没有任务专属的头部。只是不同的提示词模板。同一个检查点。

### 基准测试

来自 Emu3 论文（2024 年 9 月）：

- 图像生成：在 MJHQ-30K FID 上击败 SDXL（5.4 vs 5.6），GenEval 总体持平（0.54 vs 0.55——统计上的平局），Deep-Eval 综合评分相当。
- 图像感知：在 VQAv2 上击败 LLaVA-1.6（75.1 vs 72.4），MMMU 上大致持平。
- 视频生成：4 秒短片质量在 FVD 上与 Sora 时代公开基准测试的模型有竞争力。

这些数字并非总是胜出——Emu3 在这里换一分那里换一分——但"下一个 token 预测就是你所需要的全部"这一主张在跨模态上是站得住脚的。

### 计算成本

Emu3 在约 3000 亿个多模态 token 上用 70 亿参数模型训练。GPU 小时大致相当于 Llama-2-7B 预训练（A100 级硅片上约 2000-4000 GPU 年）。Stable Diffusion 3 等扩散模型在相近预算内训练，但需要独立的文本编码器和更复杂的流水线。

推理时，Emu3 每张图像比 SDXL 慢：4096 个图像 token 以 30 token/s 生成约需 2 分钟（512×512），而 SDXL 只需 2-5 秒。推测解码和 KV 缓存优化缩小了差距，但未能弥合。自回归图像生成是算力密集型的——这是既有的权衡。

### 为何重要

Emu3 的深层贡献是概念性的。如果下一个 token 预测能规模化到与扩散在图像生成上相当，那么统一模型路径（一个损失、一个骨干、任意模态）就是可行的。未来的模型不需要独立的文本编码器、独立的扩散调度器、独立的 VAE。一个 Transformer，每种模态一个分词器，规模化即可。

Show-o、Janus-Pro 和 InternVL-U 都在这一论点之上构建或挑战它。2025 年间，中国实验室（BAAI、DeepSeek）在这一方向上的发表比美国实验室更积极。

## 动手使用

`code/main.py` 构建两个玩具组件：

- 2D vs 3D VQ 分词器 token 数量计算器：给定（分辨率、图块、片段时长、帧率），计算图像 vs 视频的 token 数量。
- 带温度的无分类器引导自回归图像 token 采样器。

CFG 实现与 Emu3 的方案匹配——用引导权重混合条件与无条件 logit。

## 输出产物

本章生成 `outputs/skill-token-gen-cost-analyzer.md`。给定生成产品规格（图像或视频、目标分辨率、质量等级、延迟预算），它计算 token 数量、推理成本，并在 Emu3 家族和扩散方案之间做出选择。

2. 阅读 Emu3 第 3.3 节关于视频分词器的内容。描述 3D VQ 图块形状，以及为什么是 4×4×4 而不是 8×8×1。

3. 无分类器引导权重 5.0 vs 3.0：视觉效果如何不同？在 `code/main.py` 中追踪数学过程。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 下一个 token 预测（Next-token prediction） | "NTP" | 标准自回归损失：给定 token[0..i] 预测 token[i+1]；对任意模态在分词后均适用。 |
| IBQ 分词器（IBQ tokenizer） | "逆瓶颈量化器" | 一类 VQ-VAE，码本更大（32768+），重建效果优于 Chameleon 的分词器。 |
| 3D VQ | "时空量化器" | 由（时间、行、列）索引的码本；一个 token 覆盖 4×4×4 像素立方体。 |
| 无分类器引导（Classifier-free guidance） | "CFG" | 用权重 gamma 混合条件和无条件 logit；推理时提升图像质量。 |
| 统一词汇表（Unified vocabulary） | "共享 token" | 文本、图像、视频均从同一整数空间取值；模型预测下一个出现的任意模态 token。 |
| MJHQ-30K | "图像生成基准" | 基于 Midjourney 质量的包含 3 万条提示词的基准；Emu3 在此报告 FID。 |
