# 百万 Token 上下文的长视频理解（Long-Video Understanding at Million-Token Context）

> 以 24 FPS 拍摄的 1 小时 4K 视频，经过图块化和嵌入，大约产生 6000 万个 token。一集 2 小时的播客转录后是 3 万个 token。一部完整的蓝光故事片，即使经过激进的池化，也有数十万个 token。Google 的 Gemini 1.5（2024 年 3 月）用 1000 万 token 上下文开创了这个时代，在长达一小时的视频中实现了可靠的"海量文本中的针"召回。LWM（Liu 等，2024 年 2 月）展示了环形注意力的扩展路径。LongVILA 和 Video-XL 进一步扩展了摄取能力。VideoAgent 将原始上下文换成了智能体检索。每种方法在算力、召回率和工程复杂度上做出了不同的权衡。本章并排阅读这些方法。

**类型：** 构建  
**语言：** Python（标准库，"草垛中的针"模拟器 + 智能体检索路由器）  
**前置知识：** Phase 12 · 17（视频时序 token）  
**预计时间：** 约 180 分钟

## 学习目标

- 计算不同帧率和池化下长视频的视觉 token 总数。
- 解释三条扩展路径：暴力上下文（Gemini 1.5）、环形注意力（LWM）、token 压缩（LongVILA/Video-XL）。
- 在准确率和延迟上对比原始上下文视频 VLM 与智能体检索视频 VLM（VideoAgent）。
- 为 30 分钟视频设计"草垛中的针"测试，并测量特定分钟的召回率。

## 问题所在

Qwen2.5-VL 在 384 原生分辨率下单帧图块约 729 个 token。3×3 池化后每帧 81 个 token。以 1 FPS 采样的 30 分钟短片 = 1800 帧 = 145800 个 token。2025 年开放 VLM 勉强可以处理。以 2 FPS 采样，291600 个 token——只有最大上下文才放得下。

以 1 FPS 采样的 2 小时电影是 58.3 万个 token。超出大多数 2026 年开放模型；需要 Gemini 2.5 Pro 或更激进的池化。

三条扩展路径由此出现。

## 核心概念

### 路径一：暴力上下文（Gemini 1.5、Claude Opus）

用硬件硬撑。将上下文扩展到数百万 token，在一次前向传播中处理所有内容。

Gemini 1.5 Pro 以 100 万 token 上下文发布；Gemini 1.5 Ultra 达到 1000 万；2026 年的 Gemini 2.5 Pro 可靠地处理数小时视频。论文（arXiv:2403.05530）记录了在约 950 万 token 时"草垛中的针"召回率达 99.7%。

工程方面：带内存层级（局部 + 全局 + 稀疏）的自定义注意力实现，加上用于长上下文效率的 MoE 专家路由。未完整发布细节，非开源。

### 路径二：环形注意力（LWM、LongVILA）

环形注意力在设备间以"环"的形式分布长序列，每个设备持有一个块。完整序列的注意力通过每个设备将其块发送给环中下一个设备、计算部分注意力、然后聚合来实现。

LWM（Liu 等，2024）以此方式训练了一个 100 万 token 上下文模型。训练算力随上下文线性扩展，而非二次方——注意力的二次方开销在环形设备间被摊销。

LongVILA（arXiv:2408.10188）将这一模式适配到 VLM。1400 帧视频，每帧 192 个 token = 26.8 万上下文，通过 8 路并行的环形注意力训练。

### 路径三：Token 压缩（Video-XL、LongVA）

比暴力上下文更便宜：在 LLM 看到序列之前激进压缩。

Video-XL（arXiv:2409.14485）使用视觉摘要 token：N 帧组成的每个片段产生一个"摘要" token，该 token 关注 N 帧。在推理时，LLM 每个片段看到一个摘要 token，大幅缩短上下文。

LongVA 通过"长上下文迁移"技术将 LLM 上下文从 20 万扩展到 200 万。在长上下文文本上训练，通过共享表示迁移到长上下文视频。

Token 压缩以可扩展性换取特定时间戳的召回率。模型大致知道发生了什么，但有时会错过精确帧。

### 路径四：智能体检索（VideoAgent）

不把完整视频送给 LLM。而是将视频视为数据库，用 LLM 查询它。

VideoAgent（arXiv:2403.10517）：

1. LLM 读取问题。
2. LLM 向检索工具请求相关片段（"显示有猫的片段"）。
3. 工具返回匹配的片段时间戳。
4. LLM 通过 VLM 读取这些片段。
5. LLM 组合答案或发起后续查询。

这是应用于长视频的 LLM 作为智能体模式。推理更便宜（只编码相关片段），工程更难（检索质量成为瓶颈）。

### "草垛中的针"基准

标准长上下文测试：在视频随机位置插入独特的视觉或文本标记，然后提出需要回忆它的查询。

指标：跨视频长度和标记位置的 Recall@k。

Gemini 2.5 Pro 在长达 90 分钟的视频中召回率 >99%。开放 72B 模型（Qwen2.5-VL-72B、InternVL3-78B）在 30 分钟时约 85-90%，超过 60 分钟后下降。

VideoAgent 在 2 小时以上的内容中可以匹敌或超越原始上下文模型，因为检索能命中"针"——只要工具足够好。

### 选择哪条路径

**15 分钟以内前沿准确率：** 开放 72B + 原生上下文通常有效。选 Qwen2.5-VL-72B。

**30 分钟到 1 小时内容：** 开放选 LongVILA 或 Video-XL；封闭选 Gemini 2.5 Pro。质量要求越高越往封闭走。

**2 小时以上内容：** VideoAgent 或类似检索模式。或者，摘要成较小块并馈送层级摘要。

### 2026 年生产模式

实践中，生产长视频流水线是混合式的：

1. 在整个视频上运行动态帧率采样 + 激进池化（得到 10 万 token 的全局表示）。
2. 传给 72B VLM 做全局摘要。
3. 如果用户提出详细问题，使用摘要作为索引进行智能体检索。

这将暴力上下文用于全局理解，将检索用于局部细节。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 暴力上下文（Brute context） | "就是更多 token" | 将 LLM 上下文扩展到数百万 token；在一次前向传播中处理所有内容。 |
| 环形注意力（Ring attention） | "LWM 风格并行" | 分布式注意力模式，每个设备持有一个块并按环形旋转。 |
| Token 压缩（Token compression） | "摘要 token" | 通过可学习压缩器在 LLM 之前减少每个片段的 token。 |
| 草垛中的针（Needle-in-haystack） | "NIH 测试" | 在随机点插入独特标记，让模型在测试时召回它。 |
| 智能体检索（Agentic retrieval） | "LLM 作为查询规划器" | LLM 向检索工具请求相关片段，通过 VLM 读取，组合答案。 |
| VideoAgent | "视频检索模式" | 典范智能体检索设计：问题 → 工具 → 片段 → 答案。 |
