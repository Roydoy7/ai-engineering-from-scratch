# 从 CLIP 到 BLIP-2——Q-Former 作为模态桥梁（From CLIP to BLIP-2 — Q-Former as Modality Bridge）

> CLIP 能对齐图像和文本，但无法生成描述、回答问题或进行对话。BLIP-2（Salesforce，2023）用一个小型可训练桥梁解决了这个问题：32 个可学习查询向量通过交叉注意力在冻结 ViT 的特征上进行关注，然后直接插入冻结 LLM 的输入流。1.88 亿参数的桥梁将一个 110 亿参数的 LLM 与 ViT-g/14 相连。直到 2026 年，所有基于适配器的 VLM——MiniGPT-4、InstructBLIP、LLaVA 的各种变体——都是它的后代。本章解读 Q-Former 的架构，解释其两阶段训练，并构建一个将视觉 token 喂给冻结文本解码器的玩具版本。

**类型：** 构建  
**语言：** Python（标准库，交叉注意力 + 可学习查询演示）  
**前置知识：** Phase 12 · 02（CLIP）、Phase 7（Transformer）  
**预计时间：** 约 180 分钟

## 学习目标

- 解释为什么在冻结视觉编码器和冻结 LLM 之间加入可训练瓶颈在成本和稳定性上优于端到端微调。
- 实现一个交叉注意力块，其中固定数量的可学习查询向量关注外部图像特征。
- 逐步介绍 BLIP-2 的两阶段预训练：表示学习（ITC + ITM + ITG）和生成学习（使用冻结解码器的 LM 损失）。
- 比较 Q-Former 与 LLaVA 中使用的更简单 MLP 投影器，论证各自何时更优。

## 问题所在

你有一个冻结的 ViT，每张图像产生 256 个维度为 1408 的图块 token。你有一个冻结的 7B LLM，期望维度为 4096 的 token 嵌入。显而易见的桥梁——从 1408 到 4096 的线性层——可行，但将所有 256 个图块 token 喂给 LLM 的上下文，每张图像就要额外消耗 256 个 token。在 32 张图像的批次中，视觉模态单独就消耗了 8192 个 token。

BLIP-2 的问题是：能否将 256-token 的图像表示压缩为少得多的 token（比如 32 个），同时保留足够的信息让 LLM 生成描述、回答问题、对图像进行推理？能否在不触碰冻结骨干网络的情况下训练这座桥梁，将训练成本控制在桥梁自身的参数上？

答案：一个 Q-Former。32 个可学习的"查询"向量交叉关注 ViT 的图块 token，产生 LLM 所消费的 32-token 视觉摘要。总共 1.88 亿参数，在触碰 LLM 之前就用对比、匹配和生成目标进行训练。

## 核心概念

### 可学习查询

Q-Former 的核心技巧：不让 LLM 的文本 token 直接关注图像图块，而是引入一组 32 个可学习查询向量 `Q`，让*它们*来关注图像图块。这些查询是模型的参数——在训练期间学习，所有图像共用同一组 32 个查询。

交叉注意力之后，每个查询都持有图像的压缩摘要——"描述主要对象"、"描述背景"、"数出对象的数量"等。查询并不是字面意义上专注于语义标签；它们学习的是任何能让下游损失下降的编码。

### 架构

Q-Former 是一个小型 Transformer（12 层，约 1 亿参数），有两条路径：

1. 查询路径：32 个查询向量经过自注意力（互相之间），再经过交叉注意力（关注冻结 ViT 的图块 token），再经过 FFN。
2. 文本路径：类 BERT 的文本编码器与查询路径共享自注意力和 FFN 权重。文本路径禁用交叉注意力。

训练时两条路径都运行。查询和文本通过共享的自注意力相互作用，这意味着查询可以在需要时以文本为条件（ITM、ITG）。在 VLM 移交的推理时，只有查询路径运行，产出 32 个视觉 token。

### 两阶段训练

BLIP-2 分两个阶段预训练：

**阶段 1：表示学习（不涉及 LLM）。** 三个损失：
- ITC（图像-文本对比）：池化查询 token 与文本 CLS token 之间的 CLIP 风格对比损失。
- ITM（图像-文本匹配）：二分类器——这个图文对是否匹配？通过硬负样本挖掘。
- ITG（图像驱动文本生成）：文本上的因果 LM 头，以查询为条件。强制查询编码可从文本生成的内容。

只有 Q-Former 训练，ViT 冻结，不涉及 LLM。

**阶段 2：生成学习。** 接入冻结 LLM（OPT-2.7B 或 Flan-T5-XL 等）。通过小型线性层将 32 个查询输出投影到 LLM 的嵌入维度。将其前置到文本提示词。仅对线性投影和 Q-Former 在拼接的"提示词 + 图像 + 文本描述"序列上的 LM 损失进行训练。

阶段 2 结束后，Q-Former + 投影层就是完整的视觉适配器。推理时：图像 → ViT → Q-Former → 线性投影 → 前置到文本 → 冻结 LLM 输出结果。

### 参数经济学

BLIP-2 使用 ViT-g/14（11 亿，冻结）+ OPT-6.7B（67 亿，冻结）+ Q-Former（1.88 亿，训练）= 共 80 亿参数，仅训练 1.88 亿。Q-Former 单独约占整体堆栈参数的 2.4%。训练成本与此相符：数天（在少量 A100 上）对比端到端的数周。

质量：BLIP-2 在零样本 VQA 上匹配或超越 Flamingo-80B，而体积缩小了 50 倍。桥梁有效。

### InstructBLIP 与指令感知 Q-Former

InstructBLIP（2023）为 Q-Former 添加了一个额外输入：指令文本本身。在交叉注意力时，查询现在同时访问图像图块和指令。查询可以按指令专门化（"数出汽车的数量"、"描述氛围"），而不是学习单一固定的摘要。在留出任务上取得基准提升。

### MiniGPT-4 与纯投影器方法

MiniGPT-4 保留了 Q-Former，但只训练输出线性投影，冻结其他所有部分。成本低，但代价是质量——查询是 BLIP-2 的，不是你自己的。适合快速迭代，但不是最佳架构。

### 为什么 LLaVA 选择了更简单的方案

LLaVA（2023，Lesson 12.05）用一个普通的 2 层 MLP 替换了 Q-Former，将每个 ViT 图块 token 投影到 LLM 空间——对于 24×24 网格，每张图像 576 个 token，全部喂给 LLM。压缩性较差，但让 LLM 能直接关注原始图块。当时这颇具争议；到 2023 年底已成主流，因为视觉指令数据（LLaVA-Instruct-150k）证明 MLP 经过训练可以保留足够的信号。权衡：LLaVA 的上下文填充更快，但天然支持多图像和视频。

到 2026 年，该领域分化：在 token 预算有限的场景（长视频、多图像）中 Q-Former 存活；在每个 token 原始质量优先的场景中 MLP 投影器占主导。

### 门控交叉注意力：祖先 Flamingo

Flamingo（Lesson 12.04）早于 BLIP-2，使用了相同的交叉注意力思路，但施加在每个冻结 LLM 层上，而不是作为单一桥梁。BLIP-2 证明只需压缩到输入层就能有效工作。Gemini 和 Idefics 两者兼顾：交错输入 token 加上可选的门控交叉注意力，用于上下文少样本学习。

### 2026 年的后代

- Q-Former：BLIP-2、InstructBLIP、MiniGPT-4，以及大多数视频-语言模型（出于 token 预算的考虑）。
- Perceiver 重采样器：Flamingo 的变体（Lesson 12.04）；Idefics 系列、Eagle、OmniMAE。
- MLP 投影器：LLaVA、LLaVA-NeXT、LLaVA-OneVision、Cambrian-1。
- 注意力池化：VILA、PaliGemma。

四种方式都是有效的。决定因素是你受 token 预算约束还是受每个 token 质量约束。

## 动手使用

`code/main.py` 用标准库构建了 Q-Former 风格的交叉注意力：

1. 模拟 256 个图像图块 token（维度 128）。
2. 实例化 32 个可学习查询（维度 128）。
3. 运行缩放点积交叉注意力（Q 来自查询，K/V 来自图块）。
4. 通过线性层投影到 LLM 维度（512）。
5. 输出 32 个 LLM 就绪的视觉 token。

所有数学用纯 Python 实现（向量上的嵌套循环）。玩具级别但形状正确。注意力权重矩阵被打印出来，供你观察每个查询从哪些图块提取了信息。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| Q-Former | "查询 Transformer" | 带有 32 个可学习查询向量的小型 Transformer，交叉关注冻结 ViT 的特征。 |
| 可学习查询（Learnable queries） | "视觉软提示" | 作为交叉注意力查询端的固定参数集；每个模型学习一次，所有输入共用。 |
| 交叉注意力（Cross-attention） | "Q 来自这里，K/V 来自那里" | 查询、键和值来自不同来源的注意力；查询从 ViT 图块中提取信息的方式。 |
| ITC | "图像-文本对比" | 应用于 Q-Former 池化查询与文本 CLS 的 CLIP 风格损失。 |
| ITM | "图像-文本匹配" | 在硬负样本挖掘对上的二分类器；强制查询区分细粒度的不匹配。 |
| ITG | "图像驱动文本生成" | 以查询为条件生成文本的因果 LM 损失；强制查询编码可从文本解码的内容。 |
| 两阶段预训练（Two-stage pretraining） | "表示学习然后生成学习" | 阶段 1 单独训练 Q-Former（ITC/ITM/ITG）；阶段 2 接入冻结 LLM，只训练投影层 + Q-Former。 |
| 冻结骨干（Frozen backbone） | "不微调" | 视觉编码器和 LLM 权重固定；只有桥梁训练。 |
| 投影头（Projection head） | "线性到 LLM 维度" | 将 Q-Former 输出映射到 LLM 嵌入维度的最终线性层。 |
| Perceiver 重采样器（Perceiver resampler） | "Flamingo 的版本" | 类似的可学习查询交叉注意力，由 Flamingo 在每个层使用，而非作为单一桥梁。 |
