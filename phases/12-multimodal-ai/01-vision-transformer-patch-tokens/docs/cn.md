# 视觉 Transformer 与图块-Token 原语（Vision Transformers and the Patch-Token Primitive）

> 在多模态之前，图像必须先变成 Transformer 能"吞下"的 token 序列。2020 年的 ViT 论文用 16×16 像素图块、一个线性投影和一个位置嵌入回答了这个问题。五年后，2026 年的每个前沿模型（Claude Opus 4.7 的 2576px 原生分辨率、Gemini 3.1 Pro、Qwen3.5-Omni）仍以同样的方式开始——编码器从 ViT 进化到 DINOv2 再到 SigLIP 2，加入了寄存器 token，位置编码变成了 2D-RoPE，但这个原语始终不变。本章从头到尾读通图块-token 流水线，并用标准库 Python 实现它，让 Phase 12 的其余部分有一个关于"视觉 token"的具体心智模型。

**类型：** 学习  
**语言：** Python（标准库，图块分词器 + 几何计算器）  
**前置知识：** Phase 7（Transformer）、Phase 4（计算机视觉）  
**预计时间：** 约 120 分钟

## 学习目标

- 将 HxWx3 的图像转换为带有正确位置编码的图块 token 序列。
- 计算给定（图块大小、分辨率、隐藏维度、深度）的 ViT 的序列长度、参数量和 FLOPs。
- 说出将 ViT 从 2020 年研究带到 2026 年生产的三项升级：自监督预训练（DINO / MAE）、寄存器 token、原生分辨率打包。
- 根据下游任务在 CLS 池化、均值池化和寄存器 token 之间做出选择。

## 问题所在

Transformer 在向量序列上运算。文本本身就是序列（字节或 token）。图像是一个有三个颜色通道的二维像素网格——不是序列。如果将每个像素展平，一张 224×224 的 RGB 图像会变成 150,528 个 token，这种长度的自注意力根本行不通（复杂度与序列长度成平方关系）。

2020 年之前的方法是在前面接一个 CNN 特征提取器：ResNet 生成一个 7×7 的 2048 维特征图，把这 49 个 token 喂给 Transformer。这可行，但继承了 CNN 的偏置（平移等变性、局部感受野），并且失去了 Transformer 对规模扩展的适应性。

Dosovitskiy 等人（2020）提出了一个直接的问题：如果跳过 CNN 呢？将图像分成固定大小的图块（比如 16×16 像素），将每个图块线性投影成一个向量，添加位置嵌入，然后将序列喂给标准 Transformer。当时这是异端邪说——没有卷积的视觉。但有了足够的数据（JFT-300M，后来是 LAION），它在 ImageNet 上超越了 ResNet，并持续进步。

到 2026 年，ViT 原语已是无可争议的基础。每个开放权重 VLM 的视觉塔都是它的某个后代（DINOv2、SigLIP 2、CLIP、EVA、InternViT）。问题不再是"我们是否该用图块？"，而是"用什么图块大小、什么分辨率策略、什么预训练目标、什么位置编码"。

## 核心概念

### 图块即 Token

给定形状为 `(H, W, 3)` 的图像 `x` 和图块大小 `P`，将图像切分为 `(H/P) x (W/P)` 个不重叠图块组成的网格。每个图块是 `P x P x 3` 的像素立方体。将每个立方体展平为 `3P²` 维向量，再用形状为 `(3P², D)` 的共享线性投影 `W_E` 将每个图块映射到模型的隐藏维度 `D`。

对于 ViT-B/16 的标准配置：
- 分辨率 224，图块大小 16 → 网格 14×14 → 196 个图块 token。
- 每个图块是 `16 x 16 x 3 = 768` 个像素值，投影到 `D = 768`。
- 加入一个可学习的 `[CLS]` token → 序列长度 197。

图块投影在数学上等价于一个卷积核大小为 `P`、步长为 `P`、输出通道为 `D` 的二维卷积。这正是生产代码的实现方式——`nn.Conv2d(3, D, kernel_size=P, stride=P)`。"线性投影"是概念层面的表述；卷积核是高效的实现。

### 位置嵌入

图块本身没有固有顺序——Transformer 将它们视为一个集合。早期 ViT 添加了可学习的一维位置嵌入（每个位置一个 768 维向量，共 197 个）。这有效，但将模型绑定到了训练分辨率：推理时如果改变网格，就必须对位置表进行插值。

现代视觉骨干网络使用 2D-RoPE（Qwen2-VL 的 M-RoPE、SigLIP 2 的默认配置）或分解式二维位置。2D-RoPE 根据图块的（行、列）索引旋转查询和键向量，使模型能从旋转角度推断相对二维位置。没有位置表，模型在推理时可以处理任意网格大小。

### CLS Token、池化输出与寄存器 Token

什么是图像级表示？三种选择并存：

1. `[CLS]` token。在图块序列前添加一个可学习向量。经过所有 Transformer 块后，CLS token 的隐藏状态就是图像表示。继承自 BERT，被原始 ViT 和 CLIP 使用。
2. 均值池化。对图块 token 的输出隐藏状态取平均。被 SigLIP、DINOv2、大多数现代 VLM 使用。
3. 寄存器 token。Darcet 等人（2023）观察到，没有显式"汇聚 token"训练的 ViT 会出现高范数"伪影"图块，劫持自注意力。添加 4–16 个可学习寄存器 token 可吸收这种负载，提升密集预测质量（分割、深度估计）。DINOv2 和 SigLIP 2 均内置了寄存器。

对下游任务的选择很重要。CLS 适合分类任务。对于将图块 token 喂给 LLM 的 VLM，完全跳过池化——每个图块都成为 LLM 的输入 token。寄存器在移交前被丢弃（它们是脚手架，不是内容）。

### 预训练：监督、对比、掩码、自蒸馏

2020 年的 ViT 在 JFT-300M 上通过监督分类预训练。迅速被以下方法取代：

- CLIP（2021）：在 4 亿图文对上进行对比学习。见 Lesson 12.02。
- MAE（2021，He 等）：遮蔽 75% 的图块，重建像素。自监督，只需纯图像。
- DINO（2021）/ DINOv2（2023）：无标签、无字幕的学生-教师自蒸馏。2023 年的 DINOv2 ViT-g/14 是最强的纯视觉骨干，也是"密集特征"用例的默认选择。
- SigLIP / SigLIP 2（2023、2025）：带有 sigmoid 损失和 NaFlex（原生宽高比）的 CLIP 变体。2026 年开放 VLM 中最主流的视觉塔（Qwen、Idefics2、LLaVA-OneVision）。

预训练方式的选择决定了骨干网络的优势：CLIP/SigLIP 适合与文本的语义匹配，DINOv2 适合密集视觉特征，MAE 适合作为下游微调的起点。

### 缩放定律

ViT 缩放研究（Zhai 等，2022）证明 ViT 的质量在模型大小、数据量和算力上遵循可预测的规律。在固定算力下：
- 更大的模型 + 更多数据 → 更好的质量。
- 图块大小是序列长度与保真度之间的杠杆。图块 14（DINOv2/SigLIP SO400m 的典型值）比图块 16 每张图像产生更多 token；对 OCR 和密集任务更好，速度更慢。
- 分辨率是另一个主要杠杆。从 224 到 384 到 512 几乎总是有帮助的，但 FLOPs 代价是平方级的。

ViT-g/14（10 亿参数，图块 14，分辨率 224 → 256 token）和 SigLIP SO400m/14（4 亿参数，图块 14）是 2026 年开放 VLM 的两个主力编码器。

### ViT 的参数量计算

完整计算在 `code/main.py` 中。对于 ViT-B/16（分辨率 224）：

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

在加载检查点之前先用这种方式估算每个 ViT 的参数量。骨干网络的大小决定了任何下游 VLM 的显存下限。

### 2026 年的生产配置

2026 年大多数开放 VLM 使用的编码器是 SigLIP 2 SO400m/14（原生分辨率，NaFlex）。它具有：
- 4 亿参数。
- 图块大小 14，默认分辨率 384 → 每张图像 729 个图块 token。
- 图像级任务用均值池化；VQA 时全部 729 个图块流入 LLM。
- 4 个寄存器 token，在移交 LLM 前丢弃。
- 2D-RoPE 加图像级缩放，支持原生宽高比。

该配置中的每一个决策都可以追溯到一篇可以阅读的论文。

## 动手使用

`code/main.py` 是一个图块分词器和几何计算器。输入（图像 H、W、图块 P、隐藏维度 D、深度 L），输出：

- 图块化后的网格形状和序列长度。
- 一张合成 8×8 像素玩具图像的 token 序列（逐步演示展平 + 投影路径）。
- 按图块嵌入、位置嵌入、Transformer 块和头部分解的参数量。
- 目标分辨率下每次前向传播的 FLOPs。
- 跨 ViT-B/16@224、ViT-L/14@336、DINOv2 ViT-g/14@224、SigLIP SO400m/14@384 的对比表格。

运行它。将参数量与已发布数字对比。调整图块大小和分辨率，感受 token 数量的代价。

## 输出产物

本章生成 `outputs/skill-patch-geometry-reader.md`。给定一个 ViT 配置（图块大小、分辨率、隐藏维度、深度），它输出带有理由说明的 token 数、参数量和显存估计。在为 VLM 选择视觉骨干时使用这个技能——它能防止"token 数量爆炸导致 LLM 上下文被填满"的意外。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| 图块（Patch） | "16×16 像素方块" | 输入图像中固定大小的不重叠区域；变为一个 token。 |
| 图块嵌入（Patch embedding） | "线性投影" | 将展平的图块像素映射到 D 维向量的共享学习矩阵（或步长为 P 的 Conv2d）。 |
| CLS token | "类别 token" | 前置的可学习向量，其最终隐藏状态代表整张图像；2026 年已可选。 |
| 寄存器 token（Register token） | "汇聚 token" | 额外的可学习 token，吸收 ViT 在预训练期间产生的高范数注意力伪影。 |
| 位置嵌入（Position embedding） | "位置信息" | 使序列感知顺序的每位置向量或旋转编码；2D-RoPE 是现代默认方案。 |
| 网格（Grid） | "图块网格" | 给定分辨率和图块大小下的 (H/P) × (W/P) 二维图块数组。 |
| NaFlex | "原生灵活分辨率" | SigLIP 2 特性：单个模型无需重新训练即可处理多种宽高比和分辨率。 |
| 骨干网络（Backbone） | "视觉塔" | 预训练图像编码器，其图块 token 输出被喂给 VLM 中的 LLM。 |
| 池化（Pooling） | "图像级摘要" | 将图块 token 转换为单个向量的策略：CLS、均值、注意力池化或基于寄存器的方式。 |
| 图块 14 vs 16 | "更细 vs 更粗的网格" | 图块 14 每张图像产生更多 token，OCR 保真度更高但更慢；图块 16 是经典默认值。 |
