# 多模态智能体与计算机使用（综合项目）（Multimodal Agents and Computer-Use (Capstone)）

> 2026 年的前沿产品是一个多模态智能体，它能读取截图、点击按钮、导航 Web UI、填写表单，并端到端完成工作流。SeeClick 和 CogAgent（2024）证明了 GUI 接地这一基本原语。Ferret-UI 将其扩展到移动端。ChartAgent 引入了针对图表的视觉工具调用。VisualWebArena 和 AgentVista（2026）是前沿模型追逐的基准——即使是 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的难任务上也只能得约 30%。本综合项目汇集了 Phase 12 的每一条线索：感知（高分辨率 VLM）、推理（带工具调用的 LLM）、接地（坐标输出）、长期记忆和评估。

**类型：** 综合项目  
**语言：** Python（标准库，行动模式 + 智能体循环骨架）  
**前置知识：** Phase 12 · 05（LLaVA）、Phase 12 · 09（Qwen-VL JSON）、Phase 14（智能体工程）  
**预计时间：** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。
- 构建 VLM 能以 JSON 输出的 GUI 接地输出模式（点击坐标、输入文本、滚动、拖拽）。
- 对比纯截图智能体 vs 无障碍树智能体 vs 混合智能体。
- 在一个小型 VisualWebArena 切片上建立多模态智能体基准评估。

## 问题所在

一个订票网站工作流："帮我找一张 4 月 15 日去东京的航班，过道座位，800 美元以内，把它订了。"

多模态智能体需要：

1. 对浏览器截图。
2. 将截图 + URL + 目标解析为计划。
3. 输出结构化行动：点击（在 x,y 处）、输入"东京"（在元素 E 处）、向下滚动、选择（单选按钮）。
4. 将行动应用于浏览器。
5. 观察新状态（下一张截图）。
6. 重复直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误在步骤间累积，因此恢复很重要。

## 核心概念

### GUI 接地——基本原语

GUI 接地是：给定截图和自然语言指令，输出要点击的 (x, y) 坐标（或其他行动）。

**SeeClick**（arXiv:2401.10935）是第一个大规模开放结果：在合成 + 真实 GUI 数据上微调 VLM，将坐标输出为纯文本 token。有效。

**CogAgent**（arXiv:2312.08914）为密集 UI 添加了 1120×1120 高分辨率编码。得分：Web 导航约 84%。

**Ferret-UI**（arXiv:2404.05719）专注于移动 UI，与 iOS 无障碍数据集成。

输出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复：如果坐标在截图之间偏移，语义提示让系统能重新接地。

### 行动模式

典型的行动模式有 6-10 种行动类型：

- `click`：(x, y)
- `type`：(text, x?, y?)
- `scroll`：(direction, amount)
- `drag`：(x0, y0, x1, y1)
- `select`：(option_index)
- `hover`：(x, y)
- `navigate`：(url)
- `wait`：(ms)
- `done`：(success, explanation)

智能体每步输出一个行动。浏览器封装器执行并返回新状态。

### 纯截图 vs 无障碍树

两种输入模式：

- **纯截图：** 完整图像，无结构信息。最通用；适用于任何应用。
- **无障碍树：** 结构化的 DOM/iOS 无障碍信息。接地更可靠；在树可用的地方有效。
- **混合：** 两者都用，树作为原子行动的可靠接地器，截图提供语义上下文。

生产智能体在可能时使用混合模式。浏览器自动化（Selenium + 无障碍功能）始终有树；桌面应用有时有。

### 长期记忆

一个 20 步工作流生成 20 张截图。VLM 的上下文很快被填满。三种压缩策略：

- **摘要链：** 每 5 步后，总结已发生的事情，丢弃旧截图。
- **跳帧：** 保留第一张、最后一张和每隔 3 张截图。
- **工具记录日志：** 执行行动，保留已完成操作的文字日志；不重新查看旧截图。

Claude 的计算机使用 API 使用日志模式。更简单，更可靠。

### 视觉工具调用

ChartAgent（arXiv:2510.04514）为图表理解引入了视觉工具调用：裁剪、缩放、OCR、调用外部检测。智能体可以将"裁剪到区域 (100, 200, 300, 400) 然后调用 OCR"输出为工具调用。工具返回文本；VLM 继续推理。

这种模式可以推广：集合标记提示、区域注释和外部检测工具都适合同一个"输出工具调用，接收结构化响应"的模式。

### 2026 年的基准

- **ScreenSpot-Pro。** 约 1000 个 Web 截图上的 GUI 接地。开放最先进 Qwen2.5-VL-72B 约 85%。前沿约 90%。
- **VisualWebArena。** 端到端 Web 任务（购物、论坛、分类广告）。开放最先进约 20%。Gemini 3 Pro 约 27%。
- **AgentVista**（arXiv:2602.23166）。2026 年最难的基准。跨 12 个领域的真实工作流。前沿模型得 27-40%；开放模型得 10-20%。
- **WebArena/WebShop。** 较旧的基准；前沿模型已饱和。

### 为什么仍然很难

智能体性能瓶颈：

1. **细粒度视觉接地。** "点击小 X"在移动分辨率下经常失败。
2. **长期规划。** 10 个行动后，智能体开始偏离目标。
3. **错误恢复。** 当点击失败（按钮错误）时，检测 + 恢复很少有训练数据。
4. **跨页面上下文。** 在标签页之间跳转或处理长表单时会丢失状态。

研究方向：记忆架构、显式重规划、多模态验证（行动成功的截图匹配）。

### 综合项目任务

综合项目任务：构建一个计算机使用智能体，能够：

1. 读取订票网站模拟页面的 HTML + 截图。
2. 规划多步序列：搜索 → 选择 → 填写表单 → 提交。
3. 输出与行动模式匹配的 JSON 行动。
4. 在固定的 10 个任务切片上评估。

本章提供易于扩展到真实浏览器的脚手架代码。

## 动手使用

`code/main.py` 是综合项目脚手架：

- 行动模式 JSON 定义（10 种行动）。

- 10 个任务迷你基准（合成页面），测量端到端成功率。

## 关键术语

| 术语 | 通俗说法 | 准确含义 |
|------|----------|----------|
| GUI 接地（GUI grounding） | "点击坐标" | 模型输出截图上指令目标的 (x,y) 坐标。 |
| 行动模式（Action schema） | "工具定义" | 有效行动（点击、输入、滚动、拖拽）的 JSON 描述。 |
| 无障碍树（Accessibility tree） | "结构化 DOM" | 来自浏览器/iOS API 的机器可读 UI 层次结构。 |
| 混合智能体（Hybrid agent） | "截图 + 树" | 同时使用图像和结构化信息；比任何一个单独使用都更可靠。 |
| 视觉工具调用（Visual tool use） | "缩放/裁剪/检测" | 智能体在计划中途调用外部视觉工具（OCR、检测）。 |
| 摘要链（Summary-chain） | "记忆压缩" | 定期文字摘要替换长截图历史。 |
| VisualWebArena | "端到端 Web 基准" | 2024 年端到端 Web 任务基准。 |
| AgentVista | "2026 年难基准" | 12 个领域的真实工作流；即使 Gemini 3 Pro 也只得约 30%。 |
